# 화면 4 POC — 실시간 테두리 (v6)

라이브 프리뷰가 화면 전체를 채우고, 그 위에 그릴 자리 **테두리(선만)** 가 매 프레임 랜드마크에 붙어 따라간다.
화면에 두는 것은 **진행 칩 6개 · 품질 게이트 한 줄 · 구석의 작은 "확인받기"** 뿐이다. 제품 안내·근거·자리 비움 문구·건너뛰기는 없다.

## 실행
```
# 저장소 루트에서 (샘플 사진 폴더를 같이 서빙해야 함)
python -m http.server 8000
# → http://localhost:8000/poc/screen4/
cd poc/screen4 && node tests.mjs        # 자동 검증 26개
```
- 기본 소스는 촬영 세트 샘플(`danghaeung_poc_3x4_20/person_1_front_closed.jpg`). "카메라"를 누르면 웹캠(거울 모드).
- 폰에서 직접: 같은 네트워크에서 `http://<PC IP>:8000/poc/screen4/#device` — 목업이 화면 전체가 되고, 실제 폰 방향을 따른다. 카메라는 https 또는 localhost에서만 열리므로 폰에서는 터널(예: `ngrok http 8000`)이 필요할 수 있다.
- URL 해시: `#part=liner&orient=landscape&src=<이미지 경로>&nohand&cam&verify`.

## 아직 없는 것 (앱 단계)
- 쉐딩·하이라이트 가이드는 랜드마크 근사(둥근형 예시). 서버 법선 맵·얼굴형 5종 규칙은 미연결.
- 룩 템플릿 값은 `guides.js`의 TEMPLATE 한 벌(스모키 가정). 10개 룩 확정 후 교체.
- 카메라 저속 전환(자리 비움 3초)은 상태만 바뀌고 실제 프레임 레이트는 안 낮춘다.

## 알려진 위험과 대응 (실시간 테두리의 위치 어긋남·흔들림)

### 위험 1. 거울에 갔다 돌아오면 테두리 위치가 조금 달라진다
픽셀 단위로 완전히 같게 만드는 것은 **불가능**하다. 테두리가 매 프레임 새로 추정한 랜드마크에 붙기 때문이다. 목표는 "눈에 안 띄는 수준"(확대 화면 1~2px, 실제 0.5mm 이하)이고, 점수에는 영향이 없게 설계한다.

| 원인 | 설명 |
|---|---|
| 랜드마크 오차 | 눈 부위 프레임당 0.5~2px. 2~3배 확대하면 화면에서 2~6px |
| 추적 재시작 | 얼굴을 잃었다 다시 잡으면 첫 프레임이 다르고, 지금 POC는 그때 평활화를 초기화해 "툭" 옮겨간다 |
| 자세·거리·표정 변화 | 눈 자체가 다른 위치에 있으면 가이드도 따라간다. 오류가 아니라 정상 |
| 화장에 의한 편향 | 라이너를 그리면 눈꺼풀 경계 모양이 바뀌어 랜드마크가 1~2px 치우친다(모델이 맨얼굴 위주 학습) |
| 척도 재추정 | 홍채 지름을 매 프레임 다시 재서 꼬리 길이(mm→px)가 미세하게 변한다 |

**대응 (효과 큰 순서)**
1. **가이드를 한 번만 만들고 강체 변환만 적용** — 점 하나하나를 매 프레임 다시 계산하지 않고, 눈 안쪽·바깥쪽 끝과 홍채 기준 얼굴 좌표계에서 가이드를 한 번 만든 뒤 프레임마다 이동·회전·크기 4개 값만 맞춘다. 점별 떨림이 사라진다.
2. **맨얼굴 기준으로 고정** — 세션 시작 쌩얼 촬영에서 가이드 기하를 만들고, 화장 중에는 현재 얼굴에 옮기기만 한다. 라이너로 랜드마크가 치우쳐도 가이드는 영향을 받지 않는다.
3. **자리 비움 때 상태를 버리지 않기** — 평활화 상태를 유지하고, 재검출 시 0.3초 정도 이전 위치에서 새 위치로 이어 붙인다.
4. **척도 잠금** — px/mm를 기준 촬영 값으로 고정, 거리 변화가 일정 이상일 때만 재측정.
5. **같은 자세일 때만 확인** — 게이트에 "기준 촬영과 각도·거리 차이 이내" 조건 추가.
6. 필터를 EMA 대신 **One-Euro 필터**로.

**남는 오차의 대안**: 점수는 라이브가 아니라 **확인받기 순간의 정지 사진을 기준 사진에 정합해서** 매긴다(라이브 테두리는 안내용). 테두리를 선이 아니라 **±1mm 허용 띠**로 정의해 1~2px 이동은 띠 안에 두게 한다. 3D 메시(FLAME 등)로 바꾼다고 더 안정되지 않는다(결국 랜드마크로 맞춤). 더 정밀하려면 입력 해상도(1080p 이상)와 눈 영역 2차 추정.

### 위험 2. 화면·테두리가 떨린다
두 가지가 섞여 있다.

**(a) 확대 크롭 창이 흔들림** — 랜드마크 1px 떨림이 2~3배 확대돼 화면 전체가 흔들린다. 가장 눈에 띈다.
- 크롭 창은 테두리보다 훨씬 둔하게: 얼굴 중심이 얼굴 폭의 3% 이상 움직일 때만 옮기는 **데드존**, 옮길 때는 0.2~0.3초에 걸쳐 미끄러지게. 확대율도 거리 변화가 일정 이상일 때만.

**(b) 테두리 선이 떨림**
- **One-Euro 필터**: 정지 시 거의 완전히 멈추고 움직일 때는 지연 없이 따라온다(실시간 AR 표준).
- **강체 변환**(위 1번)으로 점별 떨림 대신 4개 값만 거른다.
- 안정적인 점만 기준으로: 눈 안쪽·바깥쪽 끝, 콧대, 홍채 중심. 눈꺼풀 가운데 점은 깜빡임·시선에 따라 많이 움직인다.
- **깜빡임 정지**: EAR이 임계 아래면 그 프레임은 가이드 갱신을 멈춘다.

**(c) 입력 쪽**
- 해상도 720p → 1080p면 픽셀 오차가 상대적으로 준다(처리 시간 증가 주의).
- 어두우면 노이즈로 더 떨린다. 밝기 게이트가 흔들림 방지 역할도 한다.
- 손에 들면 손 떨림이 그대로 들어온다. "폰을 세워 두세요" 안내가 현실적.
- 프레임 레이트가 들쭉날쭉하면 필터도 불안정. 손 감지 모델은 3~5프레임에 한 번만.

**우선순위**: 크롭 데드존 → One-Euro → 강체 변환 → 깜빡임 정지. 남는 미세 떨림은 점선을 조금 두껍게·반투명으로 그려 시각적으로 감춘다.

현재 POC 상태: EMA(0.5)만 있고 위 항목은 미적용. 자리 비움 시 평활화 초기화(1번·3번 반대)가 남아 있다.

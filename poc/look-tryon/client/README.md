# 당화응 POC — 룩 얹어보기 실시간 매핑 (가장 단순한 버전)

화면 1(얼굴 촬영) → 화면 2(룩 얹어보기)의 실시간 프리뷰 핵심 아이디어만 검증하는 최소 구현.

정식 스펙(`docs/archive/impl-screen1-5-definition-v6.md`)의 `LookLayer`는 468점 메시를 부위별로 UV 공간에 굽고 삼각형 단위로 실시간 재투영하지만, 이 POC는 훨씬 단순하게: **서버가 생성한 "완성 예상" 이미지 1장을 얼굴 전체 통째로, 랜드마크 3점(눈 바깥쪽 2개 + 턱) 기준 아핀 변형 1번**으로 매 프레임 라이브 얼굴 위치에 맞춰 붙인다. 표정별 국소 변형은 반영 안 됨 — 고개 각도·크기만 따라감.

## 사전 준비
1. `poc/look-tryon/server-bench/`의 Stable-Makeup Gradio 데모가 `http://127.0.0.1:7860`에 떠 있어야 한다.
   ```bash
   cd poc/look-tryon/server-bench
   conda run -n makeup-bench-sm python app_demo.py
   ```
2. 이 폴더를 로컬 서버로 연다 (카메라는 `localhost`/https에서만 열림):
   ```bash
   cd poc/look-tryon/client
   python -m http.server 8010
   ```
3. 브라우저에서 `http://localhost:8010` 접속 → 카메라 허용.

## 흐름
1. **얼굴 촬영** — 웹캠 프리뷰에서 버튼 클릭 1회 (자동 게이팅 없음, 화면 1 정의서의 4장·각도·손·밝기 검사는 생략).
2. **룩 참조 사진** — 파일 업로드 (풀메이크업 참조 사진 권장).
3. **생성** — 위 Gradio 서버 API를 직접 호출(fp16, 10 step, 약 3초). 결과 이미지에서 랜드마크 3점(33, 263, 152) 좌표를 뽑아 저장.
4. **실시간으로 보기** — 라이브 웹캠에서 매 프레임 같은 3점을 검출해 아핀 변형을 다시 풀고, 결과 이미지를 얼굴 타원 안에만 클리핑해서 합성. 슬라이더로 합성 강도 조절.

## 한계 (의도적, 다음 라운드 과제)
- 부위별 워핑 없음 — 눈썹·입술 등 각 부위가 독립적으로 움직이지 않음(표정 변화에 약함).
- 조명 보정 없음 — 촬영 시 조명과 실시간 조명이 다르면 붕 뜸.
- 화면 1의 CaptureGate(각도·손·밝기·선명도·안정성) 없음 — 정면 촬영 버튼 한 번.
- 결과 이미지 URL을 Gradio 서버에서 그대로 fetch하므로 CORS 설정에 따라 실패할 수 있음(같은 머신 localhost라 보통 통과).

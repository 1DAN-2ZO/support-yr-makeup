# Stable-Makeup 템플릿 추출 — 성능 평가

> 2026-09-29 ~ 09-30 · 전지원
> 팀에서 병행한 두 갈래 중 **"Stable-Makeup 으로 템플릿 뽑기"** 쪽 검증 결과.
> 측정은 전부 이 문서 아래 "측정 방법"대로 다시 잴 수 있다.

## 한 줄 결론

**Stable-Makeup 으로 만든 화장 사진에서 템플릿을 떠서 실시간 AR 에 쓰는 것은 실패했다.**
원인은 값 조정으로 넘을 수 없는 두 가지 구조적 한계다 — 얼굴 변형과, 사진에 묻어 있는 조명·피부색.
대신 검증 과정에서 **인페인팅 방식**이 얼굴 유지에서 3배 이상 나은 것을 확인했다.

---

## 1. 무엇을 검증했나

```
참고 화장 사진 + 맨얼굴  →  [Stable-Makeup]  →  화장한 얼굴
                              맨얼굴과 빼기   →  화장 층(템플릿)
                                              →  실시간 AR 로 얼굴에 씌우기
```

이 흐름이 **소다(SODA) 수준의 실시간 화장 얹어보기**에 쓸 수 있는지 확인하는 것이 목적이었다.

## 2. 측정 결과

### 2-1. 얼굴 변형 (핵심 지표)

원본과 결과에서 얼굴 점 468개를 찾아, 눈 사이 거리를 자로 삼아 8개 치수를 비교했다.
**화장만 얹혀야 하므로 이 값은 0에 가까워야 한다.**

| 방식 | 재료 | 평균 변형 | 최대 변형 |
|---|---|---|---|
| Stable-Makeup | 분홍머리 사진 | **8.6%** | 18.8% |
| Stable-Makeup | AI 생성 얼굴 | **6.1%** | 16.8% |
| Stable-Makeup | 전지원 사진 | **6.0%** | 19.8% |
| **인페인팅** | AI 생성 얼굴 | **2.0%** | 4.3% |
| **인페인팅** | 전지원 사진 | **2.9%** | 7.9% |

> 측정 치수: 얼굴 폭·얼굴 길이·코 폭·입 가로·양눈 가로·양눈 세로
> 참고 — 같은 사진을 두 번 넣어도 얼굴 점 찾기 자체가 약 2~5% 흔들린다. 인페인팅 값은 그 수준이다.

**Stable-Makeup 은 재료를 무엇으로 바꿔도 6% 아래로 내려가지 않았다.**
손잡이(`id` = 원본 구조 유지력)를 1.0 → 1.6 까지 올려도 개선되지 않았고, 1.6 에서는 피부에 얼룩이 생겼다.

### 2-2. 화장 층 추출량

맨얼굴과 화장 사진의 차이 중 화장으로 판정된 픽셀 비율.

| 재료 | 추출량 | 비고 |
|---|---|---|
| Stable-Makeup · AI 생성 쌍 | 1.1% | 눈두덩·볼터치 거의 안 잡힘 |
| Stable-Makeup · 분홍머리 쌍 | 2.4% | 입 벌림 차이로 입술이 뭉개짐 |
| Stable-Makeup · 성형외과 참고본 | 2.4% | 볼터치 처음 잡힘, 단 볼이 다각형 모양 |
| **인페인팅 쌍** | **6.3%** | 눈두덩·볼·입술 모두 잡힘 |

### 2-3. 속도

| 단계 | 시간 | 측정 환경 |
|---|---|---|
| Stable-Makeup 생성 (30 step) | 9초 | RTX 3060, fp16 |
| Stable-Makeup 생성 (8~10 step) | 2.55~3.15초 | 팀 `server-bench` 실측 |

## 3. 실패 원인

### 3-1. 얼굴이 바뀐다 — 확산 모델의 성질

확산 모델은 원본을 **복사하지 않고 잡음에서 다시 그린다.** 그래서 미세한 차이가 항상 남는다.
게다가 화장 지시를 **참고 사진 전체의 특징**으로 받기 때문에, 그 사진 인물의 눈 크기·코 높이·얼굴형까지 함께 넘어온다.
성형외과 홍보 사진처럼 보정이 강한 참고본에서 이 현상이 특히 컸다.

빼기 방식은 **두 사진이 완전히 겹쳐야** 성립한다. 얼굴이 바뀌면 그 차이가 화장으로 잡힌다.
실제로 얼굴 전체가 통째로 추출되는 결과가 반복해서 나왔다.

### 3-2. 사진에서 뜬 층에는 조명과 피부색이 묻어 있다

추출한 층은 **그 사진의 피부색·그날 조명·그때 그림자**를 함께 담는다.
이것을 **움직이는 얼굴**, **다른 조명**에 곱하면 어긋난다. 실시간 화면에서 멍 자국·잿빛 얼룩으로 나타났다.

소다가 사진에서 뽑지 않고 **디자이너가 표준 얼굴 판 위에 직접 그리는** 이유가 이것이다.
사람이 그린 그림에는 조명도 피부색도 들어 있지 않다.

### 3-3. 시도하고 걸러진 보정들

| 시도 | 결과 |
|---|---|
| 얼굴 점 정렬 + 조명 보정 | 각도·조명이 다른 실제 사진 쌍에서 오차가 화장으로 잡힘 |
| 부위 다각형으로 자르기 | 그 도형 모양이 얼굴에 찍힘 (육각형 볼터치) |
| 자체 학습 분할 모델로 자르기 | 도형은 사라졌으나 화장이 거의 안 남음 |
| 이마 기준 전역 색조 보정 (팀 `layer.py` 방식) | 얼굴 전체가 변한 재료에서는 효과 없음 |
| 색 대신 "변화 배수" 저장 | 스티커 느낌은 줄었으나 실시간에서 잿빛 얼룩 |
| 팀 WebGL 렌더러에 우리 무늬 넣기 | 렌더러는 정상 동작, 무늬 자체가 실시간에 부적합 |

## 4. 부수 성과

검증 과정에서 나온, 버리지 않아도 되는 결과들.

### 4-1. 인페인팅 방식 (마스크 안만 다시 그리기)

원본 사진에서 출발해 **화장 자리만** 다시 그리고, **마스크 밖은 원본 픽셀 그대로 되돌린다.**
얼굴형·머리카락·배경이 바뀔 수 없는 구조다.

| 항목 | 값 |
|---|---|
| 모델 | RealVisXL V4.0 + ControlNet(Canny) + IP-Adapter |
| 세기 | 0.8 |
| 참고 사진 비중 | 0.7 |
| 마스크 | 자체 학습 분할 모델 기반, 눈알 보호 1.2% · 눈두덩/볼/입술 개방 (8.7%) |
| 얼굴 변형 | **평균 2.9%** |

### 4-2. 화장 지우기

같은 인페인팅으로 **화장한 사진 → 맨얼굴**도 만들 수 있다. 한 장 17초.
학습 데이터를 만들 때 **정답을 진짜 사진으로 두고 입력을 생성**할 수 있어, AI 결과로 AI를 가르치는 문제를 피한다.

### 4-3. Stable-Makeup 파인튜닝 가능 여부

공식 저장소에 `utils/unet_with_adapter.py` 가 빠져 있어 학습이 시작되지 않았다.
확인 결과 **그 모듈은 `train.py` 안에서 한 번도 쓰이지 않는다** — `import` 한 줄만 있고 실제로는 기본 diffusers UNet 을 쓴다.
해당 줄을 지우고 `datasets`·`albumentations`·`wandb` 를 설치, 저장소 안 `datasets` 폴더 이름을 바꾸니 **학습 코드가 정상 기동**했다.

남은 준비물: SPIGA(얼굴 구조 그림), 학습 데이터 쌍, 디스크 여유.

---

## 5. 권고

1. **Stable-Makeup 으로 템플릿을 떠서 실시간에 쓰는 방향은 접는다.** 값 조정으로 넘을 수 있는 한계가 아니다.
2. **실시간 렌더링은 팀 WebGL 그물 필터를 쓴다.** 검증 중 정상 동작을 확인했고, 자체 캔버스 합성보다 안정적이다.
3. **소다 수준을 목표로 한다면 템플릿은 그려야 한다.** 사진 추출로는 조명·피부색 문제가 남는다.
4. **인페인팅은 "완성 예상 사진"(화면 2-b·3) 용도로 유효하다.** 실시간이 아닌 자리에서 쓴다.

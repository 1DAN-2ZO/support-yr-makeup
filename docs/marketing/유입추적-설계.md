## 보고 싶은 것 — 한 줄로 이어진 퍼널

```
게시물 노출 → 링크 클릭 → 앱 도착 → 동의 → 촬영 완료 → 화장 선택 → 첫 확인받기 → 전체 리뷰 → 결과 저장
  (플랫폼)     (플랫폼·리다이렉트)  └──────────────────── 앱 기록 (utm_campaign 으로 게시물과 연결) ────────────────┘
```

게시물 번호(장부 `2026-10-01-P2`)가 `utm_campaign` 으로 끝까지 따라가면, **"이 가설의 글이 실제 사용으로 몇 명을 데려왔나"** 를 셀 수 있다. 가설 장부 채점이 조회수가 아니라 **사용**으로 된다.

## 앱 팀께 — 요청 상세

### 2. 출처표 읽기 (작은 일)

- 첫 진입 때 `location.search` 에서 `utm_*` 4개만 읽어 세션 상태에 저장 → `{"type":"landing","utm_source":…,"utm_campaign":…}` 한 줄 기록
- 값은 영문·숫자·`-_.` 만, 각 40자로 자른다 (주소창에 아무 글이나 넣어 기록을 더럽히지 못하게)
- 없으면 `direct`

### 3. 익명 통계 보내기 (팀 결정 필요)

지금 설계는 **"기록은 폰 밖으로 안 나간다"** 가 원칙이다 (`log.ts` 머리말). 이걸 바꾸는 일이라 팀이 정해야 한다. 마케팅 쪽 제안:

| 원칙 | 내용 |
|---|---|
| 보내는 것 | 지금 기록하는 이벤트 줄 그대로 (이미 사진·얼굴 점 금지 검사가 있다) |
| 안 보내는 것 | IP 저장 안 함 · 기기 정보·위치 없음 · 세션 번호는 무작위 그대로 |
| 언제 | 동의한 사람만 · 세션 끝(`session_end`)이나 `pagehide` 때 `sendBeacon` 한 번 |
| 어디에 | VLM 서버(학원 PC)에 `POST /events` → `$DHE_DATA_DIR/events/날짜.jsonl` — `eval/funnel/run.py` 가 이미 그 자리를 읽는다 |
| 보관 | 30일 뒤 지움 |

### 1. 고정 주소 (발표 전에 필요)

`docs/device-setup-v6.md` 3절에 "발표 때 필요하면" 으로 미뤄져 있다. **홍보 링크와 사용자 실험 모집**에 필요해서 마케팅 쪽에서는 지금 필요하다.

## 링크 클릭 수 자체는?

| 방법 | 장점 | 단점 |
|---|---|---|
| 플랫폼 통계 (인스타 프로필 링크 탭 · 유튜브 링크 클릭) | 공짜, 계정만 있으면 | 플랫폼마다 다르고 게시물 단위가 아닐 때가 많다 |
| 앱 도착(`landing`) 을 클릭으로 친다 | 위 2번만 되면 바로 | 클릭했지만 앱이 안 뜬 사람(느린 망·서버 꺼짐)은 빠진다 |
| 우리 서버에 짧은 주소(`/go/코드`) → 숫자 세고 앱으로 넘김 | 정확한 클릭 수 | 서버 코드 추가 필요 |

마케팅 추천은 **처음엔 플랫폼 통계 + 앱 도착**, 클릭과 도착 차이가 크게 의심되면 짧은 주소를 붙인다.

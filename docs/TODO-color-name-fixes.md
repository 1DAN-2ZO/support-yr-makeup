# 색 이름 규칙 — 데이터 모은 뒤 고칠 것

제품 데이터를 모으며 실제 발색을 재다 발견한 것들. 지금 고치지 않고 모아 둔다
(데이터를 다 모은 뒤 한 번에 조정하기로 2026-10-07 정함).

## 1. 아이섀도우 `버건디` 구간에 밝기·채도 조건이 없다

`client/src/core/color-name.ts` 의 shadow 구역표에서 색상각 18~30° 는 밝기·채도를
보지 않고 전부 `버건디` 로 간다. 그래서 **연한 베이지핑크가 버건디로 나온다.**

모렛 뷰파인더 팔레트 사진에서 잰 값:

| 색 | L | C | h | 지금 이름 | 맞는 이름 |
|---|---|---|---|---|---|
| `#e2c5c3` | 82.0 | 11.2 | 26.6 | 버건디 | 베이지 쪽 |
| `#dfbcba` | 79.2 | 13.4 | 26.6 | 버건디 | 베이지 쪽 |
| `#cbaaa9` | 72.5 | 13.0 | 22.6 | 버건디 | 로즈/베이지 쪽 |

버건디는 어둡고 진한 색이어야 한다. 눈썹의 `레드브라운` 에 채도 조건을 넣어 고쳤던
것과 같은 종류의 구멍이다 (CN4-b 검사 참고).

## 2. 실제로 거의 안 나오는 계열

제품을 모아 보니 아래 계열은 **채울 제품이 없다.** 실제 화장에도 거의 안 나온다.
규칙에서 빼거나 옆 계열로 넘기는 것을 검토한다.

| 부위 | 계열 |
|---|---|
| 아이라인 | 네이비 |
| 아이섀도우 | 그레이 · 차콜 · 올리브 |
| 블러셔 | 그레이베이지 · 올리브 |
| 립 | 그레이베이지 · 토프 |

## 3. 한 제품이 여러 색일 때 어느 것을 사야 하는지 못 알려 준다

팔레트·펜슬은 호수가 여러 개인데 데이터는 제품 한 줄이다. 호수 이름이 계열과 같으면
("다크브라운") 괜찮지만, `와인 클래스` · `타로튜튜` 처럼 색을 안 알려 주는 이름은
사용자가 어느 것을 살지 모른다.

→ 호수마다 색(hex)을 넣고 색 거리로 고르는 방식으로 올리면 한 번에 풀린다.
   그때 모렛처럼 클래스별로 쪼개는 것도 같이 한다.

# 당화응 분업안 — 모듈 6개 + 성능 평가

당화응 · 2026-09-18 · 담당자 미정 (모듈 단위로만 나눔)
근거: `feature-spec-v6.md` §12 모듈·담당(구판), `tech-review-full-flow-v6.md`, `tech-review-screen5-v6.md`, `tech-review-screen6-v6.md`, 데이터 계획 4차(`data-plan-v6.md`), `poc/full` @ 50607ac

> **한눈에**
화면이 아니라 **모듈**로 나눈다. 화면으로 나누면 가이드 기하·랜드마크 표·크롭 코드가 사람마다 복제되고(지금 POC 6개가 그 상태), 모듈로 나누면 "내가 받는 것 / 내가 주는 것"만 맞추면 따로 돌릴 수 있다.
>
> 모듈은 여섯: **① 촬영·기준 ② 가이드·실시간 ③ 채점·합산 ④ 서버·생성 ⑤ 모델·데이터·평가 ⑥ 앱·콘텐츠·통합**. 평가는 ⑤가 데이터를 공급하고 결과를 모으되, 측정 자체는 각 모듈이 자기 것을 잰다.
>
> 분업을 시작하기 전에 해야 하는 것 둘: **공통 모듈 통합(`src/core/`)** 과 **모듈 간 데이터 계약 고정**. 이 둘 없이 나누면 첫 주가 병합 충돌로 간다.

## 3. 성능 평가

### 3-1. 원칙

- **발표 숫자 3개**가 목표: ① 채점기와 사람 판정 일치율 ② 얼굴형 규칙 정확도 → 모델 정확도(+ 라벨러 일치율) ③ 화장 전이 시간·정체성 유지·색 반영도.
- **데이터는 하나.** 아래 평가 다섯 중 넷이 실촬영 20명 세트에서 나온다. 촬영 세션이 평가 전체의 병목이라 ⑤의 1순위.
- **측정은 각 모듈이, 데이터와 결과표는 ⑤가.** 평가 스크립트와 결과 CSV는 `eval/<모듈>/`에, 결과표는 `docs/eval-results-v6.md` 하나에 자동 생성. 발표 슬라이드는 이 표를 그대로 옮긴다.
- **기준선을 먼저 잰다.** 모델을 학습하거나 알고리즘을 고치기 전에 "지금 값"을 같은 데이터로 먼저 기록한다. 개선폭이 없으면 발표 숫자가 없다.
- **통과 기준은 첫 측정 후 팀이 정한다.** 아래 "통과 기준(안)"은 논의 출발점.

## 5. 결정할 것 (분업 시작 전)

1. 담당자 배정 (이 문서는 모듈만).
2. 화면 3 구현 두 벌 중 하나.
3. 촬영 4장 중 눈 감음·45° 장의 용도 — 쓸 곳이 없으면 정면 2장으로 축소.
4. E-1·E-2·E-3 통과 기준 숫자 — 첫 측정 후 정하되, "낮으면 무엇을 바꿀지"(분할 모델 꺼내기 / 임계 재조정 / 룩 사진 교체)만 미리 합의.
5. 룩 참조 사진 10장 방법 (자체 촬영 / 생성 / 구매).

# 화면 3 부위 완성본 — 팀 공유용 정리 (2026-09-17)

담당: 화면 3 (부위 완성본) + 3-c (쉐딩·하이라이트 완성본). 이 문서 하나로 기술 선택 이유, 근거, 실측 결과, 남은 일까지 볼 수 있게 정리했다.

## 1. 화면 3이 하는 일

| 항목 | 내용 |
|---|---|
| 역할 | 부위 단계에 들어오면 "다 그리면 이렇게 됩니다"를 정지 이미지로 먼저 보여준다. 그리기 전에 목표를 눈으로 확인시키는 화면 |
| 카메라 | 안 쓴다. 정지 이미지 + 카드 화면 |
| 완성본 | 화면 2-b의 전체 완성 렌더 한 장을 그 부위로 줌 (부위별로 따로 합성하지 않음, v6 확정). 그래서 지나온 부위도 화장된 채로 보인다 |
| 방향 | 눈썹·아이라이너·섀도우 = 가로 (양쪽 눈을 한 화면에) / 입술·볼터치·쉐딩 = 세로 |

| 다음 화면 | "그리러 가기" → 화면 4 (실시간 테두리). 진행 칩으로 이 부위를 다시 고르면 이 화면부터 다시 시작 |

왜 LLM을 안 쓰나: 룩마다 고정 문장이라 매번 생성할 이유가 없고, 기능 정의서 모델 목록에 없는 모델을 늘리지 않으며, 폰에서 돌리면 30fps·용량 예산이 깨지고 서버로 보내면 지연·비용이 늘기 때문.

왜 랜드마크를 다시 안 뽑나: 촬영 1에서 이미 저장했고 화면 3은 정지 이미지라 얼굴이 안 움직인다. 재검출은 시간과 실패 가능성만 늘린다. 검출 실패는 화면 1에서 이미 걸러졌다.

## 4. 가장 큰 쟁점 — 완성본 화질 (확대 배율)

### 4-1. 문제의 크기 (실측 랜드마크로 계산)

| 기준값 | 수치 | 출처 |
|---|---|---|
| 눈 바깥끝↔바깥끝 | 얼굴 너비의 0.683배 | 샘플 사진 1번 랜드마크 실측 |
| 홍채 지름 | 얼굴 너비의 0.0957배 | 같음 |
| 표시 영역 | 가로 폰 화면의 약 72% (iPhone 15 가로 2556px 기준 약 1840px) | 레이아웃 실측 |

| 완성본 원본 | 렌더 속 얼굴 너비 | 눈 크롭 폭 | 크롭 속 홍채 | 화면을 채우려면 |
|---|---|---|---|---|
| SD1.5 기본 512 (서버 렌더) | 317px | 249px | 30px | 7.4배 확대 |
| 768로 올림 | 476px | 374px | 46px | 4.9배 |
| SDXL·FLUX 1024 | 635px | 498px | 61px | 3.7배 |
| 원본 셀피 1080×1920 | 648px | 509px | 62px | 3.6배 |
| 원본 셀피 1440×1920 | 864px | 678px | 83px | 2.7배 |

512를 줌하면 7.4배다. 게다가 확산 모델이 생성한 픽셀이라 이미 실제 디테일이 아니고, 그걸 다시 7배 늘리면 흐림이 겹친다.

## 6. 쉐딩·하이라이트 (3-c)

| 항목 | 상태·근거 |
|---|---|
| 왜 따로인가 | 룩 템플릿 10개는 눈썹·라이너·섀도우·입술·볼터치만 담는다. 쉐딩은 얼굴형 규칙에서 오므로 완성 렌더에 없다. 그래서 얼굴 아래쪽(광대~턱)으로 줌 + 규칙 자리를 점선 테두리로만 (색 면 채우기 없음, 라벨 "쉐딩"·"하이라이트") |

## 7. 화면 방향

| 항목 | 내용 |
|---|---|
| 규칙 | 눈 단계 가로, 입술·볼·쉐딩 세로. 화면 3·4·5 모두 같은 방향 |

| 안 돌리면 | 6초 안내 후 그냥 보여줌 + "가로로 돌리면 더 크게 볼 수 있어요" 한 줄. 계속 막지 않는다. 확대율 손해는 가로 부위를 세로로 볼 때만 생김(393/852 = 46%) |

## 13. 한 줄 결론

화면 3에 새로 만들 모델은 없다. 남은 결정은 완성본 원본(벡터 레이어 → 타일 업스케일 → 512 줌), 문장 55개, 쉐딩 규칙 5종이고, 셋 다 막혀도 맨얼굴 사진 + 기본 문장으로 화면은 뜬다. 그래서 다른 화면보다 먼저 만들 수 있다.

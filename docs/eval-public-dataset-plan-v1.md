# 공개 데이터셋으로 채점 먼저 확인하기 (v1, 2026-09-18)

⑤ 모델·데이터·평가. 자체 촬영(5-1) 전에 **공개 데이터셋으로 채점 파이프라인을 먼저 돌려 보는** 계획이다.

---

## 1. 왜 공개 데이터셋부터 하나

지금 채점(`score`)은 가상 화장으로만 검증돼 있다. 실제 사진을 넣으면 어디서 막히는지 아직 모른다.
자체 촬영은 사람을 모으고 화장을 하고 동의서를 받아야 해서 시간이 든다. 그래서 **바로 받을 수 있는 공개 데이터로 막히는 곳을 먼저 찾고**, 촬영은 공개 데이터로 확인할 수 없는 것만 확인하는 단계로 미룬다.

## 2. 쓰는 데이터 — FFHQ-Makeup

| 항목 | 내용 |
| --- | --- |
| 구성 | 1만 8천 명 × (맨얼굴 1장 + 화장 5장), 512×512, 얼굴 정렬됨 |
| 링크 | https://huggingface.co/datasets/cyberagent/FFHQ-Makeup |
| 라이선스 | CC BY-NC-SA 4.0 (비상업). **평가(시험지) 용도로만** 쓴다. 학습·앱 화면에는 쓰지 않는다 (`data-plan-notion.md` 8절) |
| 받은 것 | 저장소 샘플 20명 × 6장 = 120장으로 먼저 시작. 전체(3.5GB)는 저장소 밖에 둔다 |

## 3. 받아서 열어 보고 알게 된 것

샘플을 직접 확인한 결과, 계획에 반영할 점이 두 가지 있다.

1. **화장이 합성이다.** 데이터셋 설명에 "paired synthetic makeup dataset"이라고 되어 있다. 실제 사람이 손으로 그린 화장이 아니라, 화장 전이 모델로 맨얼굴에 입힌 것이다.
2. **화장 외의 부분도 바뀐다.** 화장본에서 주근깨가 사라지고 피부가 매끈해지는 등 **얼굴 전체가 보정**되어 있다. 설명서에도 "얼굴 밖(옷 색 등)에 가끔 잡티"가 있다고 적혀 있다. 아이라이너는 약하거나 없는 경우가 많고, 눈 화장은 주로 섀도우다.

우리 채점은 "맨얼굴과 색이 달라진 곳 = 화장"으로 찾기 때문에, 2번은 **화장이 아닌 곳을 화장으로 잘못 잡는(오탐) 원인**이 된다.

## 4. 이 데이터로 확인하는 것 / 못 하는 것

| 확인할 것 | 가능? | 이유 |
| --- | --- | --- |
| 채점이 실제 얼굴 사진에서 끝까지 도는가 | **가능** | 사진 규격(정면·정렬)이 우리 입력과 맞음 |
| 부위별 화장 영역을 찾는가 (입술·섀도우·눈썹) | **가능** | 부위별로 화장이 들어가 있음 |
| 화장이 아닌 변화(피부 보정)를 화장으로 착각하는가 | **가능** | 3-2의 보정이 그대로 시험 문제가 됨 |
| 이탈률 분포 | **가능** | 등급 경계를 정할 때 참고 |
| 아이라이너 채점 | 제한적 | 라이너가 약하거나 없음 |
| 사람이 손으로 그린 화장의 번짐·떨림 | 불가 | 합성 화장이라 없음 |
| 거울에 다녀온 뒤의 조명·자세 변화 | 불가 | 같은 사진을 보정한 쌍이라 조명·자세가 같음 |
| "틀리게 그린 화장"을 잡는가 | 불가 | 전부 정상 화장 |

## 5. 순서

1. **샘플 20명으로 채점 돌려 보기** — 부위별 영역 검출 결과를 이미지로 저장해 눈으로 확인
2. **오탐 측정** — 화장이 없는 영역(이마·볼 가운데·턱 끝)에서 "화장했다"고 잡힌 비율
3. **이탈률 분포 보기** — 입술·눈썹 부위에서 가이드 대비 이탈률이 어떻게 퍼져 있는지
4. **등급 경계를 설계값으로 정하기** — 예: 이탈 60% 이상 = 많이 벗어남. 이 값은 **우리가 정하는 설계값**이고 발표에서도 그렇게 밝힌다
5. 결과를 `eval/` 스크립트와 `docs/eval-results-v6.md`에 남긴다

## 6. 자체 촬영은 언제

위 4번 표의 "불가" 항목 중 **조명·자세 변화**와 **손으로 그린 화장**이 필요해질 때 한다. 촬영 문서(동의서·체크리스트·기록표)는 브랜치 `model-shoot-plan`에 보관해 두었다.

## 7. 저장 규칙

- 데이터셋 이미지는 저장소에 넣지 않는다 (`DHE_DATA_DIR`).
- 저장소에는 스크립트, 결과 CSV, 결과 요약만 들어간다.

## 8. 1차 실행 결과 (2026-09-18)

샘플 중 맨얼굴·화장 5종이 모두 있는 **10명 × 6장**을 팀 채점기에 넣었다. 부위 5개(눈썹·라이너·섀도우·입술·볼터치) × 60장 = **300건**. 실행 방법은 `eval/ffhq/README.md`.

| 확인한 것 | 결과 | 판단 |
| --- | --- | --- |
| 맨얼굴 vs 맨얼굴(화장 없음) | 50건 전부 "화장 없음" | 정상 |
| 정합 잔차(눈 사이 거리 대비) | 평균 0.8%, 최대 1.4% (허용 5%) — 전부 통과 | 정상 |
| 조명 차(이마 L*) | −9.1 ~ +7.3 — 전부 허용(±12) 안 | 정상 |
| 아이라이너 | 화장본 **50/50건 "있음"**, 평균 49.6점 | **문제** |
| 섀도우 | 화장본 19/50건만 "있음" | **문제** |
| 볼터치 | 화장본 6/50건만 "있음" | **문제** |
| 눈썹·입술 | 50/50건 "있음", 평균 64·66점 | 참고 |

### 문제 1 — 라이너가 없는 사진도 라이너로 채점

라이너 샘플 범위가 속눈썹 선에서 법선 방향 ±눈 폭 11%(≈ ±3mm)라 **섀도우와 마스카라가 같이 들어온다.** 예: `002395_makeup_02`는 연한 섀도우와 속눈썹뿐인데 라이너 72점, "꼬리 낮음" 판정. 합성 데이터라서 생긴 문제가 아니라 **실사진에서도 그대로 생길 구조적 문제**다.

고칠 방향: 라이너는 속눈썹 선 바로 위 얇은 띠만 보고, 섀도우 영역과 겹치는 바깥 띠는 "라이너 밖 번짐"이 아니라 제외한다. 섀도우가 있는 경우를 따로 판정한다.

### 문제 2 — 섀도우·볼터치를 절반 이상 놓침

섀도우·볼터치는 "부위 색 변화 − 주변 피부 색 변화"로 재는데, 이 데이터는 AI가 **주변 피부까지 같이 보정**해 차이가 작게 나온 것으로 추정한다. 실사진에서도 같은지는 자체 촬영에서 확인해야 한다. 지금은 원인이 데이터 쪽인지 채점 쪽인지 단정하지 않는다.

### #317 [server] 사용 기록 받기 — POST /events (어느 화면에서 나갔는지 · 받는 쪽만)
- 브랜치: `server-events` · 병합 2026-10-07 · +279 −2
- 한 일: 사용자가 어느 화면에서 나갔는지 보려고 서버에 사용 기록을 받는 주소 `POST /events` 를 만들었다. 받는 쪽만 만들었고 앱(프론트)은 고치지 않았다. 2026-10-07 결정으로 "우리 서버에 저장하지 않는다" 는 사진과 결과에만 해당하고 사용 기록은 모은다.
- 결과: 한 번에 64KB · 200줄까지, 글자 값은 500자까지 받는다. 답은 204(받음) · 413(너무 큼) · 422(모양이 틀림) · 503(쌓을 곳 `DHE_DATA_DIR` 없음)이다. `$DHE_DATA_DIR/events/<받은 날 UTC>.jsonl` 에 쌓인다. 테스트 `test_events` EV1~EV13(28개)을 먼저 쓰고 실패 확인한 뒤 통과시켰다. 실제 서버(uvicorn)를 띄워 보내 봤다: 정상 204 · text/plain 204 · 금지 키 422 · 너무 큼 413 → 파일에 5줄, 퍼널 집계가 그대로 읽었다. `scripts/check.sh` 통과. 병합 때는 #322 · #317 · #319 · #324 를 함께 받아 pytest 119 · vitest 1010 · 타입 · 린트 통과, main CI 통과.
- 트러블슈팅:
  - 문제: "나갔다" 신호는 폰에서 안 올 때가 많다 → 푼 방법: 이탈 위치는 세션의 마지막 `screen_enter` 로 본다. 화면에 들어올 때마다 보내는 것을 기본으로 했다.
  - 문제: 사용 기록에 사진 · 얼굴 점이 섞여 들어올 수 있다 → 푼 방법: 키 이름이 `lm` `pts` `frames` `image` `bareImage` `photo` `path` `filename` 이면 거절하고, 값은 글자 · 숫자 · 참거짓 · null 만 받아서 배열이나 객체에 좌표를 숨겨 보낼 수 없게 했다(`ver` 만 글자 사전). 주소(IP) · 브라우저 정보는 파일에 안 남긴다.
  - 문제: 폰 시계가 틀리면 순서를 알 수 없다 → 푼 방법: 서버가 받은 시각 `rt` 를 덧붙인다.
  - 문제: 저장소 안에 실수로 기록이 쌓일 수 있다 → 푼 방법: `DHE_DATA_DIR` 가 없으면 받지 않고 503 을 낸다.
  - 테스트가 진짜 잡는지 확인: 코드를 일부러 망가뜨려 봤다. 금지 키 검사 끔 → EV5, 값 검사 끔 → EV6 · EV7, `rt` 뺌 → EV1 · EV12, 크기 한도 늘림 → EV9 가 잡았다.
- 남긴 것: 프론트에서 보내기(`dev` 담당). 동의 문구(#300). 퍼널 집계가 옛 화면 이름을 쓴다. 누가 마구 보내는 것을 막는 장치는 없다(크기 한도뿐) — 공개 배포 전에 Cloudflare 쪽 제한이나 서버 제한이 필요하다. 같은 세션을 "폰에서 내보내기" 와 서버 양쪽으로 받으면 줄이 겹친다. 배포 때 `DHE_DATA_DIR` 와 `DHE_CORS_ORIGINS`(지금 기본값은 개발 주소뿐)를 정해 줘야 한다.

### #314 [app] 새 흐름 뼈대 — 촬영 → 참고 사진·정답사진 → 부위 가이드 → 시도사진 → 피드백 → 저장·공유 (빈 자리 화면)
- 브랜치: `app-flow-skeleton` · 병합 2026-10-06 · +356 −49
- 한 일: 앱이 새 흐름 순서대로 흘러가게 화면 순서 뼈대를 만들었다. 아직 안 만든 화면은 "무엇이 들어올 자리인지 · 누가 만드는지" 를 보여 주는 빈 자리 화면으로 잇고, 각 담당은 화면을 만들면 `main.ts` 에서 등록만 바꾸면 되게 했다.
- 결과: `core/flow.ts` 에 화면 이름 다섯 개(`answer` · `partguide` · `attempt` · `feedback` · `save`)를 더했다. `core/screens.ts` 의 진행 순서를 새 흐름으로 바꾸고 `inNewFlow` · `nextGuidePart` 를 넣었다. 새 파일 `screens/flow-slots.ts` 에 빈 자리 화면 세 종류를 만들었다. 테스트를 먼저 실패 확인한 뒤 통과: `screens` · `flow`(화면 16개) · `shell` · 새 `flow-slots` FS1 · FS1b · FS2 · FS2b · FS3. `scripts/check.sh` 통과(pytest 86 · vitest 924 · 타입 · 린트). 배포용 빌드를 크롬으로 열어 동의 → 촬영까지 오류 없이 가는 것을 확인했다.
- 트러블슈팅:
  - 문제: 앱을 다시 켰을 때 옛 흐름 화면에 멈춰 있던 세션이 있을 수 있다 → 푼 방법: 옛 화면은 지우지 않고 흐름만 그쪽으로 가지 않게 했고, 옛 화면에 멈춘 세션은 가까운 새 화면으로 옮긴다(`inNewFlow`).
  - 문제: ① 촬영 · ② 가이드 · ④ 서버 담당이 정답사진을 각자 다른 방식으로 구현해 보는 중이라 화면을 쪼개 나눌 수 없었다 → 푼 방법: `answer` 자리 하나(담당 `prep`)에 업로드 · 정답사진 생성 · 정답사진 보기를 다 넣고, 안에서 화면을 몇 개로 나눌지는 맡겼다.
- 남긴 것: 촬영은 아직 4장(좌 · 우 45° 포함)이다. 부위 목록은 지금 것(`PART_IDS`) 그대로다. 정답사진을 세션의 어디에 둘지는 정하지 않았다. 촬영 다음부터는 실제 얼굴이 있어야 지나갈 수 있어서 브라우저로 끝까지 눌러 보지 못했다(시험으로만). 리뷰는 병합 뒤에 받기로 했다(댓글).

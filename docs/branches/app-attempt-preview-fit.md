### #345 [app] 시도사진 미리보기 — 사진이 화면 폭 안에 두 장 나란히 들어오게 (폰 확인 10/8, #344)
- 브랜치: `app-attempt-preview-fit` · 병합 2026-10-08 · +19 −0
- 한 일: 화면 5 시도사진을 찍은 뒤의 미리보기가 화면 안에 들어오게 고쳤다. 미리보기 줄을 두 칸으로 나누고, 그림은 칸 폭에 맞추되 비율은 그대로 두고, `figure` 의 브라우저 기본 여백을 없앴다(`screens/attempt.ts` 안의 인라인 스타일).
- 결과: 테스트 `attempt-screen` AS11 을 먼저 실패 확인한 뒤 통과시켰다. 폰 폭(412px)의 브라우저에서 고치기 전 · 후를 찍어 눈으로 봤다(원본 크기 1080×1920 그림 두 장, 미리보기와 같은 구조 · 스타일을 옮긴 시험 페이지). 고치기 전은 폰에서 본 것과 같은 모습(구석만 보임 · 가로 스크롤)이고, 고친 뒤는 두 장과 버튼이 한 화면에 들어온다. `scripts/check.sh` 통과(pytest 119 · vitest 1181 · 타입 · 린트). 병합 때는 pytest 119 · vitest 1189 통과, main CI 통과. 배포된 파일에 이 수정이 들어 있는 것을 확인했다.
- 트러블슈팅:
  - 증상: 폰에서 미리보기 사진이 너무 크게 나와 사진의 구석(천장)만 보이고, "다시 찍기" · "이대로 피드백 받기" 버튼이 화면 밖으로 밀렸다(폰 확인 2026-10-08, #344 의 3번) → 원인: #330 에서 시도사진을 원본 크기로 넘기게 바꾸면서 미리보기 그림의 크기를 잡아 주지 않았다. 그때 실제 폰에서 확인하지 않고 병합했다 → 푼 방법: 위와 같이 두 칸 · 칸 폭 맞춤 · 여백 제거를 인라인 스타일로 넣었다. `app.css` 는 ⑤ 모델/UI 담당이 다듬는 중이라 겹치지 않게 건드리지 않았다.
- 남긴 것: 화면 안에 들어오게만 했고 모양(둥근 모서리 · 간격 · 버튼)은 ⑤ 몫이다. 실제 폰의 진짜 시도사진 화면에서는 아직 못 봤다(#344 에 남김). #344 의 1번(시작 안내) · 2번(찍는 중 안내 글이 안 보임)은 ⑤ 에게 남아 있다.

## 무엇을 찾으려 했나

지금 채점은 "가이드 자리에 색이 올라갔는가" 를 본다. 그런데 초보자가 틀리는 것은 **모양**이다 — 꼬리가 짧다, 한쪽만 그렸다, 선 밖으로 나갔다. 이 브랜치는 사진 한 장에서 그린 모양을 직접 읽어 내는 방법을 하나씩 시험했다. 되는 것과 안 되는 것을 가른 뒤, 되는 것만 앱 코드로 옮겼다.

## 트러블슈팅 — 실험에서 부딪힌 것

- **시도사진에서 바로 재면 가짜 꼬리가 읽힌다** (같은 자리 눈 감은 쌍에서 12눈 중 5눈). 사진마다 얼굴이 조금씩 달라서다 → 시도사진의 화장을 정답사진과 같은 모델로 맨얼굴에 옮긴 그림("옮긴 그림")끼리 견준다. 연속 촬영 두 묶음에서는 가짜 꼬리 20눈 중 0
- **한 장씩 판정하면 흔들린다** → 0.8초에 5장을 찍어 값마다 가운데 값을 쓴다 (앱의 시도사진 5장 묶음 #330 · #335 가 여기서 나왔다)
- **기준값이 실제 정답사진에서 전부 막혔다** (실험 40). 얹어 본 진한 화장에 맞춘 문턱이라 실제 모델 그림의 변화보다 높았다 → 문턱을 부위마다 따로(입술 5 · 섀도우 3.5 · 눈썹 6)
- **사진 조건 거르개가 8단계 중 6단계를 막았다** (실험 38, 밝기). 30분 사이 장면 전체가 밝아졌는데 판정은 맞았다 → 밝기 · 색 기준을 풀고(10 · 8), 틀렸던 쌍은 크기 · 고개 각도에서 걸리게
- **받은 정답사진이 맨얼굴과 다른 사진으로 만든 것이었다** (실험 39) → 정답의 맨얼굴을 따로 받는 길(`targetBare`)을 만들고, "피드백이 받는 그림의 조건" 을 문서로 정리 (#328)
- **모델로 옮긴 그림의 라이너를 틀리게 읽었다** (실험 43 · 44). 사진을 먼저 줄여 눈 폭이 52px 이 됐고, 양옆 폭이 좁았다 → 얼굴을 먼저 자른 뒤 돌리고, 화장 없는 판을 기준으로 삼으니 12개 눈이 다 맞음. 선 굵기 기준은 0.035~0.04 만 두 묶음에 다 맞았다 (넓히면 섀도우 띠를 꼬리로 읽음)
- **입술이 옆으로 번진 것을 못 잡았다** (실험 42). 둘레 띠 전체 평균으로는 묽어졌다 → 입꼬리 바깥을 좌우 따로 재니 번진 단계만 뜀 (0.48 대 최대 0.16)
- **기준 그림 없이 정답사진과 옮긴 그림을 직접 견주기는 안 됐다** (실험 46). 꼬리가 같은 자리에 안 놓이면 같은 길이도 "없음" 으로 읽힌다

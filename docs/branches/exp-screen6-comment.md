### #289 [eval] 화면 6 한줄평 확인 실험 (#287) — 규칙 한줄평 대 텍스트 LLM
- 브랜치: `exp/screen6-comment` · 닫힘 — 병합 안 함 (2026-10-06) · +2049 −2
- 한 일: #287 의 확인 실험으로 "화면 6 한줄평을 LLM 이 써야 하나" 를 봤다. 앱 코드는 안 바꾸고 `eval/` 아래만 바꿨다. B(규칙 한줄평: 가장 잘된 부위 하나 + 먼저 고칠 부위 하나, 한 문장)와 C(같은 채점 결과를 사진 없이 글로 LLM 에 넘겨 `praise_part`·`fix_part`·`comment` 를 제약 디코딩으로 받고 관문 `gateC` 를 지남)를 비교한다. 입력은 가짜 세션 30개(전부 잘됨 5, 한 부위 크게 틀림 8, 좌우 비대칭 5, 확인만 섞임 6, 건너뜀 섞임 3, 여럿 아쉬움 3)이고 둘 다 한 문장 60자 이하다. 통과 기준은 미리 정했다 — C 를 B 보다 고른 비율(비슷함 뺌)의 95% 신뢰구간 하한 > 50% 면 LLM 을 넣는다.
- 결과: 자동 지표(학원 PC RTX 3060, temperature 0)는 Gemma 4 E4B(사진 없이)가 관문 통과 48/60 · 같은 답 30/30 · p50/p95 1.2/1.4초 · 길이 46자, Qwen3-14B(공식 Q4_K_M)가 52/60 · 30/30 · 2.1/2.4초 · 35자, B 는 길이 29자다. 평가지의 C 는 Gemma 로 정했다. `scripts/check.sh` 전부 통과(pytest 90개, vitest 855개).
  - 1차 사람 평가(댓글): C 66 · B 6(91.7%, 95% 신뢰구간 83~96%).
  - 2차(comment-v7, 댓글): Gemma 관문 통과율 93%, 평가지 `총평-평가.html` 28문항.
  - 4차(rawline-v1, 댓글): 진단 코드 없이 수치만 주면 문제 코드 정밀도가 Gemma 62%, Qwen3-14B 28%, Qwen3-14B 생각 모드 54%(세션당 37초)다. 수치와 진단을 같이 주면 Gemma 관문 통과율 92%(3차는 76~88%), 통과한 문제 줄 가운데 진단과 다른 말은 약 13%(3차는 약 25%)다. 잘된 부위 174줄은 자동 검사를 모두 통과했다.
- 트러블슈팅:
  - LLM 출력에 여러 문제가 나왔다 → 실제 출력에서 나온 문제로 관문 `gateC` 를 만들었다: 숫자 · 글 잘림 · 영어 섞임 · 문장 셋 이상 · 결과에 없는 부위를 칭찬하거나 고치라고 함 · 고칠 부위를 글에서 말하지 않음 · 잘된 부위를 고치라고 함 · 건너뛴 부위를 칭찬함 · 반대 방향(진한데 더 진하게 등).
  - "잘된 부위를 고치라고 함" 검사 → 한줄평은 칭찬과 할 일이 한 문장에 같이 오기 때문에 쉼표로 나눈 마디 단위로 본다.
  - Gemma 가 "전부 잘됨" 세션 5개 모두와 다른 1개에서 관문에 거절됐다 → "적당해요" 를 부족하다는 뜻으로 읽고 고치라고 했다 → C 가 거절되면 앱은 B 를 보여 줘 B 대 B 가 되므로 그 세션을 평가지에서 빼고 개수만 적었다. 평가지는 24문항이 됐다.
  - Qwen3-14B 는 관문이 못 잡는 문제가 많았다 → 오타("셔도우", "하일라이트"), 어색한 말("발라해요", "연마해보세요"), 결과에 없는 방법("진한 톤으로 바꿔")이 나왔다 → Gemma 를 골랐다. 4차에서도 Qwen3-14B 는 한국어가 어색하고 잘된 부위에 문제를 지어내고 2.5배 느렸다.
  - 1차 사람 평가에서 C 가 크게 이겼지만 이유를 구분할 수 없었다 → B 에 할 일이 빠져 있어서 LLM 이라서 이긴 것인지 할 일을 말해서 이긴 것인지 알 수 없었다 → 2차(comment-v7)를 만들었다: 총평 100자, C 에 넘기는 입력값 전부, 이 화장의 제품으로 할 일을 쓰는 세부 멘토링, 모델 없이 규칙으로 만든 기준선 B′ 와 C 의 비교.
  - 4차: 수치만 넣으면 LLM 이 문제를 제대로 못 찾는다 → 문제 판정은 채점 코드가 해야 한다. 제안은 문제 부위 한 줄은 규칙으로, 잘된 부위 칭찬과 총평은 LLM(Gemma 4 E4B, 사진 없음)에 맡기는 것이다.

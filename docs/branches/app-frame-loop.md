### #272 [app] 2-b AR · 리뷰 정면 1장도 공용 카메라 루프로 — 카메라 새 장면에만 얼굴 찾기 (#245)
- 브랜치: `app-frame-loop` · 병합 2026-10-01 · +75 −32
- 한 일: 가이드 담당이 #269 로 만든 공용 카메라 루프(`camera-loop.ts`)를 2-b AR(`fullrender.ts`)과 화면 6 들어올 때 찍는 정면 1장(`review-shot.ts`)에도 적용했다. 얼굴 찾기를 카메라 새 장면마다 한 번만 하고, 루프가 주는 시각 하나를 얼굴 찾기 · 떨림 필터 · 머리카락 분할 간격 · 촬영 대기에 같이 쓴다. 2-b AR 의 오류 처리(기록 → 정리 → 서버 그림)는 그대로 두고 루프의 `onError` 로 옮겼다.
- 결과: `tests/camera-screens.test.ts` — 가이드 담당의 CS1~CS5 를 두 화면에 적용해 고치기 전 8개 실패(CS1·CS2·CS4·CS5 × 2 화면) → 고친 뒤 20개 통과. `scripts/check.sh` 통과(테스트 833개 · 타입 · 린트). 실제 크롬(가짜 카메라)에서 2초 동안 화면 그리기 120번 · 카메라 새 장면 39번(화면에 붙인 영상도 같은 39번)을 쟀다. 서버 담당이 macOS/iOS 사파리 실기기에서 2-b AR 캠 미리보기 추적이 잘 되고, 화면에 안 붙인 영상에서도 새 프레임 신호가 와서 멈춤·로딩 걸림이 없음을 확인했다(댓글).
- 트러블슈팅:
  - 두 화면이 같은 장면을 두세 번 분석했다(#245 에서 2-b 가 느린 원인 후보로 꼽힘) → `requestAnimationFrame` 을 직접 돌려 화면이 다시 그려질 때마다(60·120Hz) 얼굴을 찾았는데 카메라는 초당 30장쯤만 준다 → 공용 카메라 루프로 바꿔 새 장면에만 얼굴을 찾는다.
  - 다른 화면이 남긴 카메라 잠금이 PC 웹캠에 남았다(#267) → 켠 직후와 끌 때 `releaseCameraLocks` 를 부른다.
  - 리뷰 정면 1장의 루프 안 오류가 잡히지 않았다 → 기록하고 사진 없이 리뷰로 넘어가게 했다.
  - `fullrender.ts` 의 `let stream` 위에 맞지 않는 주석 한 줄("지금 AR 장면을 저장한다 …")이 남아 있었다 → 지웠다.
  - 사파리에서 화면에 안 붙인 영상에 새 장면 신호가 안 오면 2-b AR 이 서버 그림에서 안 넘어갈 걱정이 있었다 → 작성자는 확인하지 못했고, 서버 담당이 실기기로 문제없음을 확인했다.
- 남긴 것: 폰에서 2-b AR 초당 장면 수 전후 비교는 #244 폰 확인 때 같이 본다. 그리는 방식(`makeup-paint.ts` · 셰이더)은 건드리지 않았다.

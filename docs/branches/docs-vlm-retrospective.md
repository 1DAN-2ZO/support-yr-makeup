### #286 [docs] VLM 개인화 정리 — 한 것 · 결과 · 된 것과 안 된 것 (보류)
- 브랜치: `docs/vlm-retrospective` · 병합 2026-10-02 · +188 −0
- 한 일: VLM 개인화를 보류하면서(폐기가 아니라 VLM 이 맡을 역할이 바뀔 수 있어 기다리는 상태) 그동안 한 일과 결과를 `docs/reports/vlm-personalization-retrospective.md` 로 남겼다. 앱 코드는 안 바꾸고 문서, 그래프 5장(`docs/reports/img/vlm-0*.png`), README 한 줄만 바꿨다.
- 결과: 문서에 적은 결과는 다음과 같다. 구조는 VLM 이 계획을 제안하고 관문이 항목별로 받거나 거절하며 거절된 항목은 규칙값으로 채운다. 사람 평가 1회에서 VLM 대 규칙이 51%(95% 36~66%)로 구별되지 않았고 A 자리 쏠림도 보였다. 리뷰어가 그래프 5장을 직접 열어 얼굴 사진이 없는 것(막대 · 점 그래프뿐)을 확인했다(댓글).
- 트러블슈팅(문서가 정리한 문제들):
  - 모델이 예시를 베꼈다 → 형식 E 로 풀고 Gemma 4 E4B 를 골랐다. 다만 모든 모델에서 사진 근거가 +5~16%p 로 약했다.
  - 처진 눈 판정 ILoveEye 의 α>β 가 눈꼬리 방향을 재지 못했다 → 사람 표시와 맞춰 보고 눈꼬리 기울기 5° 로 바꿨다.
  - 평가 사진에 문제가 있었다 → FFHQ 의 "bare" 사진에도 화장이 있었다 → 사진을 직접 보고 생얼·정면 30장으로 바꿨다.
  - v6(자유만 줌)에서는 값이 화장 종류마다 한 값으로 몰렸다 → v7(보통 얼굴과 비교한 말을 붙임)에서는 얼굴을 따라 갈렸지만 사진은 여전히 안 봤다.
  - 얼굴이 들어간 예시 그림은 사진 라이선스(CC BY-NC-SA, 평가 전용) 때문에 저장소에 못 넣는다 → 저장소 밖 `$DHE_DATA_DIR/vlm-eval/out/docs/` 에 두고 문서에는 경로만 적었다.
- 남긴 것: v6·v7 코드는 `vlm-freedom` 브랜치에만 기록으로 두고 병합하지 않는다. 이 문서를 근거로 VLM · LLM 자리를 옮기는 제안과 확인 실험을 #287 에 올렸다.

## 트러블슈팅

- **서버가 오류 메시지 없이 통째로 죽음 (10/07 하루 3번)**
  - 처음 대응: 별도 cmd 창에서 죽으면 5초 뒤 다시 켜는 반복 스크립트 (로컬 전용). 한국어 주석을 넣은 .bat 가 CP949 줄 합쳐짐으로 안 돌아 ASCII 로만 다시 씀
  - 원인 찾기: 기록으로 보니 Windows access violation, 위치는 모델 일부를 PC 메모리 ↔ 그래픽카드로 옮기는 순간(`enable_model_cpu_offload`). 글 해석 부품(7.5GB) + 그리는 부품(7.3GB)이 RTX 3060 12GB 에 다 안 들어가서 요청마다 옮기고 있었음
  - 근본 해결: 우리 지시문은 늘 같은 한 문장 → 글 해석(임베딩)은 처음 한 번만 계산해 파일로. 서버에는 그리는 부품 + 그림 변환 부품(7.4GB)만 통째로 → 옮기기 자체가 없어짐. ① `look-transfer-gen` 의 `embed.py` 와 같은 생각
- **결과 (RTX 3060 12GB)**
  - 한 장 15 ~ 18초 → 8.6초 (6장 연달아, 안 꺼짐)
  - 켜고 첫 장 약 60초 → 9초 · 그래픽카드 최대 8.7GB · 서버 켜기는 처음 한 번 101초 (임베딩 계산 포함)
  - 같은 맨얼굴 · 참고 사진 · seed 1234 로 어제 그림과 색 차 0.00
- **받은 사진 · 만든 그림이 서버 임시 폴더(Gradio)에 남음** — #328 댓글에서 약속한 것 → 2분 뒤 지우기. 대신 실사진 문제를 볼 때 임시 폴더에서 AI 결과를 꺼내던 방법은 이제 2분 안에만 됨 (페이지 '저장' 버튼으로)
- `poc/` 는 ruff · pytest 대상이 아니라 `py_compile` 로 문법만 확인

### #275 [app][score] 처진 눈 경계 5° — Lee 2020 class I 경계 · 논문 근거 (#266 후속)
- 브랜치: `fix/droop-tilt-5deg` · 병합 2026-10-01 · +81 −18
- 한 일: #266 이 4° 커밋까지만 병합돼서 뒤에 올린 논문 근거 · 5° 커밋을 main 위로 옮겼다. `personalize.ts` 의 `DROOP_TILT_DEG` 를 4° → 5° 로 바꾸고 주석에 논문 근거를 적었다. Lee 2020 요약(`docs/research/papers/개인화 근거/[JKAOMS 2020] …/요약.md`)과 논문 목록 README 를 넣었다. 리뷰에서 앱 통합 담당이 `PROMPT_VER` v4 → v5 커밋 하나를 얹었다.
- 결과: 근거 논문은 둘이다. Lee 2020(JKAOMS 46(6), 한국인 76명, 13~38세)은 0~5° = class I(14명, 평균 3.2°), 5° 초과 = class II(62명), 0° 미만 = class III(0명)이다. Jung 2020(AAPS 26(1), 한국 20대 여성 120명)은 쌍꺼풀 8.4° ± 2.9°, 외꺼풀 8.8° ± 3.0° 이고 5° 는 평균 − 1.2 SD, 아래 약 10~12% 다. 둘 다 원문에서 수치를 확인했다.
  - 사람 표시(1명, 27장)와의 일치: 0° 는 처진 눈 0장 · 20/27, 4° 는 5장 · 23/27("아님" 을 처진 눈으로 1), 5° 는 7장 · 22/27(2), 6° 는 11장 · 19/27(5).
  - Gemma 4 E4B + 형식 E(30장, daily·edgy): 4° 와 5° 모두 관문 100% · 측정값 뒤집기 100%, p95 5.8초 / 5.9초. 5° 에서 처진 눈 7장 → 라이너 14/14 `extend`, 나머지 23장 → 46/46 `winged`.
  - 테스트는 5° 경계 앞뒤(5.5 · 5 → winged, 4.5 · 2.3 → extend). `scripts/check.sh` 전부 통과. 병합 뒤 main CI 초록.
- 트러블슈팅:
  - 4° 는 근거가 표시 1명 · 27장뿐이었다(#266 리뷰 지적) → 4° 와 5° 는 사진 한 장 차이로 이 표본에서는 잡음 수준이다 → 표본에 맞춘 4° 대신 논문 경계 5° 를 쓴다.
  - Lee 2020 이 "class I = 처진 눈" 이라고 하지는 않는다(class 경계의 근거도 논문에 없다) → 논문은 경계의 위치를, 사람 표시는 그 경계가 처진 눈 인상과 맞는지를 받친다고 역할을 나눠 적었다.
  - (리뷰) 경계가 바뀌면 프롬프트의 판정 줄("5° 보다 작으면")과 4~5° 얼굴의 라이너 선택지가 달라지는데, 버전을 그대로 두면 서버 로그에서 4° 프롬프트와 5° 프롬프트를 가를 수 없다 → "프롬프트를 바꾸면 버전을 올린다" 는 규칙대로 `PROMPT_VER` 를 v5 로 올리고 `docs/vlm-server-handoff.md` 표기도 맞췄다.
- 남긴 것: 재는 방법이 다르다 — 논문은 사람이 찍은 눈꼬리, 여기는 MediaPipe 점이다. 이 30장 평균 6.7° 는 논문(약 8.4°)보다 약 2° 낮다 → #84 에서 실제 사진으로 같이 본다. 사람이 처진 눈이라 한 7장 중 3장(윗꺼풀 피부가 눈꼬리를 덮는 모양)은 어떤 경계로도 안 잡힌다. 기울기 4~5° 얼굴의 라이너 가이드가 `winged` → `extend` 로 바뀌므로(이 30장 중 2장) 골든 세트·채점 결과를 다시 봐야 한다. VLM 확인(30장)은 `vlm-prompt-v3` 으로 돌린 값이고 v5 로는 다시 돌리지 않았다. 표시 1명 · 27장이라 팀원 실제 사진으로 다시 맞춘다(#84).

## 트러블슈팅

- **후처리를 켤지 비용으로 못 정함 (#125)**
  - 문제: 변환행렬 · 블렌드셰이프를 켜면 느려질까 걱정 → 네 조합(V0~V3)을 같은 프레임에서 25초씩 측정
  - 원인: 차이가 1ms 미만으로 잡음보다 작았다 (켠 V2 가 끈 V0 보다 빠르게 나옴)
  - 해결: 비용 대신 **정확도**로 결정 — pitch 근사 오차가 게이트 폭의 절반(p95 6.45°)이고, 웃음은 블렌드셰이프만 냄(무표정 0.000 / 웃음 0.754) → V3. 숫자를 보기 전에 판정 기준을 README 에 먼저 적어 둠
- **얼굴 추론이 같은 장면에 두 번 돎 (#140)**
  - 원인: rAF 는 화면 주사율(60Hz)에 묶여 카메라(30fps)보다 자주 깨어남 → 실측 중복 57%. 기존 POC 가드(`now !== lastT`)는 `performance.now()` 라 한 번도 안 걸렸음
  - 해결: rVFC(새 장면에만) + 단조 증가 타임스탬프. 손 · 게이트 주기 확대와 합쳐 S23 기준 49.9 → 약 31ms
- **확인받기를 "가장 선명한 한 장" 으로 했다가 (#145)**
  - 문제: 한 장만 넘기면 ③ 의 여러 장 평균이 불가능
  - 해결: 정의서 정정(#143)대로 3~5장을 다 넘기고, 데이터를 못 만드는 장(얼굴 없음 · 478점 아님 · NaN · 이마 L* 못 잼)만 뺌. NaN 은 모든 비교를 통과해 버려서 먼저 거름
- **가림 판정에 손 모델(7.46MB)이 무거움 (#148)**
  - 해결: 이마 참조의 급변으로 판정 — 손 말고 머리카락 · 브러시도 잡힘. 알려진 구멍(입 · 볼 근처 가림)은 ③ 의 중앙값(#147)이 보완
- **연습 코드 라이너가 두께를 안 그림 (#154)**
  - 문제: 사용자가 얼마나 두껍게 칠할지 알 수 없었음
  - 해결: 속눈썹 선 → 꼬리 끝 → 위로 `thick × 눈 폭` 윤곽. 연습 코드를 복사하지 않고 테스트부터 새로 씀(연습 코드엔 검증 0개)
- **#167 리뷰에서 나온 것**
  - 묶음을 비트맵으로 바꾸다 실패하면 멈춤 → 화면 4 를 다시 열게, 바꾸는 사이 화면을 떠났으면 아무것도 안 하게 (D1~D4)
  - iPad 가로에서 양옆이 잘려 부위 가시성이 틀림 → 화면에 실제로 보이는 영역(`coverView`)으로 판정
  - main 의 개인화 계획(#172)과 `main.ts` 충돌 → 화면 3 · 4 · 5 가 같은 `guideFor` 를 쓰게 합침

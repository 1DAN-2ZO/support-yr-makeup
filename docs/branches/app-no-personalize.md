### #299 [app] "개인화"를 뺌 — 모두 같은 표준 계획, 화장을 누르면 바로 2-b AR, VLM 없어도 앱이 돎
- 브랜치: `app-no-personalize` · 병합 2026-10-05 · +219 −356
- 한 일: 얼굴을 재서 화장 모양을 바꾸던 "개인화" 를 앱에서 떼고, 모든 사람이 같은 표준 계획(`standardPlan()`)으로 그려지고 채점되게 했다. 얼굴에 맞추는 일(자리 · 크기)은 얼굴 점이 이미 하고, 개인화가 더하던 것은 규칙 세 개(처진 눈이면 라이너 꼬리를 곧게 · 눈두덩으로 섀도 높이 0.8~1.2배 · 얇은 윗입술이면 오버라인)뿐인데 근거가 약했기 때문이다(처진 눈 5° = 평가자 1명 · 27장, VLM(그림을 보는 언어 모델)은 규칙과 구별 안 됨).
- 결과: 화장을 누르면 "개인화 중입니다…" 기다림(최소 1.5초) 없이 바로 2-b AR(얼굴에 화장을 입혀 보는 화면)로 간다. `main.ts` 에서 VLM 서버 확인 · "이용 불가" 막음 · 계획 대기열 · VLM 호출을 뗐다(−140줄). 새 테스트 `standard-plan` SP1~SP4 · `looks-screen` · `fullrender-plan` FP1 · FP2 를 먼저 쓰고 실패를 확인한 뒤 통과시켰다. `scripts/check.sh` 통과(pytest 86 · vitest 897 · 타입 · 린트). 배포용 빌드를 VLM 주소 없이 만들어 크롬으로 열었더니 동의 화면이 떴다. 병합 뒤 main CI 초록.
- 트러블슈팅:
  - 문제: 계획을 아예 없애면(`planGuide(x, null)`) 라이너 꼬리가 ② 가이드의 기본 꼬리(30° · 눈 폭 15%)로 바뀌어 모든 사람의 테두리와 채점 기준이 달라진다 → 푼 방법: 규칙이 "바꿀 것 없음" 으로 본 얼굴이 받던 계획(위로 올리는 꼬리 15° · 12%, 배율 1)을 표준으로 삼았다. 처진 눈이 아니고 · 눈두덩이 표준이고 · 윗입술이 충분한 얼굴은 테두리 · 채점 기준이 전과 똑같다(`standard-plan.test` SP2 — 화장 10종 × 부위 전부 같음).
  - 문제: VLM 서버가 없으면 배포판이 "지금은 이용할 수 없어요" 에서 멈췄다 → 원인: 앱이 켜질 때 VLM 서버를 확인하고 막았다 → 푼 방법: 그 확인과 막음을 떼어 서버 없이도 켜지게 했다.
  - 문제: `fullrender.ts` 에 계획을 안 넘기면 카메라 얼굴로 규칙 계획을 만들던 숨은 길이 있었다 → 푼 방법: 그 길도 표준 계획으로 바꿨다. FP1 은 일부러 틀린 계획을 넣어 실패하는 것도 확인했다.
  - 병합 뒤 확인(댓글): 표준 계획의 라이너 꼬리(15° · 눈 폭 12%)가 ④ 서버 담당의 실험 화면에서 화장 10종을 맞출 때 쓰던 꼬리와 같았다(`makeup-probe.ts` 는 늘 스타일을 넘겨서 30° 기본 꼬리를 쓴 적이 없다).
- 남긴 것: 눈꼬리 기울기 5° 미만(처진 눈) · 눈두덩이 표준보다 좁거나 넓은 얼굴 · 얇은 윗입술 얼굴은 테두리 · 채점 기준이 바뀐다(위로 올리는 꼬리 · 섀도 1배 · 오버라인 0). `resolvePlan` · `vlm-flow` · `vlm-client` · `vlm-prompt` · `plan-queue` · `vlm-image` 와 그 테스트, 실험(`eval/vlm`), 세션의 `plans` 칸은 지우지 않고 연결만 끊었다. ① 촬영 담당의 동의 화면 문구("맨얼굴 사진 3장을 서버로 보내…")가 이제 사실과 안 맞는데 이 PR 에서는 안 고쳤다(#300 으로 넘김). 촬영을 지나 화장 선택 → 2-b AR → 화면 3 · 4 · 5 를 실제 카메라로 끝까지 돌려 보지 못했다(헤드리스 크롬). 폰 확인(#290) 때 보기로 했다.

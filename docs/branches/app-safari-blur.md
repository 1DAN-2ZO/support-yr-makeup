### #271 [app] 사파리에서 화장이 딱딱한 도형으로 나오던 것 — 번짐 기능이 없으면 줄였다 키워 번지게 (2-b AR · 화면 3)
- 브랜치: `app-safari-blur` · 병합 2026-10-01 · +160 −14
- 한 일: `screens/makeup-paint.ts` 가 캔버스 번짐 기능(`ctx.filter`)이 있는지 한 번 감지한다(브라우저 이름이 아니라 기능으로). 있으면 전과 똑같이 그리고(윈도·안드로이드 영향 없음), 없으면 그린 뒤 절반씩 여러 번 줄였다가 두 배씩 다시 키워 번지게 한다(`softenByResize` · `softenLevels`). 글리터 점은 번짐이 끝난 뒤에 찍는다. 채점은 안 바뀐다.
- 결과: 헤드리스 크롬에서 번짐 기능을 꺼 놓고 같은 얼굴에 그려 비교했다. 절반씩 여러 단계 방식은 볼·쉐딩이 부드러워 기준과 거의 같고, 섀도우·눈썹도 부드럽고, 글리터 점은 또렷했다. 시험 `makeup-paint-nofilter.test.ts` N1~N4 — 고치기 전 실패 확인. CI 와 같은 조건에서 `scripts/check.sh` 통과(vitest 823). 서버 담당이 macOS/iOS 사파리 실기기에서 2-b AR·화면 3 완성본 모두 볼·쉐딩·섀도우 가장자리가 계단 없이 번지고 글리터 점도 또렷함을 확인했다. 단계 수는 지금 값 그대로 뒀다(댓글).
- 트러블슈팅:
  - 아이폰(사파리)에서 2-b AR 과 화면 3 완성본의 화장이 번짐 없이 딱딱한 도형으로 나올 수 있었다 → 일부 사파리에는 캔버스의 번짐 기능(`ctx.filter`)이 아예 없어서 번짐 지정이 조용히 무시된다. 서버 담당이 실험 화면에서 실기기로 찾아 고쳤고(#263) 앱 그리기에도 같은 문제가 있었다 → 번짐 기능이 없으면 줄였다 키워서 번지게 한다.
  - 처음에는 서버 담당 방식대로 한 번에 크게 줄였다 키웠더니(번짐이 큰 볼·쉐딩은 20분의 1까지) 볼·쉐딩에 계단 모양이 보이고 섀도우·눈썹이 조금 각졌다 → 중간 픽셀을 건너뛴다 → 절반씩 줄이면 단계마다 이웃 네 픽셀이 고르게 섞인다. 번짐이 클수록 단계를 늘린다.
  - 번짐 기능이 없는 쪽에서 글리터 점도 같이 번진다(서버 담당 실험 화면, #263) → 글리터 점을 번짐이 끝난 뒤에 찍는다.
  - 기존 그리기 시험(`makeup-paint-fx` · `-lash`)의 가짜 컨텍스트 → "번짐 기능 있음" 으로 맞춰 그대로 통과시켰다.
  - (댓글) 작성자는 사파리 실기기가 없어 크롬에서 기능을 꺼 놓고 흉내만 냈다 → 실기기 확인과 이후 수정을 서버 담당에게 넘겼다. 실험 화면(`makeup-probe.ts`)의 `blurByDownscale` 에도 같은 계단 현상이 있어 서버 담당이 같은 방식으로 맞췄다(#274).
- 남긴 것: 앞으로 그리는 방식(효과 · 번짐 · 텍스처) 수정은 서버 담당이 `makeup-paint.ts` 에 직접 PR 로 올리고 앱 통합 담당이 리뷰·병합한다. 앱 통합 담당은 그 파일에서 앱에 잇는 부분(화면 3 · 2-b 에 넘기는 것, 머리카락 마스크 · 셰이더)만 맡는다.

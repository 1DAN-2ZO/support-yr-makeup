### #328 [docs] 피드백(화면 6)이 받는 그림 — 첫 배포는 지금 것으로, 그다음 요청은 "옮긴 그림" 하나 (① · ②)
- 브랜치: `docs/feedback-input-contract` · 병합 2026-10-07 · +83 −0
- 한 일: 화면 6 피드백(③ 채점 담당)이 받는 그림의 조건을 문서 하나(`docs/feedback-input-contract.md`)로 정리했다. 누가 만들든 같은 형식으로 받도록 "지킬 것" 다섯 가지를 적었다. 코드 변경은 없다(문서 1개 + 색인 한 줄).
- 결과: 첫 배포는 맨얼굴 · 시도사진 · 정답사진만 있으면 입술 · 섀도우 · 눈썹 문장이 나온다. 그다음 요청은 "옮긴 그림" 하나이고 라이너 꼬리 길이에 쓴다. 병합 때는 #327 · #328 · #329 · #330 을 함께 받아 pytest 119 · vitest 1142 · 타입 · 린트 통과, main CI 통과.
- 트러블슈팅:
  - 문제: 촬영 화면 사진(2160 x 3840)을 먼저 줄이면 눈 폭이 52px 이 되어 라이너 꼬리가 사라진다 → 푼 방법: "지킬 것" 3번으로 "줄이기 전에 얼굴을 먼저 자르기" 를 적었다.
  - 문제(⑥ 앱 통합 담당 댓글): 시도사진 화면이 사진을 긴 변 1024 로 줄여서 넘기고 있어 "지킬 것" 3번에 걸렸다 → 푼 방법: #330 에서 원본 크기로 넘기게 고쳤다.
  - 문제(③ 댓글): ⑥ 이 정한 묶음 간격 80ms 는 시험해 본 적이 없다. 확인한 것은 0.2초 간격 · 1초 동안의 다섯 장이고, 간격이 짧으면 다섯 장이 서로 너무 비슷해서 흔들림을 덜 줄일 수 있다 → 푼 방법: `ATTEMPT_BURST` 의 간격을 200ms 로 바꿔 달라고 요청했다(덕현 결정, 2026-10-07 — #335 에서 반영).
  - 숫자 어긋남(② 가이드 담당 댓글): RTX 3060 에서 그림 한 장이 15~17초 걸려 문서의 7~9초보다 길다 → ③ 이 문서의 7~9초 옆에 적어 두기로 했다.
  - ② 댓글에서 정리된 것: 옮긴 그림은 서버가 아니라 폰 세션 저장소(`core/session-store`)에 정답사진 옆에 둔다(`answer` · `moved` 칸). 만드는 함수는 하나((맨얼굴, 화장 사진) → AI 서버(FLUX.2 klein) → 그림)다. 지금 klein 서버는 얼굴을 먼저 자른 뒤 768 로 맞추고 원본 크기로 되붙인다.
  - 댓글에서 정해진 것(2026-10-07): 옮긴 그림을 넣는다 — 시도사진(눈 뜬 장)을 서버로 보낸다. 서버로 보내는 장은 다섯 장 중 가운데(셋째) 장이다. 묶음이 1~4장이어도 `feedbackWhole` 은 값마다 가운데 값으로 판정하므로 괜찮다.
- 남긴 것: 정답사진 만드는 방식(① #323 · ② #324)이 두 벌이라 하나로 정하도록 이슈를 올렸다. 옮긴 그림을 받는 자리 · 화면 6 에서 기다리는 방법은 방식이 정해진 뒤로 미뤘다. 서버가 만든 그림을 임시 폴더(Gradio)에 남기는 것은 배포 전에 ② 가 고치기로 했다. 감은 장은 지금 피드백에 쓰지 않는다.

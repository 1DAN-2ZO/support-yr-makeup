# `guide-frame-loop` — 공용 카메라 루프: 카메라 새 장면에만 얼굴 찾기 (화면 4 · 촬영)

촬영 화면이 화면 그리기(rAF, 60 · 120Hz)마다 얼굴을 찾아 같은 장면을 두세 번 분석하던 것을, 공용 도우미로 모아 카메라 새 장면에만 부르게 한 브랜치. 같이 화면 4 의 카메라 노출 잠금 문제도 고침.

- ⚠ ① 파일 두 곳(`screens/capture.ts` · `screens/capture-probe.ts`) — 루프 예약/정리만 바꿈

## 한 일

- `screens/camera-loop.ts` `startFrameLoop(video, (now) => …, { onError? }) → stop()`
  - rVFC 가 있으면 새 장면마다, 없으면 rAF
  - `now` 는 늘어나기만 함(같거나 거꾸로 오면 직전 + 1) — `detectForVideo` 에 그대로
  - 다음 장면을 먼저 예약하고 콜백을 부름(오류를 삼키지 않음), `stop()` 뒤에는 안 불림
  - 가렸다 돌아왔을 때 영상이 멈춰 있으면 다시 틂 (rVFC 는 멈춘 영상에서 안 불림)
- 화면 4 · 촬영 · 촬영 측정 도구를 도우미로. 2-b AR 은 ⑥ 이 따로
- 화면 4 카메라 잠금을 촬영과 같게(`DEFAULT_LOCKS` — 지금은 안 잠금), 켤 때 · 끌 때 남은 잠금 풀기

## 트러블슈팅

- **같은 장면을 두세 번 분석**
  - 원인: 화면 그리기(rAF)는 60 · 120Hz, 카메라는 30fps
  - 해결: rVFC — 바꾸기 전 촬영은 화면만 4번 다시 그려도 분석 4번 → 바꾼 뒤 0번 (CS1)
- **화면 4 가 켜고 1.5초 뒤 하얗게 날아가 "너무 밝아요" 로 막힘 (PC 시험)**
  - 원인: ① 이 촬영을 색 · 초점만 잠그게 바꿨는데 화면 4 는 노출까지 잠금
  - 해결: 화면 4 도 같은 잠금. PC 웹캠은 잠금이 기기에 남아 고친 뒤에도 하얬는데, 콘솔에서 `exposureMode` 를 `manual` → `continuous` 로 돌리자 정상 → 남는 문제 · 파란 색감은 ① 에게 #267 로 넘김
- **main(① #268 카메라 잠금 안 함)과 충돌**
  - `capture.ts` · `capture-probe.ts` 의 import 줄과 끄기 — 둘 다 살림. ⑥ 리뷰대로 화면 4 도 켤 때 · 끌 때 잠금을 풀고, 잠글 게 없으면 1.5초 안 기다리게 (CS4 · CS5)
- **PC 웹캠이 640×480 이라 눈 폭 조건에 걸림** — 시험 중에만 임시로 낮췄고 커밋엔 없음

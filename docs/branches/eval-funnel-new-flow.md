### #319 [eval] 퍼널 집계를 새 흐름 화면으로 — 이탈 위치 줄 추가
- 브랜치: `eval-funnel-new-flow` · 병합 2026-10-07 · +112 −20
- 한 일: 사용 기록을 모아 표로 내는 퍼널 집계가 옛 흐름 화면 이름(`looks` `fullrender` `live` …)으로 세고 있어서 새 흐름 화면으로 바꾸고, 어느 화면에서 나갔는지(이탈 위치) 줄을 더했다.
- 결과: 화면 순서는 `consent → capture → answer → partguide → attempt → feedback → save` 로 앱의 `SCREEN_ORDER` 와 같다. 이탈 위치는 끝(저장)까지 못 간 세션이 가장 멀리 간 화면의 비율이다(예: `이탈 위치 · capture(%) 50.0 (2/4)`). "리뷰 도달률" 은 "피드백 도달률" 로 바꿨다. 테스트를 먼저 고쳐 실패 확인(7개)한 뒤 통과시켰다. `ruff` · `pytest` 90개 통과. 병합 때는 #322 · #317 · #319 · #324 를 함께 받아 pytest 119 · vitest 1010 · 타입 · 린트 통과, main CI 통과.
- 트러블슈팅:
  - 문제: "나갔다" 신호는 폰에서 안 올 때가 많다 → 푼 방법: 들어간 화면 기록만으로 이탈 위치를 본다. 뒤로 갔다가 나가도 가장 멀리 간 화면으로 센다(도달률과 같은 기준).
  - 문제: 옛 로그에는 옛 화면 이름이 남아 있다 → 푼 방법: 앱이 옮기는 자리로 센다(`looks`·`fullrender` → 정답사진, `guide`·`live`·`result` → 부위 가이드, `review` → 피드백 — 앱 `inNewFlow` 와 같은 표).
- 남긴 것: 부위 상태 · 확인만 이유 · 채점 시간 · 개인화 줄은 그대로 뒀다. 새 흐름에서는 그 기록이 안 남아 줄이 비거나 안 나온다 — ③ 채점 담당의 피드백이 무엇을 기록할지 정해지면 맞추기로 했다. 앱(client)은 안 건드려서 앱 쪽 검사는 CI 에 맡겼다.

# 촬영 체크리스트 (v1, 2026-09-18)

팀원끼리 찍는 1차 촬영용. 분업 5-1·5-2, 데이터 계획 A-2.
동의서는 `consent-form-v1.html`, 기록표 양식은 `templates/` 폴더.

---

## 1. 이번 촬영의 목표

앱 채점이 사람 판단과 맞는지 잴 **시험지**를 만든다. 그래서 잘 그린 사진과 틀리게 그린 사진이 **둘 다** 필요하다.

| | 1차 (이번) | 2차 | 문서상 목표 |
| --- | --- | --- | --- |
| 부위 | 아이라이너만 | + 눈썹·입술 | 5부위 |
| 인원 | 팀원 6명 | 팀원 + 지인 | 20명 |
| 사람당 | **3장** | 5장 | 10장 |
| 합계 | 18장 | 30장(골든 세트 크기) | 200장 |

**1차의 목적은 정확도 숫자가 아니라 "진짜 사진에서 되는가"다.** 지금 채점은 가상 화장으로만 검증돼 있어서, 실제 사진을 넣으면 정합·조명·검출에서 문제가 터질 가능성이 높다. 그 문제를 먼저 찾아 고친 뒤에 부위와 인원을 늘린다.

### 촬영보다 공개 데이터셋이 먼저 (2026-09-18 결정)

"앱이 실제 사진에서 화장 영역을 찾는가"는 **공개 데이터셋으로 먼저 확인한다.** FFHQ-Makeup은 같은 얼굴의 맨얼굴·화장 쌍이 정면·정렬된 상태로 있어 우리 파이프라인에 그대로 넣을 수 있고, 평가(시험지) 용도로는 라이선스도 맞다.

| 확인할 것 | 공개 데이터셋 | 자체 촬영 |
| --- | --- | --- |
| 화장 영역을 찾는가 | **가능** | 가능 |
| 이탈률 계산이 도는가 | **가능** | 가능 |
| 이탈률 분포로 등급 경계를 정하기 | **가능** | 가능 |
| 조명·자세가 바뀌어도 되는가 | 불가 | **필요** |
| 사람 감각과 등급이 맞는가 | 불가 | **필요** |

그래서 순서를 이렇게 둔다.

1. 공개 데이터셋으로 검출·이탈률 확인 → 문제가 있으면 코드 먼저 고친다
2. 이탈률 분포를 보고 등급 경계(예: 60% 이상 = 많이 벗어남)를 **설계값으로 정한다.** 이 경계는 우리가 정하는 값이고, 발표에서도 "설계값"으로 밝힌다
3. 그 뒤에 자체 촬영으로 조명·자세 변화와 사람 감각 확인

이 문서의 촬영 계획은 3단계용이다. 촬영 규모는 1·2단계 결과를 보고 줄일 수 있다.

## 2. 준비물

- 폰 1대 (전면 카메라). **가능하면 촬영 내내 같은 폰**
- 아이라이너 — 위생상 **사람마다 따로** 쓰거나 본인 것 사용 (2차에서 눈썹 펜슬·립 추가)
- 클렌징 티슈, 면봉
- 인쇄한 동의서 (사람 수만큼), 펜
- 삼각대나 거치대 (없으면 책 위에 폰 세우기)

## 3. 한 사람당 순서 (약 5분)

1. 동의서에 서명받는다. 선택 항목은 본인이 직접 표시.
2. 참가 번호를 정한다 (`person_01`, `person_02` …).
3. 자리에 앉히고 폰 위치를 고정한다. **이 자리는 3장 내내 바뀌지 않는다.**
4. 아래 3장을 순서대로 찍는다. 화장은 **지우지 않고 쌓아 올린다.**

| # | 무엇을 | 비고 |
| --- | --- | --- |
| 1 | 맨얼굴 (눈 뜬 상태) | 비교 기준. 없으면 나머지가 무의미 |
| 2 | 아이라이너 제대로 그리고 | 잘 그릴 필요는 없다. 초보가 그린 상태가 실제 사용 상황 |
| 3 | 아이라이너 한쪽 꼬리만 위로 올려 덧그리기 | **틀린 표본**. 전원이 할 필요는 없고 1~2명이면 된다 |

- 1차는 아이라이너만 본다. 채점 방식(맨얼굴 대비 색 변화 → 가이드와 겹침)은 부위마다 같아서, 한 부위에서 되면 방식 자체가 검증된다.
- 초보가 그리면 자연스럽게 어긋나므로 "조금 벗어남" 표본은 따로 만들 필요가 없다. 3번은 "많이 벗어남" 표본 확보용이라 1~2명이면 충분하다.
- 그리는 사람은 본인이 아니어도 된다.
- **여유가 되면**: 라이너를 지우고 2·3번을 한 번 더 반복하면 사람당 5장, 6명이면 30장이 되어 골든 세트 크기를 채운다.

### 2차에서 추가할 것

눈썹과 입술을 같은 방식으로 쌓아 올려 찍는다(맨얼굴 → 눈썹 → 라이너 → 입술 → 틀린 장). 섀도우·볼터치는 점수를 매기지 않고 "확인만" 하는 부위라 넣지 않는다.

## 4. 촬영 규칙 (이게 틀리면 데이터가 못 쓰게 된다)

- **같은 자리, 같은 조명, 같은 폰**으로 3장을 찍는다. 자리를 옮기면 색이 달라져 비교가 깨진다.
- 얼굴이 **화면 폭의 60% 이상** 차게. 너무 멀면 라이너가 안 보인다.
- 정면을 보고, **눈을 뜬 상태**로.
- 손이나 브러시가 얼굴에 닿지 않은 상태에서 찍는다.
- 안경은 벗는다. 앞머리는 이마가 보이게 넘긴다(밝기 기준을 이마에서 잰다).
- 자동 필터·뷰티 모드는 끈다.

## 5. 조명과 각도는 사람마다 나눈다

한 사람이 여러 조명에서 찍기 어려우니 배정한다.

| 사람 | 조명 | 각도 |
| --- | --- | --- |
| person_01, 02 | 창가 (자연광) | 정면 |
| person_03, 04 | 실내등 | 정면 |
| person_05 | 어두운 곳 | 정면 |
| person_06 | 실내등 | 고개 15° |

## 6. 파일 이름과 저장

```
person_01_01_bare.jpg        맨얼굴
person_01_02_liner.jpg       아이라이너
person_01_03_liner_wrong.jpg 일부러 틀린 라이너
```

2차에서 부위가 늘면 `_brow`, `_lip`을 같은 규칙으로 붙인다.

- 원본은 `DHE_DATA_DIR`(팀이 정한 로컬 폴더)에만 둔다. **GitHub 저장소에 올리지 않는다.**
- 서명받은 동의서는 사진으로 찍어 `DHE_DATA_DIR/consent/person_01_consent.jpg`로 저장한다.
- 이름과 참가 번호를 잇는 표(`participants.csv`)도 저장소 밖에 둔다.

## 7. 찍은 뒤에 할 일 — 라벨 붙이기

사진만 있으면 시험지가 아니다. 사람이 보고 판정을 적어야 정답지가 된다.

1. `templates/labels.csv`를 복사해 사진마다 한 줄씩 적는다.
2. 앱이 낸 판정과 점수를 보고 **동의 / 비동의**만 표시한다. 비동의일 때만 이유를 한 줄 적는다. 3단계(잘 그림·조금·많이)로 적는 것보다 빠르고, 우리가 확인하려는 것("앱 판정이 말이 되는가")에 그대로 답한다.
3. **팀원 2명이 서로 안 보고 따로 적는다.** 다르면 3번째 사람이 정한다.
4. 두 사람이 얼마나 같게 적었는지도 숫자로 남긴다. 이게 앱 성능의 상한선이다.

얼굴형(계란·둥근·각진·긴·하트)도 사람마다 2명이 따로 적는다.

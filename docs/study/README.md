## 1. `docs/tech-stack-and-datasets` (PR #1, 73개 파일)

프로젝트 초반에 "무슨 기술과 데이터로 만들 수 있는가" 를 조사하고 직접 돌려 본 브랜치.

### 결과

- **문서**: 필요 기술 목록(`tech-stack-v6.md`), 선행 연구 크로스체크(`related-work-v6.md`), 데이터셋 순위표(최선 · 차선 · 이유 · 상용 가능 여부, 라벨링 · 파인튜닝 방법)
- **데이터셋 실측** (`poc/datasets-eval/`): 공개 데이터 6종 200장을 같은 파이프라인에 넣어 비교
- **합성 학습 데이터 생성기** (`poc/synth/`): 맨얼굴 사진에 화장을 그려 넣고 정수 라벨 PNG 를 같이 내보낸다. 색 팔레트 19개 → 48개, 자동 검증 27개
- **촬영 샘플** (`poc/samples/phone-portraits-20/`): 5명 × 4장

### 트러블슈팅 · 발견

| 무엇이 문제였나 | 어떻게 풀었나 |
|---|---|
| 쓰려던 공개 데이터 · 모델에 비상업 라이선스가 섞여 있었다 (위험 5건) | 건마다 대체안을 정리하고, 분할 모델 학습 데이터는 **자체 합성**으로 바꿨다 |
| 0차 학습에서 클래스 가중치를 넣으면 좋아질 줄 알았다 | 돌려 보니 오히려 손해였다 → 결과를 학습 문서에 그대로 남겼다 |
| MediaPipe 가 1.0 에서 Tasks API 로 바뀌어 예전 코드가 안 돌았다 | Tasks API 로 옮기고, 브라우저 경로와 파이썬 경로의 결과 차이를 쟀다 |
| 홍채 지름으로 mm 를 재려 했다 | 재 보니 홍채 ÷ 눈 너비가 사람 라벨 0.51, MediaPipe 0.45 로 달랐다 → 순위표에 기록. 팀은 9/16 에 홍채 척도를 빼고 눈 폭 · 입술 폭 · 얼굴 폭 비율로 정했다 |
| 화장을 하면 랜드마크가 움직일 수 있다 (선행 연구에서 발견) | 위험으로 기록했다 (`related-work-v6.md` 8번 — 맨얼굴 vs 화장 후 이동량을 재 보기) |

### 3-5. 아직 남은 것

- 조명 3종 × 사람 3명 측정(1-4)과 가정값 확정 — 촬영 세션 #58 대기
- 정면 고개 숙임(pitch): 코드는 ±15°, 정의서는 ±5° 인데 똑바로 서도 −5.9 ~ +3.4 가 나와서 ±5 면 정상이 막힌다. "숙임" 을 재고 정한다
- 꼬리 판정은 연구용 공개 자료(상업 이용 불가)와 팀원 사진으로 맞췄다. 정답 표시도 한 사람 눈대중이다 → 사업화할 때는 쓸 수 있는 사진으로 다시 맞춰야 한다
- 룩 옮기기 생성 서버는 RTX 4080 에서만 돌려 봤다. 짧은 꼬리(눈 폭의 15% 미만) · 블러셔는 잘 못 옮긴다

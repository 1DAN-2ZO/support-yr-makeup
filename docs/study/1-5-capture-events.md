# 1-5 공부 기록 — 촬영 이벤트 찍기 consent · capture · restore (2026-09-21)

> 이슈 #13. 브랜치 `capture`. **커밋 없이 검증만**. 이 문서도 미커밋.
> 기다리는 쪽: 모듈 ⑥(이탈 퍼널 집계). 1-2·1-3 실측 뒤라서 폰에서 실제로 찍힌 이벤트로 검증했다. 1-4 는 보류 중.

## 1. 1-5 가 하는 일 한 줄

촬영 화면에서 일어나는 일을 **숫자 요약만** 공통 `log()` 로 남긴다: 동의 결과(`consent`), 장별 촬영 성공·실패·재촬영(`capture`), 앱 복귀 복원(`restore`). ⑥ 은 이 줄들만으로 "동의 거부율 → 촬영 완주율 → 장별 재촬영" 퍼널을 계산한다. 사진·좌표는 절대 안 남긴다.

## 2. 들어가는 기술 — 최선·차선·왜

| 요소 | 최선 (쓴 것) | 차선 | 왜 최선인가 |
|---|---|---|---|
| 로그 출구 | 공통 `createLogger().log()` 하나 (`log.ts`) — sid·t·screen·part·ver 자동 부착, 한 줄 JSON | 모듈마다 `console.log` | 전 모듈이 같은 모양이라 ⑥ 집계 스크립트 하나로 끝난다. 금지 키(`lm`·`pts`·`image`…)는 `log()` 가 throw 로 막는다 |
| 이벤트 모양 | `types.ts EventFields` 판별 유니온 (`{name:"capture"; shot; ok; retry; reason}`) | 자유 객체 `{name, ...any}` | 필드 오타·누락을 컴파일이 잡는다. 새 이벤트는 표(`work-split §2`)에 먼저 적고 타입에 넣는 규칙 |
| 재촬영 횟수 | `createCaptureEvents` 가 장별 `retries` 를 세고 `capture.retry` 에 넣음 | ⑥ 이 로그를 뒤에서 세기 | 찍는 쪽이 세면 줄 하나에 답이 있어 집계가 단순. `retake()` 호출 = 사용자가 "다시" 를 누른 순간 |
| **`capture ok=false` 를 찍는 시점** | **같은 조건(firstFail)에 3초 이상 막혀 있을 때 그 조건으로 한 번** (`blocked()`, `stuckMs=3000`) | 프레임마다 / N프레임마다 / 재촬영 누를 때만 | 자동 촬영이라 "시도" 라는 순간이 없다. 프레임마다면 초당 17줄, 30프레임마다면 기기 속도(17fps vs 30fps)에 따라 뜻이 달라진다. 재촬영 때만 찍으면 오늘처럼 재촬영 0회인 세션에서 "오른쪽 45° 가 18초 걸린 이유" 가 사라진다. 사람이 느끼는 시간(3초) 기준이 기기와 무관하고 ⑥ 의 "어느 조건에서 막히나" 에 바로 쓰인다 |
| 얼굴 놓침 | `landmark_lost{ms}` — 1초 이상 놓쳤다 찾았을 때 (`faceLost()`) | 안 찍음 | 계약 표에 이미 있는 이벤트. 1-2 에서 오른쪽 45° 에 52프레임(≈3초) 놓친 게 시간을 잡아먹었는데 이벤트가 없어 로그로는 안 보였다 |
| 저장 | 메모리 sink (테스트·프로브) → 기기에서는 IndexedDB (⑥ 담당) | 바로 서버 전송 | 규칙: 기기 안에 먼저 쌓고 실험 동의 때만 내보낸다 |

## 4. 공부할 스킬

| 스킬 | 왜 | 어디서 |
|---|---|---|
| 판별 유니온으로 이벤트 정의, `EventBase & EventFields` 교차 타입 | 자동 필드와 이벤트 필드를 분리하면서도 한 객체로 | `types.ts` |
| 클로저로 상태 숨기기 (`retries`, `cur` 를 함수 안에 두고 메서드만 노출) | 밖에서 재촬영 수를 못 바꾸게, 테스트는 `retries()` 로만 읽게 | `capture-events.ts` |
| 시간 기반 디바운스 (같은 값이 T ms 이어질 때 한 번) | 프레임 루프에서 이벤트 폭주를 막는 표준 방법 | `blocked()` |
| 한 줄 JSON(JSONL) → 집계 | ⑥ 퍼널 스크립트가 읽는 형식. `sid` 로 세션 묶고 `t` 로 정렬 | `scratchpad/study15/funnel_check.py` |
| 로그에 넣으면 안 되는 것 | 개인정보: 사진·좌표뿐 아니라 파일명·경로도 금지 키 | `log.ts FORBIDDEN_KEYS` |

## 5. 검증 방법

1. 1-2 폰 실측이 남긴 이벤트 15줄을 파이썬으로 읽어 ⑥ 퍼널을 **실제로 계산**해 본다 (동의 → 완주 → 장별 시간·재촬영·실패 이유). 금지 키·자동 필드도 확인
2. 새 규칙(`blocked` 3초, `faceLost` 1초)을 vitest 로 검증 (4개 추가 → 8개)
3. 프로브를 새 규칙으로 바꿔 다음 폰 측정 때 실제 줄 수·내용 확인

당화응 · 2026-09-23 · ⑥ · 대상: `ai-pipeline-v6.md` §1 호출 그래프의 모든 **"실패 시"**

> **한눈에**
> 문서에 적힌 실패 경로 15개 중 **7개가 코드에 있고 검증이 따라붙는다.** 4개는 담당 모듈이 아직 안 만든 것(추적 중), 3개는 **문서가 낡은 것**, 1개는 **계약과 정의서가 어긋난 것**이다.
> 낡은 문서 3건은 이 확인과 같은 PR 에서 고쳤다. 어긋난 계약 1건은 ②③ 과 함께 고쳐야 해서 따로 올렸다.

판정 기준은 셋이다.

- **있다** — 코드가 문서대로 떨어지고, 그것을 깨면 실패하는 검증이 있다
- **아직** — 담당 모듈이 그 조각을 안 만들었다. 이슈 번호를 적는다
- **안 맞다** — 코드·문서·정의서 중 둘이 서로 다르다

## 3. 안 맞는 것 둘

### 3-1. `check_only` 이유 이름이 정의서와 다르다 — `hand` vs `occluded`

정의서는 2026-09-23 정정으로 **"손 없음" 을 "가려지지 않음" 으로** 바꿨고(#144·#148), `check_only(reason='occluded')` 라고 적는다(F-07). 계약(`types.ts`)은 아직 `hand` 다.

| | 정의서 (2026-09-23) | 계약 `types.ts` |
|---|---|---|
| 확인만 이유 | `occluded` | `hand` (100행) |
| 게이트 첫 실패 | 가림 | `hand` (77행) |

이름만의 문제가 아니다. 사용자에게 나가는 문구가 **`"손에 가려서 재지 못했어요"`** (`score.ts:131`) 인데, 실제로 가리는 것은 머리카락·브러시·퍼프·마스크가 더 많다 — #148 이 손 검출을 뺀 이유가 바로 그것이다. **브러시에 가려 놓고 "손에 가려서" 라고 말하게 된다.**

**지금이 제일 싸다.** `hand` 를 **내는 곳이 코드에 하나도 없다** — 타입·문구·검증 픽스처 한 줄뿐이다. ② `gate.ts`(#21)와 ③ #34 가 올라오면 그때는 세 모듈을 맞춰야 하는 변경이 된다. 계약 변경이라 ②③ 동의가 필요해 **#155** 로 올렸다.

### 3-2. 서버 장애 — 문서가 결정 #8 이전에 멈춰 있었다

`ai-pipeline-v6.md` 의 원칙 문단이 **"서버 장애는 이용 불가가 아니라 '룩 준비 중' 이어야 한다 — 팀 결정"** 으로 열어 둔 채였다. 2026-09-21 **결정 #8** 이 반대로 정했고(이용 불가, 룩 없이 진행하는 대체 흐름 없음), 정의서(§39)와 코드(`processing.ts:36`)는 결정 #8 을 따른다. **코드가 맞고 이 문서만 낡았다** — 이 PR 에서 고쳤다.

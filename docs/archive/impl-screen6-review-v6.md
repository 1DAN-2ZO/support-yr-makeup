## A-2. 데이터 구조

```
PartResult {
  partId: 'brow' | 'liner' | 'shadow' | 'lip' | 'cheek' | 'contour'   // contour = 쉐딩·하이라이트, 항상 check_only
  status: 'not_started' | 'in_progress' | 'check_only' | 'passed' | 'skipped'
  score: number | null            // 0~100, check_only·skipped·not_started는 null
  diagnosis: string               // 한 줄 진단 (채점 엔진이 생성)
  metrics: { ... }                // 겹침률, 이탈(눈 폭 대비 비율), 좌우 차, 톤 차이 등 (화면 5·6에서 쓰던 값 그대로)
  lrIndex: { left: number, right: number } | null   // 좌우 지수 (있는 부위만)
  toneDelta: number | null        // 피부 대비 톤 차이 (쉐딩·하이라이트, 확인만 부위라 점수엔 미사용)
  updatedAt: timestamp
  attempts: number                // 확인받기 횟수
}

SessionSummary {
  total: number | null            // 합산, 측정 부위 0개면 null
  measuredCount: number
  partCount: number               // 룩 부위 수 (기본 5, contour 제외)
  symmetryPenalty: number         // 0 ~ -5
  harmonyPenalty: number          // 0 ~ -5
  weights: { brow:1.0, liner:1.0, shadow:1.0, lip:1.0, cheek:0.7 }   // contour는 합산에 없음
  computedAt: timestamp
}
```

## A-3. 계산 방법

### 합산 (F-10)
```
measured = parts.filter(p => p.status == 'passed' && p.score != null)
if measured.length == 0: total = null, 화면엔 "측정된 부위가 없어요"
base = Σ(weight[p] * score[p]) / Σ(weight[p])      // 측정 부위만
total = clamp(round(base + symmetryPenalty + harmonyPenalty), 0, 100)
```
- `passed`만 넣는다. `check_only`(측정 불가, contour는 항상)와 `skipped`는 제외하고 `measuredCount`에서 뺀다. 화면에는 합산 숫자만(기준·보정 표기 없음).
- 부위를 다시 확인받으면 `PartResult`를 덮어쓰고 합산을 다시 계산한다(멱등).

### 대칭 보정 (0 ~ −5)
- 입력: 눈썹·아이라이너·볼터치의 좌우 차. 형태 부위는 이탈 좌우 차(눈 폭 대비 비율), 강도 부위는 좌우 지수 차.
- 규칙(초안): 부위별 좌우 차를 0~1로 정규화(형태: 눈 폭의 0.11(≈3mm)=1, 지수: 30=1) → 평균 → `−5 × 평균`. 맨얼굴 자연 비대칭은 채점 단계에서 이미 뺀 값을 쓴다.

### 조화 보정 (0 ~ −5)
- 입력: 볼터치와 입술의 색상(Lab a*, b*) 거리, 룩 템플릿에 적힌 허용 범위.
- 규칙(초안): 템플릿 범위 안이면 0, 범위 밖이면 초과량에 비례해 최대 −5. 템플릿에 범위가 없으면 0(적용 안 함). 화면 표시는 없다.

### 쌩얼 vs 내 화장 이미지
- 쌩얼: 촬영 1(정면 눈 뜸) 원본. 이 용도로 세션 끝까지 보관.
- 내 화장: 리뷰 진입 시 품질 게이트 통과한 프레임 1장. 얼굴 랜드마크로 두 이미지를 같은 크롭 박스(눈썹 위 15% ~ 턱 아래 10%)로 잘라 같은 크기로 표시.
- 조명 차이는 보정하지 않는다(그대로 보여주는 게 정직). 다만 이마 밝기 차가 임계 이상이면 "조명이 달라 색은 참고만"을 작은 글자로 표시.

## B-2. 데이터 구조·저장

```
SessionRecord {
  id: uuid
  date: ISO 날짜시간
  lookId: string, lookName: string
  summary: SessionSummary
  parts: PartResult[]              // diagnosisCode 포함 (아래)
```

## B-3. 계산 방법

### 추이 그래프
- x: 회차(날짜), y: 합산. `total == null`인 회차는 점 없이 빈칸.
- 같은 룩끼리만 비교하는 필터(기본 "전체", 룩별 토글).

### 자주 틀리는 부위
```
최근 N회(기본 5) 중 status == 'passed' 또는 'check_only'인 회차만 대상
코드별 count = 그 코드가 등장한 회차 수
표시 = count 내림차순 상위 2개, "부위 · 문장 · N회 중 k회"
같은 count면 최근 등장이 더 최근인 것 우선
```

### 날짜 간 지수 참고 표기
- 회차 상세에서 좌우 지수·톤 차이는 그대로 보이되, `lightingRef.foreheadL` 차이가 기준(예: 8) 이상인 회차 쌍은 "조명 다름" 배지.

# Part C. 두 화면 공통

## C-1. 상태·오류 처리
| 상황 | 처리 |
|---|---|
| 측정 부위 0개 | 합산 null, "측정된 부위가 없어요. 부위를 눌러 다시 확인받을 수 있어요" |
| 내 화장 이미지 없음 (리뷰 진입 시 품질 게이트 실패) | 비교 칸에 "정면을 보면 내 화장 사진을 찍어요" + 재시도 |
| 룩 템플릿에 조화 범위 없음 | 조화 보정 0 (표시 없음) |
| 결과 저장 실패(권한·용량) | 토스트 + 재시도, 세션은 유지 |

## C-2. 접근 규칙
- 진행 칩·막대 탭으로 어느 부위든 이동 가능(F-04). 리뷰에서 돌아가 다시 확인받으면 리뷰로 복귀 시 합산 재계산.
- 리뷰 화면에서 "끝내기"를 누르기 전까지는 세션이 유지된다(앱이 종료돼도 복원). 끝내면 전부 삭제. 기록은 남지 않는다.

## C-3. 1주차에 확인할 것
1. 합산·보정 순수 함수를 먼저 만들고 테스트 8종 통과.
2. `diagnosisCode` 목록을 채점 모듈(C)과 합의(부위 6개 × 코드 3~5개).
3. 비교 이미지 크롭 규칙(눈썹 위 15% ~ 턱 아래 10%)이 4장 촬영 정면 사진과 확인받기 프레임 모두에서 잘리지 않는지 실기기 확인.
4. 세션 임시 저장 구조(웹: IndexedDB/localStorage) v1 고정. 기록 DB는 로드맵(Part B)에서.

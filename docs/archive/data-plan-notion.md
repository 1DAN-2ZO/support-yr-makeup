# 당화응 데이터 계획 — 쉬운 말 판 (2026-09-17, 2판)

📌 우리 앱을 만들려면 어떤 사진과 자료가 필요한지, 왜 필요한지, 어디서 어떻게 구하는지를 처음 보는 사람도 알 수 있게 쓴 문서. 전문 용어와 기능 번호는 뺐다. 자세한 근거와 실측 수치는 저장소 `docs/archive/data-plan-v6.md`, `docs/archive/datasets-ranked-v6.md`에 있다.

> **2판에서 바뀐 것 (2026-09-17 오후 논의)**
> 1. **채점의 정답은 우리가 이미 갖고 있다.** 사용자가 룩을 고르면 우리가 그 사람 맨얼굴에 맞춰 화장 위치를 계산해 그려 준다. 그 그림이 곧 "여기에 이렇게 그려야 한다"는 정답이다. 정답을 남의 사진에서 찾아올 필요가 없다.
> 2. 그래서 **"화장 발린 곳을 오려내는 모델"은 첫 버전에서 뺀다.** 채점은 맨얼굴과 화장 후의 색 차이 + 얼굴 점 468개로 잡은 부위 영역으로 한다. 이 모델을 위해 필요했던 합성 데이터 수천 장과 손 라벨 500장은 "나중에 여유 있으면"으로 내린다.
> 3. 대신 **우리가 직접 가르치는 모델은 얼굴형 판단**으로 정한다. 지금은 자로 재듯 규칙으로 얼굴형을 정하는데, 그걸 사진 5,000장 + 우리 사진 100장으로 배운 모델로 바꾸고, 규칙보다 얼마나 나아지는지 숫자로 보여 준다.
> 4. **화장 얹어보기(생성 AI)** 는 공개 모델을 그대로 쓰되, "얼굴이 그 사람 그대로인가", "룩 색이 제대로 옮겨졌나"를 숫자로 재고, 시간이 되면 우리 룩 10개 전용으로 추가 학습(LoRA)한다. 룩 사진 10장이 그 출발점이라 더 급해졌다.

## 1. 앱이 도는 원리와, 그래서 필요한 데이터

당화응은 이렇게 돈다. **맨얼굴을 찍는다 → 룩을 고른다 → 그 사람 얼굴에 맞춰 "여기에 이렇게 그리세요" 테두리를 그려 준다 → 그리고 나서 확인받기를 누르면 점수를 준다.**

여기서 중요한 사실 하나. **"어디에 그려야 맞는지"는 우리가 계산해서 그려 준 테두리 자체가 정답이다.** 사용자가 그린 것과 우리가 그려 준 것을 비교하면 된다. 그래서 채점의 정답을 만들기 위한 사진은 필요 없다.

컴퓨터가 해야 하는 일은 네 가지고, 각각 데이터가 다르게 필요하다.

| 컴퓨터가 하는 일 | 어떻게 하나 | 우리가 가르치나 | 그래서 필요한 데이터 |
|---|---|---|---|
| 얼굴에 점 468개 찍기 | 구글 공개 모델(MediaPipe) | 아니오 | 없음. 잘 되는지 확인만 |
| 맨얼굴 대비 색이 얼마나 변했나 재기 | 계산식 | 아니오 | **진짜 화장 사진**으로 계산이 맞는지 확인(시험지) |
| 얼굴형 판단해서 쉐딩 위치 정하기 | 지금은 규칙 → **우리가 학습한 모델로 교체** | **예** | 얼굴형이 적힌 사진(공개 5,000장 + 우리 100장) |
| 룩을 내 얼굴에 얹어 보여 주기 | 공개 생성 모델(Stable-Makeup) | 아니오, 나중에 추가 학습 가능 | **룩 사진 10장** + 우리 맨얼굴로 결과 검사 |

그래서 필요한 건 크게 세 가지다.

- **시험지** — 우리가 만든 게 진짜 얼굴에서도 되는지 확인할 사진(검증용). 가장 급함
- **연습 문제** — 얼굴형 모델을 가르칠 사진(학습용). 양이 많지 않음
- **화면에 보여줄 것** — 룩 사진, 문구, 제품 이름(콘텐츠). 룩 사진이 생성 AI의 재료이기도 함

그리고 규칙 하나. **인터넷에 있는 얼굴 사진은 대부분 "연구할 때만 써도 된다"는 조건이 붙어 있다.** 시험지로는 써도 되지만, 컴퓨터를 가르치거나 앱 화면에 띄우면 안 된다. 그래서 학습용과 화면용은 우리가 직접 찍거나, 컴퓨터가 만든 가짜 얼굴을 쓴다.

## 2. 우리가 직접 찍어야 하는 것 (가장 급함)

지금까지 채점은 **컴퓨터가 그린 가짜 화장**으로만 시험을 봤다. 진짜 사람이 진짜로 그린 화장 사진이 없으면 채점이 실제로 맞는지 알 수 없다. 이건 인터넷 어디에도 없어서 우리가 찍어야 한다.

1판과 달라진 점: **사진에 정답을 칠하는 작업(라벨)이 없어졌다.** 분할 모델을 안 가르치니까 픽셀마다 색칠할 필요가 없다. 대신 사진마다 "이 부위는 잘 그렸다 / 조금 벗어났다 / 많이 벗어났다"를 사람이 적는다. 장당 1분이면 되고, 그게 채점기와 사람 판단이 얼마나 일치하는지 재는 정답이 된다.

### 촬영 세션 한 번으로 다 해결한다

| 항목 | 내용 |
|---|---|
| 누가 | 팀원 6명 + 지인 14명 = 20명 |
| 몇 장 | 한 사람당 10장. 1차 200장이면 충분(2차는 필요할 때) |
| 무엇으로 | 폰 앞카메라. 얼굴이 화면 폭의 60% 이상 차게 |
| 어떻게 | 같은 자리에서 **맨얼굴 → 눈썹 → 아이라이너 → 섀도우 → 립 → 볼터치** 순서로 한 단계 그릴 때마다 한 장씩. 일부러 삐뚤게 그린 장도 섞는다(틀린 걸 틀렸다고 하는지 봐야 하니까) |
| 조명 | 창가, 실내등, 어두운 곳 3가지 |
| 각도 | 정면, 좌우로 조금(15°), 좌우로 더(30°) |
| 꼭 | **사진 사용 동의서**에 서명 받기 (발표·학습·앱 화면에 쓴다고 적힌 것) |

이 사진 한 묶음으로 한 번에 얻는 것:

- **채점 시험지**: 진짜 화장 사진 200장에서 채점기 판정과 사람 판정이 몇 %나 같은지. 발표에서 "채점 정확도 N%"로 나가는 숫자
- **얼굴형 답지**: 20명 각각에 "둥근형·계란형·…"을 팀원 2명이 따로 적는다. 두 사람이 얼마나 같이 적었는지도 숫자로 남긴다(사람끼리도 안 맞으면 모델한테 더 바랄 수 없다)
- **조명이 바뀌어도 되는지**: 조명 3가지로 찍었으니까
- **고개를 돌려도 되는지**: 각도 3가지로 찍었으니까
- **얹어보기 검사 재료**: 20명의 맨얼굴에 룩 10개를 얹어 보고 "얼굴이 그 사람인가"를 잰다
- (나중에 분할 모델을 하게 되면) 단계별 전후 사진이 정답 초안이 된다. 그때 가서 칠하면 된다

💡 왜 인터넷 사진으로 안 되나: 같은 사람의 맨얼굴과 "초보자가 실제로 그린" 화장이 짝지어진 공개 사진은 없다. 있는 것도 AI가 입힌 화장이거나 연구용이다.

## 3. 얼굴형 모델을 가르칠 사진 (우리가 학습하는 유일한 모델)

### 3-1. 이게 왜 모델이 필요한가

얼굴형에 따라 쉐딩·하이라이트 위치가 다르다. 지금은 얼굴 폭·턱 폭·얼굴 길이 비율로 규칙에 따라 5가지(계란·둥근·각진·긴·하트)를 정하는데, 논문에 따르면 이런 규칙 방식은 사람 판단과 36~65%밖에 안 맞는다. 사진에서 직접 배운 모델로 바꾸면 그보다 나아지는지 보는 게 목표다. **쉐딩을 어디에 그리느냐는 그대로 규칙**이고, 모델은 "이 얼굴이 어느 형인가"만 맡는다.

### 3-2. 얼굴형이 적힌 공개 사진 (Kaggle Face Shape) — 1차 학습용

- **이게 뭔데**: 서양 여성 연예인 사진 5,000장에 "하트형·긴형·계란형·둥근형·각진형"이 1,000장씩 적힌 것.
- **왜 필요한데**: 모델이 "얼굴형이란 이런 것"을 처음 배우는 교재. 양이 있어서 출발점으로 좋다.
- **조심할 것**: 누가 어떻게 적었는지 근거가 없고, 인터넷에서 긁어모은 연예인 사진이라 **라이선스가 불명확**하다. 그래서 **첫 학습에만 쓰고, 최종 모델은 우리 사진과 정부 데이터로 다시 다듬는다**(아래 3-3, 3-4). 발표에서 이 한계를 그대로 말한다.
- **어떻게 받나**: Kaggle 계정 만들고 → 설정에서 API 토큰 받아 `kaggle.json`을 내 컴퓨터 `.kaggle` 폴더에 두고 → 아래 한 줄.
  ```
  pip install kaggle
  kaggle datasets download -d niten19/face-shape-dataset -p C:\data\danghwaeung\faceshape --unzip
  ```
  링크: https://www.kaggle.com/datasets/niten19/face-shape-dataset
- **안 되면**: 전처리본 https://www.kaggle.com/datasets/zeyadkhalid/faceshape-processed · 3분류만 있는 https://www.kaggle.com/datasets/attanmhd/face-shape-oval-round-square/data

### 3-3. 우리가 적는 한국인 얼굴형 답지 (2번 촬영 사진 재사용)

- 2번 촬영 20명 + 지인 셀피를 더해 **50~100명**. 각 사람에 얼굴형을 **팀원 2명이 따로** 적고, 두 사람이 다르게 적은 건 셋째가 정한다.
- 이게 **한국인 얼굴에 맞추는 다듬기 교재이자 최종 시험지**다. 서양 연예인 사진으로만 배운 모델이 한국인 얼굴에서 얼마나 틀리는지, 우리 사진으로 다듬으면 얼마나 좋아지는지를 이걸로 잰다.
- 발표에 나갈 숫자: **규칙 정확도 vs 모델 정확도**, 그리고 **사람 둘이 서로 일치한 비율**(모델의 상한선).

### 3-4. 한국인 얼굴 많이 (AI Hub 한국인 안면 이미지) — 신청해 두고 기다림

- 정부가 스튜디오에서 한국인 1,000명을 찍은 사진. 얼굴형 라벨은 없지만, 우리가 100명만 적어도 한국인 얼굴 1,000명 분포를 볼 수 있고, 조명·각도 시험(4번)과 겸한다.
- 신청·승인 절차는 4번에.

## 4. 인터넷에서 받아오거나 신청하는 것 (시험지·기준선용)

### 4-1. 얼굴 부위가 색칠된 셀피 (EasyPortrait) — 부위 영역이 맞는지 시험

- **이게 뭔데**: 폰으로 찍은 셀피 2만 장에 "여기는 왼쪽 눈썹, 여기는 입술" 하고 픽셀마다 색칠해 둔 정답 사진. 상업 사용 가능 계열.
- **왜 필요한데**: 우리는 얼굴 점 468개로 눈썹·눈·입술 영역을 잡아서 그 안의 색 변화를 잰다. **그 영역이 실제 부위와 얼마나 겹치는지** 이 정답지로 확인한다. 1판에서는 "분할 모델 가르치는 교재"였는데 이제는 **시험지로만** 쓴다.
- **믿을 만한가**: jeakeun이 200장을 우리 파이프라인에 돌려 봤다. 얼굴 검출 100%, 우리 앱이 요구하는 해상도를 93%가 만족했다.
- **어떻게 받나**:
  ```
  pip install -U huggingface_hub
  hf auth login
  hf download gofixyourself/EasyPortrait --repo-type dataset --local-dir C:\data\danghwaeung\easyportrait
  ```
  링크: https://huggingface.co/datasets/gofixyourself/EasyPortrait
- **안 되면**: LaPa(2.2만 장) → CelebAMask-HQ(3만 장, Kaggle 미러 https://www.kaggle.com/datasets/ipythonx/celebamaskhq). 둘 다 "연구용만"이라 시험지로만.

### 4-2. 눈 부위가 색칠된 사진 (Periorbital) — 눈썹·눈꺼풀 영역 시험

- **이게 뭔데**: 눈 주변만 잘라낸 사진 2,842장에 홍채·흰자·눈꺼풀·눈썹을 사람이 손으로 색칠한 것. 상업 사용 가능(CC BY 4.0).
- **왜 필요한데**: 아이라이너·섀도우 영역이 실제 눈꺼풀·눈썹과 맞는지 시험. 이걸로 "MediaPipe가 잡는 홍채가 실제보다 12% 작다"는 걸 확인했고, 그래서 홍채 크기로 mm를 재는 방식을 버렸다.
- **어떻게 받나**: Zenodo·GitHub `periorbital-dataset` 검색. 눈만 있어서 얼굴 검출은 안 된다.

### 4-3. 화장 전·후 사진 쌍 (FFHQ-Makeup) — 참고만

- **이게 뭔데**: 같은 얼굴의 맨얼굴 1장 + 화장 5가지 = 10만 장. 사진이 정확히 겹쳐져 있다.
- **왜 필요한데**: "화장하면 색이 보통 얼마나 변하나"를 통계로 내서 우리 기준값의 출발점으로 삼는다. 얹어보기 모델 비교 발표에도 쓴다. 화장은 AI가 입힌 것이고 "연구용만"이라 학습·화면에는 못 쓴다.
- **어떻게 받나**: `hf download cyberagent/FFHQ-Makeup --repo-type dataset`
- 비슷한 것(MT, BeautyFace, Makeup-Wild)도 전부 연구용. CPM은 링크가 죽었다.

### 4-4. 정부 데이터 3종 (AI Hub) — 신청해 두고 기다림

AI Hub는 정부가 공개하는 한국인 데이터 사이트다. **회원가입(한국인 휴대폰 인증) → 데이터 페이지에서 "다운로드" → 신청서 제출 → 승인 → 다운로드.** 승인에 시간이 걸리니 **이번 주에 세 개를 한꺼번에 신청**해 둔다. 조건: 학습에는 써도 되지만 **앱 화면에 띄우거나 남에게 넘기면 안 된다.**

| 데이터 | 이게 뭔데 | 왜 필요한데 |
|---|---|---|
| **한국인 안면 이미지** | 한국인 1,000명을 스튜디오에서 조명 30가지 × 고개 각도 20가지로 찍은 사진 | ① 조명이 바뀌어도 채점이 흔들리지 않는지 넓게 시험 ② 고개를 돌려도 추적이 되는지 ③ 얼굴형 모델의 한국인 다듬기(3-4) |
| **글로벌 다인종 피부색** | 2,525명의 이마·볼·목 피부색을 **기계로 정확히 잰 값** + 조명 4가지 | 우리가 사진에서 계산한 "색 차이"가 진짜 측정값과 맞는지 대조하는 저울 |

## 7. 나중에 여유 있으면 (첫 버전에서 뺀 것)

- **화장 발린 곳 오려내는 모델(분할 모델)**. 색 차이 방식이 실제 사진에서 잘 안 되면 그때 꺼낸다. 재료는 이미 있다: 컴퓨터가 맨얼굴에 화장을 그리면서 정답도 같이 만드는 생성기(jeakeun `poc/synth`), 그 생성기에 넣을 가짜 맨얼굴 42만 장(SFHQ, https://www.kaggle.com/datasets/selfishgene/synthetic-faces-high-quality-sfhq-part-1), 그리고 2번 촬영의 단계별 사진(정답 초안). 실제로 하게 되면 2번 사진 200장에 손 라벨(장당 5분)이 추가된다.
- 채점 기준값("꼬리가 이만큼 벗어나면 틀림") — 실험으로 재지 않고 우리가 정한다. 2번 사진에서 사람 판정과 맞춰 보며 조정.
- 전문가 평가(화장 전문가가 사진 30~50장에 점수) — 하면 좋지만 필수는 아님.
- 설문 100명, 사용자 실험 10명 — 일정표대로 1주차·4주차.

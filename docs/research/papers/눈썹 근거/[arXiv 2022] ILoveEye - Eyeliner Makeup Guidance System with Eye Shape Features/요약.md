# ILoveEye — 눈 모양 특징을 쓰는 아이라이너 화장 가이드 시스템

**원제** ILoveEye: Eyeliner Makeup Guidance System with Eye Shape Features
**저자** Hange Wang, Haoran Xie, Kazunori Miyata — 일본 북륙첨단과학기술대학원대학(JAIST)
**발표** arXiv:2203.13592 (2022-03) · 최종본은 HCII 2022(인간–컴퓨터 상호작용 국제학회) 논문집 · [arXiv](https://arxiv.org/abs/2203.13592)
**라이선스** arXiv 게재본이 CC BY 4.0 (그래서 전문번역이 있습니다). 학회 최종본은 출판사 저작권

> **한 줄**: 웹캠으로 **MediaPipe 눈 윤곽 16점**을 잡고, **규칙으로 눈 모양을 판정**한 뒤, 그 눈에 맞는 **라이너 모양을 실시간으로 겹쳐** 보여 준다. 화장 초보 8명이 써 보니 라이너를 **더 두껍고 선명하게** 그렸다. **우리 화면 4와 거의 같은 구조의 선행 연구**다.

---

## 무엇을 풀려 했나

아이라인은 초보자에게 어렵다. 사람마다 눈이 달라서 **자기 눈에 맞는 스타일**로 그려야 하는데, 유튜브·틱톡 튜토리얼은 **개인의 얼굴 특징과 맞지 않는다.**

## 어떻게

**1. 눈 잡기** — MediaPipe 얼굴 메시에서 **눈 윤곽 16점**을 고름. 웹캠 60fps. 사용자가 정면을 보고 "저장"하면 그 프레임의 점으로 판정

**2. 눈 모양 판정 — 규칙 기반, 특징 세 개**

| 특징 | 재는 법 | 기준 |
|---|---|---|
| **가로세로 비** a | 눈 폭(양 끝점 거리) ÷ 눈 높이(위·아래 윤곽에서 양 끝 선까지 가장 먼 수직 거리의 합) | **2.75~3.00 보통** / 3.00 초과 = 작고 긴 눈 / 2.75 미만 = 크고 둥근 눈 |
| **바깥 눈꼬리 방향** | 눈꼬리에서 양 끝 선과, 윗눈꺼풀 최고점·아랫눈꺼풀 최저점 각각이 이루는 각 α(위)·β(아래) | **α > β면 처진 눈**, 아니면 올라간 눈 |
| **두 눈 사이 거리** | 두 눈 사이 거리 De vs 두 눈 폭의 평균 | 1.05배 초과 = 먼 눈 / 0.95배 미만 = 가까운 눈 |

**3. 라이너 스타일** — 다섯 가지를 정의하고 조합

| 스타일 | 모양 | 치수 |
|---|---|---|
| **Basic** | 윗눈꺼풀을 따라 굵은 선. 각 구간의 **수직 방향**으로 두께 h만큼 | h |
| **Winged** (올린 날개) | 눈꼬리에서 위로 뻗은 날개 | **눈 축에서 15°** (자연스러운 날개 라이너 표본을 잼), **길이 = 눈 폭의 12%** |
| **Drop** (처진 날개) | 윗눈꺼풀 최고점 → 눈꼬리 선을 **그대로 연장** | 길이 12% |
| **Extend** (수평) | 눈꼬리에서 **수평**으로 연장 | 길이 12% |
| **Inner / Outer** (아래) | 아랫눈꺼풀 안쪽 / 바깥쪽에 얇게 | 윗선 두께의 1/3까지 점점 가늘게 |

**4. 추천 규칙**
- 눈 크기가 작거나 보통 → Basic / 크면 → Basic을 **더 얇게**
- 바깥 눈꼬리 방향 → Winged · Drop · Extend 중 하나
- 두 눈 사이 거리 → 아래 라이너 Inner · Outer
- 고른 스타일을 합쳐 **다각형 마스크**를 만들고 **주황색**으로 겹쳐 표시

**5. 구현** — Python, OpenCV 4.5.2, MediaPipe 0.8.6 / Windows 10, i7-9700, RTX 2060 SUPER / 로지텍 C920 웹캠. 왼눈·오른눈을 따로 확대한 창에 가이드를 보여 줌

## 결과

**평가**: 화장 경험이 적은 **여성 대학원생 8명**(약 25세, 중국·일본인). 시스템 없이 한 번, 지운 뒤 시스템으로 한 번 그림. 5점 척도 설문

| 질문 | 평균 |
|---|---|
| 평소 화장을 하나 | 2.63 |
| 눈 화장 실력 자기 평가 | 2.25 |
| 시스템이 내 눈 모양을 맞게 설명했나 | **3.88** |
| 시스템이 라이너 그리기를 도왔나 | **3.88** |
| 혼자보다 더 잘 그렸나 | 3.63 |
| 라이너 실력이 늘었다고 느끼나 | **4.13** |

- 시스템을 쓰면 라이너가 **더 두껍고 선명**해졌다. 저자들은 그래서 눈이 더 커 보인다고 해석
- **모든 사람의 완성 시간이 늘었다.** 가이드 위치를 찾고 따라 그리는 데 시간이 들었다
- **평소 화장을 자주 하는 사람일수록 실력이 늘었다고 느꼈다**(상관 0.71). 원래 화장을 안 하는 사람보다, 경험이 있는 사람이 자기 눈의 정확한 윤곽을 알면 더 도움이 된다는 해석
- 이미 자기 방식이 굳은 숙련자에게는 만족도가 낮았다(1명)

## 한계 (저자 명시 + 읽으며 본 것)

- **8명**뿐이고, 중국·일본인이다. 추천된 스타일도 거의 Winged·Extend·Outer로 몰렸다(눈 모양이 비슷해서)
- **쌍꺼풀(눈꺼풀 주름)을 잡지 못한다.** MediaPipe가 눈꺼풀 주름을 주지 않아서, 눈꺼풀이 크게 영향을 주는 사람은 판정이 틀릴 수 있다
- 카메라 각도를 손으로 맞춰야 했다
- **"얼마나 잘 그렸나"를 채점하지 않았다.** 결과 사진을 눈으로 비교했을 뿐이다
- 판정 기준값(2.75, 3.00, 5%)과 15°·12%의 근거가 "표본을 재 봤다" 수준이다

## 우리 프로젝트에 주는 것

**1. 우리 구조가 학계에서 이미 쓰인 방식이라는 근거다.** MediaPipe 점 → 규칙 → 실시간 가이드 오버레이. 화면 4가 하는 일과 같다. 발표에서 "선행 연구 ILoveEye(HCII 2022)와 같은 구조에, 우리는 **채점**과 **부위 순서 교육**을 더했다"고 차별점을 말할 수 있다. 이 논문은 채점이 없다.

**2. 라이너 꼬리 15° · 길이 12%의 출처가 된다.** 지금 `guides.ts`의 `GUIDE_PARAMS.liner`는 **꼬리 30°, 길이 15%**이고 출처가 없다(② B1). 이 논문은 **같은 기준(눈 축에서 잰 각도)**으로 15°·12%를 썼다. ②에게 넘길 가장 구체적인 근거다. 다만 "표본을 재 봤다"는 수준이라, 논문을 인용하되 **사용자 실험으로 확인**하는 게 맞다.

**3. "따라감 / 보정"이 이미 스타일로 정의돼 있다.**
- **Drop** = 눈의 처진 선을 그대로 연장 → 우리의 **"따라감"**(지금 코드의 동작과 같은 방향)
- **Winged / Extend** = 위로 또는 수평으로 → 우리의 **"보정"**
- 우리가 `looks.json`에 넣으려던 "따라감 / 보정" 항목을 **이 세 스타일 이름으로** 두면 근거가 붙는다

**4. 눈 모양 특징 세 개가 MediaPipe 점으로 바로 계산된다.** 가로세로 비, 바깥 눈꼬리 방향(α·β), 두 눈 사이 거리. 기준값까지 있다. 다만 우리는 **분류하지 말고 연속값으로** 쓰기로 했으니(Alashkar 2017의 61% 문제), **기준값은 "어디서 스타일이 바뀌나"의 경계로만** 참고한다.

**5. 두께도 눈 크기에 따라 바꾼다.** 큰 눈은 라이너를 **더 얇게**. Jung(2020)의 "외꺼풀은 눈 높이가 작다"와 합치면, **두께를 눈 높이에 맞춰 조절**하는 근거가 두 개가 된다.

**6. 우리도 같은 한계가 있다.** MediaPipe는 **쌍꺼풀 주름을 주지 않는다.** 이 논문도 여기서 막혔다. 우리 두께 개인화는 눈 높이(윗·아래 눈꺼풀 점 사이)로 **간접 추정**할 수밖에 없다.

**7. 가이드를 쓰면 시간이 늘어난다.** 모든 사용자의 완성 시간이 늘었다. 우리 화면 4도 사용자가 가이드를 찾는 시간을 고려해야 한다. **양쪽 눈을 확대한 창**을 따로 둔 설계는 우리 가로 모드(눈 단계)와 같다.

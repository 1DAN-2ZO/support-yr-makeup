# 머리카락 가림 · 피부 보정 — 논문 조사와 적용할 곳

2026-09-29 · ⑥ · 조사만 (코드 변경 없음)

## 왜 조사했나

2-b AR 과 화면 3 완성본은 얼굴 그물(MediaPipe 478점) **안 전체**에 피부 보정(7×7 bilateral, 0.3)과 화장을 입힌다(`client/src/screens/makeup-gl.ts`). 앞머리·옆머리가 그물 안에 들어오면:

- 머리카락도 흐려진다 — 가닥끼리 색이 비슷해 bilateral 이 오히려 잘 뭉갠다 → 결이 사라져 플라스틱처럼 보인다
- 머리카락이 그물 경계를 지나면 안쪽만 흐려져 **경계선**이 보인다
- 블러셔·섀도 같은 화장 층이 **머리카락 위에 칠해진다**

### 피부 보정 · 피부색

| 이름 | 핵심 | 우리에게 |
|---|---|---|
| **Guided Image Filtering** — He · Sun · Tang, ECCV 2010 / TPAMI 2013 (`2013-he-guided-image-filtering.pdf`) | 창마다 q = a·I + b 선형식. ε 가 bilateral 의 색 분산 역할. bilateral 과 달리 **경계에서 경사 반전 인공물 없음**, 박스 평균만이라 반경과 무관 O(N) | 지금 bilateral 을 바꿀 후보. WebGL 여러 패스로 옮기기 쉬움 |
| Fast Guided Filter — He · Sun, arXiv 1505.00996 (`2015-he-fast-guided-filter.pdf`) | 1/s 로 줄여 계산 → 10배 넘게 빠르고 열화 거의 없음. 폰 사진 앱에 쓰였다고 적힘 | 폰 실시간용 |
| **FabSoften** — Velusamy 외 (Samsung), CVPRW 2020 (`2020-velusamy-fabsoften.pdf`) | 랜드마크 윤곽 + 피부 확률 마스크 → 마스크를 원본 안내 guided filter 로 다듬어 **눈썹·수염 같은 털을 살림**("Guided Feathering"). 피부 확률만큼 반경을 바꾸는 guided filter 로 보정, 눈·입 안쪽은 랜드마크로 0 | **우리 문제와 가장 가까운 설계.** 반경을 키우면 털이 흐려진다는 경고 |
| 피부색 검출 서베이 — Kakumanu 외, Pattern Recognition 2007 (`2007-kakumanu-skin-color-survey.pdf`) | Jones & Rehg 요약 포함. 적응형 방법은 가림이 생기면 비피부로 끌려갈 위험 | 참고 |
| Jones & Rehg, IJCV 2002 (유료, 링크만: https://experts.illinois.edu/en/publications/statistical-color-models-with-application-to-skin-detection) | 웹 이미지 약 10억 픽셀로 피부/비피부 RGB 히스토그램, 확률 비율 판정. 탐지 80% 에서 오검출 8.5% | 모두에게 공통인 모델이라 거침. FabSoften 은 이 방식이 머리카락 분리에 자주 실패한다고 지적 |
| Bianco 외, IEEE TIP 2015 (유료, 링크만: https://ieeexplore.ieee.org/document/7185418/) | 검출한 얼굴에서 사람마다 피부 분류기를 초기화 | 초록만 확인 |

## 적용할 곳

### 1. AR 피부 보정 · 화장 — `client/src/screens/makeup-gl.ts` (⑥)

2-b AR(`fullrender.ts`)과 화면 3 완성본(`completed.ts`, #195)이 **같은 코드**라 한 곳을 고치면 둘 다 좋아진다.

- 머리카락 마스크 → `(1 − 머리카락)` 을 보정 강도(`uBeauty`)와 화장 층 알파에 곱한다
- 그물 가장자리에서 보정이 부드럽게 0 으로 → 경계선 없앰
- 화면 3(사진 한 장)은 한 번만 돌리면 됨. AR 영상은 **3~5 프레임에 한 번** + 이전 마스크와 섞기(`mix(prev, new, 0.3~0.5)`) + smoothstep 가장자리
- 마스크 넘기기: `ImageSegmenter` 생성 옵션 `canvas` 에 **우리 WebGL2 캔버스를 넘겨 컨텍스트를 같이 써야** `MPMask.getAsWebGLTexture()` 를 셰이더에서 바로 쓸 수 있다. 번거로우면 256² 를 `getAsUint8Array` 로 받아 `texSubImage2D`
- 다음 단계: bilateral → guided filter (FabSoften 식, 반경은 작게)

### 2. 이마 참조 — `client/src/core/color.ts FOREHEAD_POLY` (코드를 읽다 찾음, 영향이 가장 클 수 있음)

`FOREHEAD_POLY = [10, 338, 297, 332, 284, 251, 21, 54, 103, 67, 109]` 은 **머리선 바로 아래 이마 윗 테두리**다. 앞머리가 있으면 거의 머리카락 색을 잰다. 이 값을 쓰는 곳:

| 쓰는 곳 | 모듈 | 앞머리가 있으면 |
|---|---|---|
| 촬영 밝기 판정 (`flow.ts`, `brightMin 40`) | ① | 검은 앞머리면 L* 가 40 아래 → **"더 밝은 곳으로" 만 뜨고 촬영이 안 될 수 있음** |
| #175 어두울 때 가림 임계 (이마 L* 중앙값 50 미만) | ① | 앞머리만으로 "어두운 환경" 으로 켜질 수 있음 |
| 가림 판정 #144 (`occlusion.ts`) | ① | 앞머리가 흔들리면 가림으로 잡힐 수 있음 |
| 화면 4 밝기 판정 (`gate.ts`) | ② | 촬영과 같은 문제 |
| 흰자 기준 `scleraLab` (피부와 비슷한 픽셀 거르기) | ① | 기준 피부색이 틀림 |
| 채점 조명 보정 `lightShift` | ③ | 머리가 움직이면 조명이 바뀐 걸로 → 확인만(lighting) |
| 리뷰 조명 비교 (`review.ts lightingDiffers`) | ⑥ | 같은 문제 |

- 당장: 평균 대신 **중앙값** (FabSoften 조사 쪽 권고와 같음)
- 사진(촬영·채점·리뷰): **머리카락 마스크로 그 픽셀을 빼고** 잰다
- **코드로 추론한 것** — 앞머리 있는 사람으로 폰에서 실제로 막히는지 먼저 확인

### 3. 채점 — `client/src/core/sampling.ts` · `score-part.ts` (③)

- 눈썹(앞머리가 덮음) · 쉐딩(관자놀이·얼굴 옆) · 볼터치 표본 영역에 머리카락 픽셀이 섞이면 ΔE 가 틀어진다
- 맨얼굴과 화장 사진 사이에 머리가 움직이면 "화장이 바뀐 것" 으로 잡힌다
- 두 사진에 마스크를 돌려 머리카락 픽셀을 빼고, 너무 많이 가렸으면 확인만(가림)

## 추천 순서

1. **폰 확인** — 앞머리 있는 얼굴로 촬영·AR. 2번(촬영 막힘)이 실제로 일어나는지
2. **사진 쪽에 머리카락 마스크** — 촬영 · 채점 · 화면 3 (사진당 한 번이라 부담 적음)
3. **AR 영상** — 폰에서 fps 를 재 보고. iOS 는 실기기 필수

## 주의

- 속도는 모두 **Pixel 6 공식 수치** — 우리 폰에서 다시 잰다
- 2번은 ①·②·③·⑥ 이 걸친 공통 문제라 고치려면 합의가 필요하다
- CelebAMask-HQ 와 그 파생 가중치는 상업 서비스라 쓰지 않는다

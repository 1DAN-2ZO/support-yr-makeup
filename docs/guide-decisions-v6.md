# ② 가이드·실시간 — 기술 결정 목록

모듈 ②(가이드 테두리 + 실시간 게이트)가 **구현 전에 정해야 하는 기술 선택**을 한곳에 모은다.
이슈(`[guide]` #21~#31)는 *할 일* 목록이고, 이 문서는 *정할 것* 목록이다. 둘은 다르다 —
이슈 하나가 여러 결정을 품기도 하고(#22 = E1·E2), 결정 하나가 여러 이슈에 걸리기도 한다(D1 = #27·A1).

**왜 따로 두나**: 결정이 대화에만 남으면 "지금 어디까지 했지"를 매번 다시 찾게 된다. 실제로 그랬다.

기호: `[x]` 정해짐 · `[ ]` 미정 · `◐` 일부만 정해짐 · `⛔` 남의 답을 기다리는 중

## A. 기반

- [x] **A1 랜드마크 엔진·얼굴 후처리** → **MediaPipe Face Landmarker 478점, `numFaces: 1`, delegate GPU→CPU, 변환행렬 켬, 블렌드셰이프 켬(V3)**
  네 조합(V0~V3)을 25초씩 5회 실측. 비용 폭이 0.95ms(7%)로 측정 잡음 이하라 **정확도만으로 결정**했다.
  pitch 근사 오차 p95 6.45°가 게이트 폭 ±6°의 절반이라 행렬은 켠다. 웃음(무표정 0.000 / 웃을 때 0.754)은
  EAR·MAR 로 못 만들어 블렌드셰이프를 켠다.
  근거: `poc/screen4/README.md` A1 · PR #125 · PR #140
  되돌리기: 폰에서 V0~V3 재측정해 비용이 크면 **블렌드셰이프 → 행렬** 순으로 끈다

- [x] **A2 좌표계·단위** → **프레임 px, 저장하지 않고 그때그때 계산**
  계약 `types.ts` 는 `GuideSet` 을 "기준(쌩얼) 좌표계"로 적었지만, ③ 이 실제로 쓰는 것은
  `GuideSource: (partId, f: SampleFrame) => PartGeometry` 다. 맨얼굴·화장 사진에 각각 부르므로
  **저장된 좌표가 아니라 넘긴 랜드마크로 그 자리에서 만든다.** 길이는 전부 비율(눈 폭·입술 폭·얼굴 폭),
  `unitScale` 은 ①의 `baseline.ts` 것을 쓴다. `CaptureBundle.pts` 단위는 **px**.
  근거: #21 코멘트

- [x] **A3 프레임 루프** → **rVFC + 단조 증가 타임스탬프 + 손·게이트 주기 확대. Worker 는 미룸**
  rAF 는 주사율(60Hz)에 묶여 카메라(30fps)보다 자주 깨어나 **중복 프레임 57%**. rVFC 는 0.
  손 5~10프레임마다(19.1→2~4ms), 게이트 주기 확대(3.5→1.2ms). S23 기준 49.9 → 약 31ms.
  Worker 는 위 넷으로 예산에 들어오고 "30fps 유지" 기준 자체가 미검증이라 미룬다 —
  대신 **추론 호출을 함수 하나로 분리**해 나중에 그것만 옮기게 한다.
  근거: `poc/screen4/README.md` A3 · PR #140

## B. 테두리 모양

- [ ] **B1 부위별 테두리 기하** ⛔ **③ 대기**
  치수의 출처가 문제다. 라이너 두께 `0.045` 는 원래 `guides.js` 의 `thickMm: 1.2`(우리가 그릴 선 굵기)였고,
  `6410a39`(mm→비율)에서 `guides.js`·`score.js` 가 **동시에** 받았다. 즉 **채점이 우리 선 굵기를 되돌려 잰다.**
  게다가 `looks.json` 의 룩 10개가 두께를 0.030~0.052 로 다 다르게 갖는데 채점은 0.045 고정,
  허용 범위(0.023~0.060)가 룩 전체를 삼켜 **룩 선택이 라이너 채점에 영향이 없다.**
  기다리는 답: `guide.liner.thick` 을 룩에서 읽을지 (#44 코멘트)
  참고: 같은 치수 사본이 네 곳 — `poc/full/lib/guides.js` · `score.ts PARAMS` · `eval/score/guide-poc.mjs` · `tests/helpers/synth-face.ts`

- [ ] **B2 얼굴형 → 쉐딩·하이라이트 규칙**
  `screen3-rules.js` 의 `CONTOUR_RULES` 5종이 출발점. 문서는 "교재 3곳 + 전문가"로 정하라고 적혀 있다.

- [ ] **B3 매 프레임 새로 만들기 vs 한 번 만들고 옮기기**

## D. 게이트 — 언제 "찍어도 좋다"고 할까

- [ ] **D1 조건 목록** ◐ **웃음은 넣기로 정해짐**
  `poc/full/lib/gate.js` 의 6조건(`frontal·visible·hand·sharp·bright·stable`)이 출발점.
  표정 게이트에 **웃음을 포함**한다(⑥ 과 합의, PR #125). ③의 #43(표정 차 → `check_only`)이 `deferred` 라
  사후 탐지 경로가 안 만들어질 수 있어 사전 차단이 안전하다. **나머지 조건은 미정.**

- [ ] **D2 조건별 판정 방법**
  A1 이 절반을 정했다 — 자세는 행렬 분해, 눈 감음은 EAR, 웃음은 블렌드셰이프.
  **표정 값을 통로 하나로 받아** 게이트가 출처를 모르게 한다 → 웃음을 빼면 설정만 바꿔 V1 으로 내려간다.

- [ ] **D3 가림 판정** ⛔ **손 검출로는 부족하다**
  수용 기준은 "가림 상태에서 채점 0건"인데 손 검출은 손만 잡는다. 브러시·앞머리·안경은 못 잡고,
  화장 중에는 손이 늘 얼굴 근처라 오탐도 난다. MediaPipe `visibility` 는 **항상 0**이라 못 쓴다.
  대안 4개(추가 비용 0): 검출 실패 · 기하 이상 · 참조 영역 오염 · ΔE 가 마스크 경계를 넘음.

- [ ] **D4 임계 기준**
  `GATE_LIMITS`(yaw 15·pitch 10·dYaw 8·dPitch 6·sharpMin 30·brightTol 12·stable 5)가 출발점이지만
  `tech-review-full-flow-v6.md` §12 가 **"가정값 — 전부 미검증"**으로 분류한 값들이다.

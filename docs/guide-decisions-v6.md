## ② 가 ③ 에게 주는 것 (PR #139 로 확정)

B·F 를 짜기 전에 보는 계약. 좌표는 **받은 프레임의 px**, 맨얼굴·화장 프레임에서 각각 불린다.

```ts
guide("liner",   f) → { liner: { wing: {R,L}, thick: <두께, 눈 폭 비율> } }
guide("lip",     f) → { lip: { offset: <오프셋, 입술 폭 비율> } }
guide("shadow"|"cheek", f) → { regions: {R, L} }
guide("contour", f) → { contour: { shading: Pt[][], highlight: Pt[][] } }
```

**2026-09-22 — 치수의 주인이 ② 로 옮겨졌다.** 원래 채점이 `PARAMS.guide`(라이너 두께 0.045 등)를 자기 상수로
갖고 있어서, 룩 10개 두께(0.030~0.052)가 허용 범위(0.023~0.060)에 통째로 들어가 **룩 선택이 채점에 영향이 없었다**
(#44). ③ 이 `PARAMS.guide` 를 삭제하고 ② 가 그린 값을 그대로 받도록 바꿨다.

- **치수를 안 주면 던진다.** 기본값으로 조용히 채점하지 않는다
- 쉐딩은 **좌우 구분 없이 밴드 배열 그대로** 넘긴다. 좌우 분류(무게중심 x)와 가운데 밴드(콧대·이마 위·턱 끝) 제외는 **채점이 한다**
- `highlight` 가 빈 배열이면 하이라이트 비교만 건너뛴다. 쉐딩 밴드가 없으면 던진다
- 명세는 `client/src/core/guide-poc.ts` (PR #139 이후 판. 화면 5 와 평가 CLI 가 같은 파일을 쓴다 — 전에는 `eval/score/guide-poc.mjs`). `guides.ts`·`contour.ts` 가 올라가면 그 파일을 지운다

  **주의 — 내가 정한 숫자가 곧 채점 기준이 된다.** `wingDev` 는 내 선에 수직인 오프셋이라, 내 선이 0점이다.
  미용적으로 틀린 값을 넣으면 앱이 사용자에게 자신 있게 "틀렸다"고 말한다. 그런데 ③ 에 대응물이 없어
  **아무도 교차검증하지 않는다.** 최종 값은 #78(룩 확정)·#121(값 측정)에서 온다 — 그때까지는 POC 값을 쓰되
  출처를 `looks.json` 하나로 모아 둔다.

  `looks.json` 에 없는 값(꼬리 각 30°, 섀도우 0.55, 볼 0.11×0.07 −25°)은 대응물이 아예 없다. `doll` 룩에만

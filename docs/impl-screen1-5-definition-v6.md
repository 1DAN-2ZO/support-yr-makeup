# 화면 1~5 — 기능 구현 요소 정의 (v6, 1단계: 정의만)

> 2026-09-15 · 1단계(요소·데이터·상태) 정의. 구현 방법·검증은 2단계 문서에서. 화면별 확정 사항은 `service-definition-v6.md` 부록이 기준이며, 아래 본문과 다르면 부록을 따른다.

> **v6 반영 사항 (사용자 확정)**
> - 화면 3은 **부위 완성본**(전체 완성 예상 렌더링을 이 부위로 줌한 정지 이미지) + 근거 + 필요한 제품 + "그리러 가기". 화면 4가 **실시간 테두리**(아래 3-1의 요소 3-3~3-9). 화면 5의 "다시 확인받기"는 화면 4로, 진행 칩은 화면 3으로.
> - 화면 5·5-b 결과는 **점수 + 가이드 테두리 겹침 + 한 줄 평만** 표시. 아래 5-1의 지표 4줄·좌우 차 숫자, 5b-3·5b-5의 좌우 지수·톤 차이 숫자는 **화면에 표시하지 않고** 내부 계산·진단 코드 생성에만 쓴다.
> - 화면 5-b(쉐딩·하이라이트 결과) 목업 브리프는 `screen-image-brief-v6.md`에 있다. 쉐딩·하이라이트는 항상 "확인만", 섀도우·볼터치는 점수.
> - 서버 처리 동의를 거부하면 이용 불가. 폰 전용 모드 없음. 서버로는 정면·좌·우 3장 전송.
> - **POC 검증 (2026-09-16, `poc/look-tryon/`)**: 서버 화장 전이 모델 = Stable-Makeup(SD1.5+ControlNet, Apache-2.0), fp16·DDIM 10 step 설정으로 RTX 3060에서 추론 3.15초·VRAM 5.3GB — "왕복 목표 3초" 달성 확인(`poc/look-tryon/server-bench/README.md`). 화면 2 `LookLayer`는 당초 구상한 468점 UV 메시 텍스처 굽기 대신, **부위별 랜드마크 폴리곤을 가운데점 팬 삼각분할한 3점 아핀 워핑**(정식 삼각형 메시보다 가벼운 절충안)으로 실시간 재투영하는 방식이 동작함을 확인 — 2-1·2-2 갱신.
> 모든 좌표는 랜드마크 기준(화면 방향 무관). 사진은 서버 처리 후 즉시 삭제. 채점은 "확인받기" 버튼을 눌렀을 때만.

```
Session {
  id: uuid
  startedAt: timestamp
  baseline: Baseline                 // 화면 1에서 생성
  bareFacePhoto: uri                 // 촬영 1 정면 눈 뜸. 화면 6 비교용, 세션 끝 삭제
  faceShape: FaceShapeResult         // 쉐딩·하이라이트 가이드에만 사용
  serverAssets: ServerAssets         // 법선 맵·부위 마스크·룩 레이어 (동의 필수)

  parts: PartResult[]                // 화면 5·5-b에서 갱신 (화면 6 문서와 같은 구조)
```

## 1-2. 촬영 조건 (CaptureGate)

| 조건 | 기준 | 출처 |
|---|---|---|
| 얼굴 검출 | 468점 신뢰도 ≥ 임계 | CV 얼굴 랜드마크 검출 |
| 각도 | 단계 0·1: yaw·pitch ±5°, 단계 2: yaw −45°±5°, 단계 3: yaw +45°±5° | 랜드마크 자세 행렬 |
| 얼굴 크기 | 눈 폭(안쪽 끝~바깥쪽 끝) ≥ 80px (비율 척도 정밀도) | 눈 끝 랜드마크 33·133·362·263 |
| 눈 상태 | 단계 0: 양쪽 눈 뜸, 단계 1: 양쪽 눈 감음(EAR 임계) | 눈꺼풀 랜드마크 |
| 손 없음 | 손 검출 박스가 얼굴 박스와 겹치지 않음 | CV 손 검출 |
| 선명 | 라플라시안 분산 ≥ 임계 | 얼굴 크롭 |
| 밝기 | 이마 L* 40~85 | 이마 영역 평균 |
| 안정 | 위 조건 연속 10프레임 | — |

충족 시 자동 촬영(셔터 없음, 수동 촬영 없음). **웹(브라우저)에서는 노출·화이트밸런스 고정이 불가**하므로 `Baseline.exposureLocked=false`로 두고 4장을 같은 자리에서 연속 촬영해 이마·눈 흰자 참조로 정규화한다. 안드로이드 앱 전환 시 단계 0 직전 고정(FULL 등급).

## 2-2b. 실시간 워핑 알고리즘 (POC 검증, `poc/look-tryon/client/`)

당초 구상한 468점 UV 메시 텍스처 굽기(부위별 deltaLab·alpha 맵) 대신, 훨씬 가벼운 절충안으로 동작을 확인했다:

1. `fullRender` 생성 직후(1회) 랜드마크를 검출해 부위별 폴리곤(`LookLayer.regions[partId].sourcePts`)을 뽑아 고정해 둔다. 부위는 눈썹(좌우 10점 링), 눈섀도우(눈꺼풀 선 9점 + 눈썹 쪽으로 45% 지점까지 올린 대응점, 밴드 형태), 입술(외곽 20점), 볼터치(좌우 8점 폴리곤) — 룩 5부위 중 라이너는 별도 부위로 분리하지 않고 눈섀도우 폴리곤에 포함(향후 필요시 눈꺼풀 선만 따로 얇은 밴드로 분리 가능).
2. 매 라이브 프레임: 같은 부위 폴리곤을 현재 랜드마크로 다시 계산(`sourcePts`와 동일한 랜드마크 인덱스, 좌표만 새로).
3. 각 폴리곤을 폴리곤 중심점 기준 팬(fan) 삼각분할 — `[중심, p[i], p[i+1]]` 삼각형 N개.
4. 삼각형마다 `fullRender` 좌표계의 3점 → 라이브 프레임 3점을 잇는 2×3 아핀 행렬을 3점 대응 선형계(Cramer 공식)로 직접 풀고, 그 삼각형으로 클리핑한 뒤 `fullRender`를 그 변환으로 그려 알파 블렌딩.
5. 부위 밖은 전혀 합성하지 않음 — 이전 시도(부위 구분 없이 얼굴 전체를 통째로 아핀 변형 1번)는 배경·피부톤까지 섞여 "화장이 전체적으로 진하게 뜨는" 문제가 있어서 폐기.

**한계**: 표정 변화 시 부위 내부의 국소 왜곡은 반영 안 됨(부위 자체는 랜드마크를 따라가지만 부위 내부는 강체 근사). 조명 보정 없음. 정식 스펙의 deltaLab 방식(피부 위에 "색차"만 얹어 원래 피부 텍스처 유지)이 아니라 `fullRender`의 픽셀을 그대로 이식하는 방식이라, 원본과 라이브 프레임의 피부 톤·조명이 크게 다르면 경계가 두드러질 수 있음 — 다음 라운드 과제.

## 2-3. 서버 장애 시
- 폰 전용 모드는 없다. 룩 생성이 실패하면 썸네일이 "로딩 중"에서 "다시 시도"로 바뀌고, 전부 실패하면 "잠시 후 다시 시도해 주세요" 안내.

## 2-4. 룩 확정 시 생성
- `LookSelection.fullRender` = 서버 화장 전이 결과(정면, 룩 전체). 화면 2-b에 표시하고, 화면 3 부위 완성본은 이 이미지를 해당 부위 크롭 박스로 줌해서 쓴다(다른 부위도 화장된 채, 별도 합성 없음). 세션 끝까지 보관 후 삭제.
- `partOrder = template.requiredParts`(눈썹→라이너→섀도우→입술→볼터치) + `contour`(쉐딩·하이라이트, 얼굴형 규칙, 룩과 무관). 사용자 변경 가능.
- `contour` 완성본은 `fullRender`에 없으므로 `fullRender`(얼굴 아래쪽 줌) 위에 규칙 마스크(F-05)의 윤곽선만 그린다(`ContourOutline`, 색 면 없음, 라벨 "쉐딩"·"하이라이트").
- `parts[]`를 `not_started`로 초기화.

## 3-5. 실시간 테두리의 위험과 대응 (POC에서 확인, 2026-09-16)

> **(2026-09-22 정정·구체화)** 아래 표의 "강체 변환", "안정 점", "각도·거리 차이 조건" 이 말로만 있어서
> 구현할 때마다 다른 점을 골랐다. 실제로 쓰는 값을 여기에 적는다.

### 강체 점 목록 — 정합에 쓰는 13점

화장·표정에 안 흔들리는 점만 쓴다.

| 부위 | 인덱스 |
|---|---|
| 눈 안팎 끝 | `33 133 362 263` |
| 콧대·코끝 | `168 6 197 195 5 4` |
| 이마 | `10` |
| 광대 | `50 280` |

**얼굴 옆(`234` `454` `127` `356`)과 턱(`152`)은 뺐다** — 입을 벌리면 메시가 같이 벌어져 유사변환을 흔든다(실기기 확인). 구현은 `client/src/core/score.ts` 의 `STABLE_IDS`.

### 각도 차 게이트

기준 사진과 확인받기 사진의 자세가 너무 다르면 **비교 자체가 성립하지 않는다.** 표정 차·정합 잔차가 임계를 넘으면 점수를 내지 않고 `check_only(reason='align')` 로 둔다(③ #43).

MediaPipe 변환행렬로 각도를 읽을 때는 **열 우선(column-major)** 으로 읽어야 랜드마크 기준과 부호가 맞는다. 크기도 0.7배 차이가 나서 **게이트는 랜드마크 yaw 를 쓴다** (#124 실측).

### 깨진 측정값

`NaN`·`Infinity` 는 모든 비교가 `false` 라 **범위 조건을 전부 통과한다.** 랜드마크 yaw 가 얼굴 폭으로 나누는 식이라 점이 겹치면 실제로 `NaN` 이 난다. 게이트 맨 앞에서 유한성을 검사해 막는다 (#127).

| 5b-5 | 톤 차이 (쉐딩·하이라이트, 내부 계산만) | 화면 표시 없음. 좌우 비교 한 줄 평 생성에만 사용 | `toneDelta`, `targetBand` |
| 5b-6 | 판정 문구 | 섀도우·볼터치: 초과 "조금 진해요" / 미달 "조금 더 진하게" / 밴드 안 "적당해요". 쉐딩·하이라이트: 판정 없이 "확인하고 넘어가세요" | `toneVerdict` |
| 5b-7 | 방향(섀도우) | "방향 일치 / 불일치" | `metrics.directionOk` |
| 5b-8 | 점수 또는 확인만 | 섀도우·볼터치: 밴드 있으면 점수, 없으면 "확인만". **쉐딩·하이라이트: 항상 "확인만"** | `score \| null` |
| 5b-9 | 버튼 | 결과 보러 가기(마지막 부위) / 다시 확인받기 / 건너뛰기 (화면 5와 동일) | — |

## 5b-2. 산출 정의

| 값 | 정의 |
|---|---|
| 유무 | 부위 평균 ΔE − 비화장 참조 ΔE > t_present |
| 세션 내 지수 | clamp((부위 평균 ΔE − 참조 ΔE) / ΔE_max_session × 100, 0, 100). `ΔE_max_session`은 고정 상한(초안 25) |
| 좌우 지수 | 좌·우 마스크 각각 |
| 피부 대비 톤 차이 | (부위 L* − 인접 비화장 L*)_now − (같은 위치)_bare → ΔL* → 톤 = ΔL*/4 (가정값) |
| 톤 판정 | 밴드 [min,max]와 비교, 밴드 없으면 판정 없음 |
| 방향(섀도우) | 지수 그라디언트 방향과 가이드 방향의 각도 차 < 30° |
| 점수 (볼터치) | 밴드 안 100, 초과·미달 정도에 비례 감점, 좌우 차 감점. 밴드 없으면 `null`(확인만) |
| 점수 (쉐딩·하이라이트) | 항상 `null`(확인만). 좌우 지수 차만 한 줄 평에 사용 |

# 진행 칩·단계 이동 (F-04, 모든 화면 3~5 공통)

| 동작 | 결과 |
|---|---|
| 칩 탭 (이전 부위) | 그 부위 `guide_shown`으로, `currentPart` 갱신(진행 중 표시 이동). 기존 `PartResult` 유지, 다시 확인받으면 `upsertPart`로 덮어쓰기(attempts+1) |
| 칩 탭 (뒤 부위, 앞 단계 미완료) | 이동 허용 + "눈썹을 아직 안 했어요" 한 줄 |
| 다음 | `status=passed`(점수 낮아도), 다음 미완료 부위로. 자동 통과 판정 없음. 남은 미완료 부위가 없으면 버튼 문구가 "결과 보러 가기"이고 화면 6으로 |
| 다시 확인받기 | 결과 화면(5)에서 화면 4 `guide_shown`으로. 확인받기 결과는 `upsertPart`로 덮어쓰기(attempts+1). 이전 점수는 유지되다가 새 결과로 교체 |
| 건너뛰기 | `status=skipped`, 다음으로. 버튼은 결과 화면(5)에만. 결과 없이 건너뛰려면 진행 칩으로 다음 부위 이동 |
| 모든 부위가 passed/check_only/skipped | 화면 6으로 |

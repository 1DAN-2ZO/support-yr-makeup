# 화면 1~5 — 기능 구현 요소 정의 (v6, 1단계: 정의만)

> 2026-09-15 · 1단계(요소·데이터·상태) 정의. 구현 방법·검증은 2단계 문서에서. 화면별 확정 사항은 `service-definition-v6.md` 부록이 기준이며, 아래 본문과 다르면 부록을 따른다.

> **v6 반영 사항 (사용자 확정)**
> - 화면 3은 **부위 완성본**(전체 완성 예상 렌더링을 이 부위로 줌한 정지 이미지) + 근거 + 필요한 제품 + "그리러 가기". 화면 4가 **실시간 테두리**(아래 3-1의 요소 3-3~3-9). 재시도는 화면 3으로.
> - 화면 5·5-b 결과는 **점수 + 가이드 테두리 겹침 + 한 줄 평만** 표시. 아래 5-1의 지표 4줄·좌우 차 숫자, 5b-1의 좌우 지수 막대·톤 차이 숫자는 **화면에 표시하지 않고** 내부 계산·진단 코드 생성에만 쓴다.
> - 화면 5-b(쉐딩·하이라이트 결과) 목업은 나중에. 쉐딩·하이라이트는 항상 "확인만", 섀도우·볼터치는 점수.
> - 서버 처리 동의를 거부하면 이용 불가. 폰 전용 모드 없음. 서버로는 정면·좌·우 3장 전송.
> 모든 좌표는 랜드마크 기준(화면 방향 무관). 사진은 서버 처리 후 즉시 삭제. 채점은 "확인받기" 버튼을 눌렀을 때만.

# 공통 데이터 (세션 전체)

```
Session {
  id: uuid
  startedAt: timestamp
  baseline: Baseline                 // 화면 1에서 생성
  bareFacePhoto: uri                 // 촬영 1 정면 눈 뜸. 화면 6 비교용, 세션 끝 삭제
  faceShape: FaceShapeResult         // 쉐딩·하이라이트 가이드에만 사용
  serverAssets: ServerAssets         // 법선 맵·부위 마스크·룩 레이어 (동의 필수)
  look: LookSelection | null         // 화면 2
  partOrder: PartId[]                // 화면 2 확정 시
  parts: PartResult[]                // 화면 5·5-b에서 갱신 (화면 6 문서와 같은 구조)
  currentPart: PartId | null
  consent: { serverProcessing: true, at: timestamp }   // false 면 세션 생성 안 됨
}
```

부위 상태: `not_started | in_progress | check_only | passed | skipped`. `in_progress`는 지금 보고 있는 부위(`currentPart`). 어느 단계든 진행 칩으로 이동 가능(F-04).

# 화면 1. 맨얼굴 촬영 (F-01)

## 1-1. 화면 요소

| # | 요소 | 내용 | 데이터 |
|---|---|---|---|
| 1-1 | 카메라 프리뷰 | 전면 카메라, 거울 모드 | 프레임 스트림 |
| 1-2 | 타원 가이드 | 얼굴 크기 점선 타원, 조건 충족 시 청록 | `CaptureGate` |
| 1-3 | 단계 안내 | "정면을 보고 눈을 뜨세요" → "눈을 감으세요" → "왼쪽으로 45°" → "오른쪽으로 45°" | `captureStep` 0~3 |
| 1-4 | 진행 표시 | 4칸, 찍힌 만큼 채움 | `captured[]` |
| 1-5 | 조건 안내 한 줄 | 칩 없음. 안 맞는 조건 하나만 문구(각도 → 얼굴 크기 → 눈 상태 → 손 → 선명 → 밝기 순) | `CaptureGate.firstFail` |
| 1-6 | 동의 화면 (**세션마다**) | 서버 처리 동의/거부. **거부하면 "서버 처리에 동의해야 사용할 수 있어요" 안내로 멈춤**(폰 전용 모드 없음). 웹이라 저장하지 않음 | `consent` |
| 1-7 | 완료 화면 | 썸네일 4개 + 장별 "다시 찍기" + "룩 고르러 가기". | `Baseline` |
| 1-8 | 다시 찍기 (틀린 장만) | 해당 단계로 돌아가 그 장만 재촬영. 정면 눈 뜸 재촬영 시 기준 재계산 + 나머지 3장 재정렬 | `captured[i]` |

## 1-2. 촬영 조건 (CaptureGate)

| 조건 | 기준 | 출처 |
|---|---|---|
| 얼굴 검출 | 468점 신뢰도 ≥ 임계 | CV 얼굴 랜드마크 검출 |
| 각도 | 단계 0·1: yaw·pitch ±5°, 단계 2: yaw −45°±5°, 단계 3: yaw +45°±5° | 랜드마크 자세 행렬 |
| 얼굴 크기 | 홍채 지름 ≥ 25px (mm 척도 정밀도) | 홍채 랜드마크 468~477 |
| 눈 상태 | 단계 0: 양쪽 눈 뜸, 단계 1: 양쪽 눈 감음(EAR 임계) | 눈꺼풀 랜드마크 |
| 손 없음 | 손 검출 박스가 얼굴 박스와 겹치지 않음 | CV 손 검출 |
| 선명 | 라플라시안 분산 ≥ 임계 | 얼굴 크롭 |
| 밝기 | 이마 L* 40~85 | 이마 영역 평균 |
| 안정 | 위 조건 연속 10프레임 | — |

충족 시 자동 촬영(셔터 없음, 수동 촬영 없음). **웹(브라우저)에서는 노출·화이트밸런스 고정이 불가**하므로 `Baseline.exposureLocked=false`로 두고 4장을 같은 자리에서 연속 촬영해 이마·눈 흰자 참조로 정규화한다. 안드로이드 앱 전환 시 단계 0 직전 고정(FULL 등급).

## 1-3. 출력 데이터

```
Baseline {
  photos: { frontOpen, frontClosed, left45, right45 }: { uri(임시), w, h, landmarks[468+10], pose{yaw,pitch,roll}, capturedAt }
  mmPerPx: number                     // 11.7mm / 홍채 지름 px (frontOpen 기준)
  lighting: { foreheadL: number, scleraWhite: {L,a,b} }     // 조명 참조
  skinRef: { [partId]: {L,a,b} }      // 부위 인접 비화장 피부 Lab (frontOpen)
  bareTexture: { [partId]: LabMap }   // 부위별 맨얼굴 Lab 맵 (랜드마크 정렬)
  lidPoints: Landmark[]               // frontClosed 에서 눈꺼풀 기준점
  sideRefs: { left: {cheekLine, jawLine}, right: {...} }    // 측면 45°에서 옆 볼·턱선 랜드마크
  exposureLocked: boolean
}
```
사진 원본은 `Baseline` 생성 후 즉시 삭제(frontOpen만 `bareFacePhoto`로 세션 끝까지 보관). 서버 전송은 frontOpen·left45·right45 3장.

## 1-4. 얼굴형 판정 (F-02, 쉐딩·하이라이트 가이드 전용, 화면 표시 없음)

| 입력 | 계산 | 출력 |
|---|---|---|
| frontOpen 랜드마크 | 가로세로비(얼굴 높이/광대 폭), 광대 폭 대비 턱 폭, 턱 각도, 이마 폭 대비 광대 폭 | `FaceShapeResult { label: 'oval'|'round'|'square'|'heart'|'oblong', ratios{...}, confidence, userOverride: label|null }` |

규칙 임계는 규칙 DB에서 받는다. 결과는 쉐딩·하이라이트 가이드(3-2)와 그 완성본 멘트에서만 참조한다.

## 1-5. 서버 요청 (동의 시)

```
POST /jobs { type:'session_assets', images: { frontOpen, left45, right45 }(jpeg), lookIds: [...] }
→ { jobId }  ;  GET /jobs/{jobId} → { status, result: ServerAssets }
ServerAssets { normalMap(uri), partMasks{ [partId]: mask }, lookLayers{ [lookId]: layerUri }, expiresAt }
```
왕복 목표 3초. 거부 시 세션 생성 안 됨(이용 불가 안내). 서버 장애 시 "잠시 후 다시 시도" 안내.

## 1-6. 상태

```
capture: idle → consent → (거부: blocked) / (동의) step0 → step1 → step2 → step3 → processing → done
                                   ↑ 각 단계에서 조건 미충족이면 안내 문구, 15초 넘으면 "손·머리카락 확인" 힌트
```

# 화면 2. 룩 얹어보기 + 제품 목록 (F-03, F-04)

## 2-1. 화면 요소

| # | 요소 | 내용 | 데이터 |
|---|---|---|---|
| 2-1 | 실시간 프리뷰 + 룩 레이어 | 카메라 프리뷰에 선택 룩의 화장 레이어를 매 프레임 워핑 합성, "LIVE" 칩 | `LookLayer`, 프레임 랜드마크 |
| 2-2 | 룩 썸네일 가로 스크롤 (10개) | 서버 생성 전 룩은 스피너 + "로딩 중", 끝난 룩부터 활성. 선택 표시 | `LookTemplate[]`, `lookLayers` |
| 2-3 | 제품 목록 카드 | "이 룩에 쓰인 것" 부위별 제품 종류·색 계열·질감·도구. 전부 펼침, 접기 없음 | `LookTemplate.products[]` |
| 2-4 | 버튼 | "이 룩으로 시작" → 화면 2-b | — |
| 2-5 | **화면 2-b 전체 완성 예상** | 내 정면 사진(촬영 1)에 룩 전체가 입혀진 서버 렌더링 한 장 + "시작". 멘트 없음. 화면 3 완성본의 원본 | `LookSelection.fullRender` |

## 2-2. 데이터

```
LookTemplate {
  id, name, referenceImage(uri, 서버만)
  parts: { [partId]: { mask: 규칙 마스크 정의, guideParams: {...} } }   // brow·liner·shadow·lip·cheek 만. contour(쉐딩·하이라이트)는 룩에 없음
  products: [{ partId, type: '파우더 블러셔', colorFamily: '핑크', finish: '매트', tool: '블러셔 브러시', order: 3 }]
  guideParams: { wingAngleDeg, wingLenMm, browTailY, ... }   // 룩 고정값, 얼굴형 조정 없음
  harmonyRange: { maxDeltaAb } | null
  weights: { [partId]: number }
  requiredParts: PartId[]            // 룩 부위. 세션 partOrder = requiredParts + ['contour'] (얼굴형 규칙 단계, 항상 마지막)
}

LookLayer {                              // 서버 결과에서 폰이 만든 실시간 트래킹용 레이어
  lookId
  meshUV: Float32Array                   // 468점 UV 좌표(고정)
  layer: { [partId]: { deltaLab: LabMap, alpha: AlphaMap } }   // 메시 텍스처 공간
  builtFrom: 'server'                    // 서버 결과만 (폰 전용 대체 없음)
}

LookSelection { lookId, selectedAt, previewImage(uri), fullRender(uri) }
```

## 2-3. 서버 장애 시
- 폰 전용 모드는 없다. 룩 생성이 실패하면 썸네일이 "로딩 중"에서 "다시 시도"로 바뀌고, 전부 실패하면 "잠시 후 다시 시도해 주세요" 안내.

## 2-4. 룩 확정 시 생성
- `LookSelection.fullRender` = 서버 화장 전이 결과(정면, 룩 전체). 화면 2-b에 표시하고, 화면 3 부위 완성본은 이 이미지를 해당 부위 크롭 박스로 줌해서 쓴다(다른 부위도 화장된 채, 별도 합성 없음). 세션 끝까지 보관 후 삭제.
- `partOrder = template.requiredParts`(눈썹→라이너→섀도우→입술→볼터치) + `contour`(쉐딩·하이라이트, 얼굴형 규칙, 룩과 무관). 사용자 변경 가능.
- `contour` 완성본은 `fullRender`에 없으므로 `fullRender`(얼굴 아래쪽 줌) 위에 규칙 마스크(F-05)의 윤곽선만 그린다(`ContourOutline`, 색 면 없음, 라벨 "쉐딩"·"하이라이트").
- `parts[]`를 `not_started`로 초기화.

| 3-7 | 품질 게이트 한 줄 | 칩 없음. 다 맞으면 "확인받을 준비 됨", 안 맞으면 가장 먼저 걸린 조건 하나만 문구로 (정면 → 양쪽 눈 → 손 → 선명 → 밝기 순) | `QualityGate.firstFail` |
| 3-8 | 버튼 | "확인받기"만 (게이트 충족 시 활성, 누르면 즉시 촬영). 건너뛰기는 화면 5에만 | — |

## 3-2. 가이드 정의 (GuideSet)

| 부위 | 기준점 | 가이드 형태 | 파라미터 (룩 템플릿 고정값, 위치·크기만 내 랜드마크에 맞춤) |
|---|---|---|---|
| 눈썹 | 눈썹 랜드마크 10점, 콧방울·눈꼬리 연장선 | 시작·산·꼬리 3점 + 곡선, 좌우 높이 기준선 | 산 위치 비율, 꼬리 길이 mm, 두께 mm |
| 아이라이너 | 위 눈꺼풀 선(눈 뜸), 눈꺼풀 기준점(눈 감음) | 속눈썹 선 점선 + 꼬리 선 (각도·mm 라벨 없음) | 꼬리 각도°, 길이 mm, 두께 mm, 앞머리 두께 (내부값) |
| 섀도우 | 눈꺼풀 기준점, 눈두덩 마스크 | 영역 테두리 + 방향 화살표(눈꼬리 쪽으로 진하게) | 범위 비율, 방향, 목표 지수 밴드 |
| 입술 | 입술 윤곽 20점 | 경계선 + 오버/언더 표시 | 경계 오프셋 mm |
| 볼터치 | 광대 랜드마크 다각형 | 영역 테두리 + 방향 | 룩 템플릿 위치·범위, 목표 지수 밴드 |
| 쉐딩·하이라이트 | 얼굴형 규칙(F-02) × 서버 법선 맵(광대 최고점·턱선 방향), 없으면 랜드마크 근사 | 영역 테두리 + 방향 | 얼굴형별 위치·범위, 방향, 톤 밴드(표시용). 얼굴형이 들어가는 유일한 부위. 룩과 무관 |

```
GuideSet { partId, polylines: [{pts(mm 좌표, 랜드마크 기준), style}], regions: [{mask, style: 'outline-only'}], labels: [{text, anchor}],   // 화면 4는 테두리만, 면 채우기 없음
           rationale: string, targetBand: {toneMin, toneMax} | null, source: 'normal_map' | 'landmark_only' }
```
가이드는 프레임마다 랜드마크에 다시 붙인다(좌표는 랜드마크 상대·mm). 화면 방향과 무관.

## 3-3. 품질 게이트 (QualityGate)

| 조건 | 기준 |
|---|---|
| 정면성 | yaw ±15°, pitch ±10° |
| 부위 가시성 | 눈 단계: 양쪽 눈 랜드마크 신뢰도 / 입술·볼: 해당 랜드마크 |
| 손 없음 | 손 박스가 부위 크롭과 겹치지 않음 |
| 선명 | 라플라시안 분산 ≥ 임계 |
| 밝기 | 이마 L* 가 `Baseline.lighting.foreheadL ± 12` |
| 안정 | 연속 5프레임 |

미충족 시 한 줄 안내(가장 먼저 걸린 조건 하나만). 버튼 비활성.

## 3-4. 상태 (부위 하나)

```
guide_shown → (얼굴 미검출 3s) away → (얼굴 재검출) guide_shown
guide_shown + gate_ok → ready   →  [확인받기 탭] → capturing (3~5프레임) → scoring → result(화면 5·5-b)
ready + gate_fail → guide_shown
어느 상태에서든 진행 칩 탭 → 다른 부위의 guide_shown
```
세션 draft는 상태가 바뀔 때마다 로컬 저장(앱 종료 복원용).

# 화면 5. 부위 결과 — 형태 부위 (F-08, F-09: 눈썹·아이라이너·입술)

## 5-1. 화면 요소

| # | 요소 | 내용 | 데이터 |
|---|---|---|---|
| 5-1 | 결과 사진 | 평균 프레임 위에 가이드 테두리(청록)만 겹침. 감지 영역·이탈 화살표·점 표시 없음 (내부 `overlay` 데이터는 계산하되 그리지 않음) | `PartResult.metrics`, `overlay` |
| 5-2 | 점수 | 부위 점수 0~100 | `score` |
| 5-3 | 지표 (내부, 화면 표시 없음) | 겹침(좌/우), 이탈 최대 mm, 두께 mm, 꼬리 각도 / 입술은 경계 안·밖 mm. 한 줄 평 생성과 점수 계산에만 사용 | `metrics` |
| 5-4 | 좌우 차 (내부) | 눈 단계: 좌우 꼬리 높이 차 mm 등 | `metrics.lrDiffMm` |
| 5-5 | 한 줄 평 + 코드 | "오른쪽 꼬리가 조금 위로 갔어요. 왼쪽에 맞춰 살짝 내려 그리세요" (숫자 없음) | `diagnosis`, `diagnosisCodes` |
| 5-6 | 버튼 | 다음(점수 무관 활성, `status=passed`) / 건너뛰기(`status=skipped`, 합산 제외). 재시도 버튼 없음, 다시 하려면 진행 칩 | → `status` |

## 5-2. 인식 파이프라인 정의 (F-08)

```
frames(3~5) → 랜드마크 정렬(각 프레임을 Baseline.frontOpen 좌표계로) → 프레임 평균
→ 조명 보정(이마·눈 흰자 참조로 L 스케일) → ΔE 맵 = Lab(now) − Baseline.bareTexture[part]
→ 손 마스크 제외 → 임계(ΔE > t_part) → 후보 영역
→ CV 화장 영역 시맨틱 분할 모델(INT8)로 정밀화 (실패 시 임계 영역 그대로)
→ 부위 영역 마스크 + 골격선(라이너·눈썹은 skeleton, 입술은 경계)
```

## 5-3. 채점 정의 (F-09, 형태)

| 지표 | 정의 | 단위 |
|---|---|---|
| 겹침률 | 감지 영역 ∩ 가이드 밴드 / 감지 영역 | % (좌·우) |
| 이탈 최대 | 감지 골격선에서 가이드까지 최대 거리 | mm, 방향(위/아래/밖) |
| 두께 | 골격선 법선 방향 폭 중앙값 | mm |
| 꼬리 각도 | 꼬리 구간 회귀 직선 각도 | ° (좌·우, 가이드) |
| 좌우 차 | 좌우 꼬리 끝 높이 차(맨얼굴 비대칭 차감) | mm |

```
score = 100 − (1−coverage)·50 − min(overflow·60, 30) − min(|wingΔ|·8, 20) − min(|thick−guide|·5, 10)   // POC 식 유지, 부위별 계수는 규칙 DB
diagnosisCodes: 규칙 DB 코드표에서 임계 초과 항목 매핑 (예 LINER_WING_HIGH_R)
```

# 화면 5-b. 부위 결과 — 강도 부위 (F-08, F-09: 섀도우·볼터치는 점수, 쉐딩·하이라이트는 확인만. 화면 5와 같은 화면, 강도 부위용 설명)

## 5b-1. 화면 요소

| # | 요소 | 내용 | 데이터 |
|---|---|---|---|
| 5b-1 | 결과 사진 | 부위 확대 + 가이드 테두리 겹침. 라벨·숫자 없음 | `overlay` |
| 5b-2 | 유무 | "발림 확인" / "감지되지 않음" | `metrics.present` |
| 5b-3 | 좌우 지수 (내부) | 세션 내 지수 0~100, 화면 표시 없음. 한 줄 평 방향에만 사용 | `lrIndex` |
| 5b-4 | 이전 대비 (내부) | 진행 칩으로 다시 와서 확인받았을 때 증감, 한 줄 평("아까보다 진해졌어요")에만 사용 | `attempts` 이력 |
| 5b-5 | 톤 차이 (쉐딩·하이라이트, 내부 계산만) | 화면 표시 없음. 좌우 비교 한 줄 평 생성에만 사용 | `toneDelta`, `targetBand` |

| 5b-7 | 방향(섀도우) | "방향 일치 / 불일치" | `metrics.directionOk` |
| 5b-8 | 점수 또는 확인만 | 섀도우·볼터치: 밴드 있으면 점수, 없으면 "확인만". **쉐딩·하이라이트: 항상 "확인만"** | `score | null` |
| 5b-9 | 버튼 | 다음 / 건너뛰기 (화면 5와 동일, 재시도 없음) | — |

## 5b-2. 산출 정의

| 값 | 정의 |
|---|---|
| 유무 | 부위 평균 ΔE − 비화장 참조 ΔE > t_present |
| 세션 내 지수 | clamp((부위 평균 ΔE − 참조 ΔE) / ΔE_max_session × 100, 0, 100). `ΔE_max_session`은 고정 상한(초안 25) |
| 좌우 지수 | 좌·우 마스크 각각 |
| 피부 대비 톤 차이 | (부위 L* − 인접 비화장 L*)_now − (같은 위치)_bare → ΔL* → 톤 = ΔL*/4 (가정값) |
| 톤 판정 | 밴드 [min,max]와 비교, 밴드 없으면 판정 없음 |
| 방향(섀도우) | 지수 그라디언트 방향과 가이드 방향의 각도 차 < 30° |
| 점수 (볼터치) | 밴드 안 100, 초과·미달 정도에 비례 감점, 좌우 차 감점. 밴드 없으면 `null`(확인만) |
| 점수 (쉐딩·하이라이트) | 항상 `null`(확인만). 좌우 지수 차만 한 줄 평에 사용 |

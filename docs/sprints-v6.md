## 3. 스프린트 3개

### 스프린트 1 — 기준선·결정·착수 (9/21~9/23, 작업 2일 + 리뷰)

**목표**: 여섯 명이 각자 자기 브랜치에서 막힘없이 일할 수 있는 상태 + 촬영 세션 준비 완료.

- 담당자 배정, 팀 결정 6개 (화면 3 두 벌, 촬영 4장 용도, 룩 사진 방법, 통과 기준, 서버 장애 문구)
- 전원 `bash scripts/setup.sh` 통과, 계약(`types.ts`·`schemas.py`) 읽고 이의 정리
- 다른 모듈이 기다리는 ★ 항목 착수: core TS 이전(`flow`·`guides`·`gate`·`score`), 확인받기 프레임 묶음, 채점 Node CLI, 서버 워커 연결
- 촬영 동의서 양식 완성 → **9/23까지 촬영 일정 확정** (추석 연휴에 각자 지인 섭외)

**리뷰(9/23)**: 결정 6개가 다 닫혔나. 각 모듈 브랜치에 커밋이 하나 이상 있나.

### 스프린트 2 — core 이전 완료·촬영·평가 1차 (9/28~10/2, 작업 4일 + 리뷰)

**목표**: 발표 숫자의 재료를 전부 만든다. 이 스프린트가 프로젝트의 중심이다.

- **촬영 세션 20명 × 10장** (5-1) — 가장 긴 줄. 월·화에 끝낸다
- core TS 이전 완료 → `client/src/core/`에 촬영·가이드·게이트·채점·합산이 전부
- 골든 세트 30장 고정, 부위별 사람 판정, 얼굴형 2인 라벨 + 규칙 기준선
- 서버: Stable-Makeup 워커 + 룩 10개 30초, 화장 레이어 추출
- 룩 참조 사진 10장 확보 → 룩 템플릿 값 확정
- **E-1 실사진 채점 1차** — 발표 숫자 ①

**리뷰(10/2)**: 촬영 사진이 골든에 들어갔나. E-1 숫자가 나왔나. 폰에서 전 흐름이 도나.

### 스프린트 3 — 통합·평가 마무리·발표 (10/6~10/8, 작업 2일 + 최종)

**목표**: 하나의 앱으로 합치고, 숫자를 표로 만들고, 발표 자료를 낸다.

- 화면 통합: 각 모듈 core를 화면에 연결, 폰에서 끝까지
- E-3 화장 전이 평가(시간·정체성·색 반영) — 발표 숫자 ③
- 얼굴형: 규칙 vs 모델 비교 — 발표 숫자 ② (모델 학습이 늦으면 규칙 기준선만으로 발표)
- 사용자 실험 **3~5명**으로 축소 (10명은 시간이 없다), 퍼널 로그 집계
- `eval/run_all.py` 최종 실행 → 결과표, 발표 슬라이드 4장

**최종(10/8)**: 데모가 폰에서 도나. 결과표에 숫자 세 개가 채워졌나.

## 4. 범위에서 뺀 것 (백로그)

작업일 8일에 안 들어가서 뺐다. 발표에서는 "확장 단계"로 말한다.

| 뺀 것 | 이유 | 대신 |
|---|---|---|
| 룩 전용 LoRA 학습 | GPU 시간 + 룩 사진이 늦게 온다 | 공개 모델 그대로, 평가만 |
| 화장 영역 분할 모델 | 이미 MVP에서 뺀 것 (데이터 계획 4차) | ΔE + 랜드마크 영역 |
| Redis + RQ 큐 | 시연은 한 명이라 프로세스 큐로 충분 | 지금 큐 유지, 문서에 교체 방법 |
| 468점 메시 워핑(WebGL) | 이틀 이상 | 부위별 아핀까지 |
| IndexedDB 사진 복원 | 시연 흐름에 없어도 됨 | 상태만 복원, 사진 없으면 안내 |
| AI Hub 데이터 3종 | 승인이 마감 전에 안 떨어진다 | 신청만 해 두고 발표에 "신청 중" |
| 사용자 실험 10명 | 일정 없음 | 3~5명으로 축소 |
| 흔들림 대응 3·4단계(강체 변환·깜빡임 정지) | 1·2단계로 체감 대부분 해결 | 데드존 + One-Euro 까지 |
| 얼굴형 모델 여러 후보 비교(S-2 C·D) | 학습 시간 | 규칙 기준선 + 후보 하나만 |

**백로그 이슈는 지우지 않는다.** 마일스톤 "백로그"에 그대로 두고, 남는 시간이 생기면 위에서부터 꺼낸다.

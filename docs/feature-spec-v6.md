## 1. 세션 시작

### F-01 맨얼굴 촬영
- **동의**: 세션 시작마다 서버 처리 동의 화면(웹이라 저장 안 함). **거부하면 서비스 이용 불가 안내**("서버 처리에 동의해야 사용할 수 있어요")로 멈춘다. 폰 전용 모드는 없다.
- **촬영 안내 (2026-09-22 추가)**: 동의하면 카메라를 켜기 전에 한 번 "찍기 전에 확인해 주세요 — 앞머리를 넘겨서 이마가 다 보이게 / 머리카락을 귀 뒤로 넘겨서 양쪽 귀가 다 보이게" 를 보여 주고 "확인했어요" 를 누르면 촬영을 시작한다. 이마는 조명 참조·잘림 판정, 귀까지의 얼굴 윤곽은 45° 장·얼굴형·쉐딩에 쓰이므로 머리카락이 가리면 안 된다 (`client/src/core/flow.ts CAPTURE_GUIDE`).
- **가림 차단 (2026-09-22 추가, 2026-09-23 정정)**: 얼굴에 장애물(손·머리카락·브러시·퍼프·마스크)이 있으면 찍지 않고 "얼굴을 가리지 말아 주세요" 한 줄로 알려 준다. **모델을 쓰지 않는다** — 손 검출(7.46MB)·셀피 분할(16.4MB)은 첫 로딩 때문에 뺐다(#144). 비화장 참조인 이마 L*a*b* 가 갑자기 크게 변하면 가림으로 본다(조명은 서서히 변한다). 안경·앞머리·귀는 찍기 전 안내("앞머리를 넘겨서…", "머리카락을 귀 뒤로…", "안경을 쓰셨다면 벗어 주세요")로 알려 준다.
- **얼굴형 판단용 정면 프레임 (2026-09-22 추가)**: 첫 장(정면 눈 뜸)을 찍을 때 사용자 모르게 앞뒤 프레임 5장을 같이 저장해 얼굴형 분류(⑤)에 넘긴다. 따로 찍는 단계는 없다. 사진은 기기 메모리에만, draft 에는 장수만.
- **입력**: 정면(눈 뜸), 정면(눈 감음), 좌 45°, 우 45° 4장. 고개 각도 자동 감지 촬영, 허용 ±5°. **자동 촬영만, 수동 셔터 없음.** 정면 2장은 색 기준·척도·눈꺼풀, 측면 2장은 옆 볼 쉐딩 기준·±30° 얹어보기·서버 법선 정밀화. **(2026-09-18 확정, 1-10)** 눈 감음 장은 윗눈꺼풀 선을 눈 축 기준 비율로 저장해 화면 4 에서 눈 감고 그릴 때 테두리를 옮기는 데 쓴다(`client/src/core/baseline.ts eyelidRef`). 45° 2장은 서버 법선 정밀화용으로 유지하되, 1주차 검증 4에서 MediaPipe 3D 메시만으로 쉐딩 위치가 나오면 정면 2장으로 줄인다. 촬영 조건에 **색(이마 a*b* 변동)** 조건이 밝기 다음에 추가됐다(1-9, 임계는 1-4 실측으로).
- **다시 찍기**: 틀린 장만 다시 찍는다(4장 처음부터 아님). 정면 눈 뜸을 다시 찍으면 색 기준·척도·조명 참조를 자동 재계산하고, 나머지 3장은 새 기준으로 다시 정렬한다.
- **노출**: 브라우저에서는 노출·화이트밸런스 고정이 안 되므로 4장을 같은 자리·같은 조명에서 연속 촬영하고 이마·눈 흰자 참조로 정규화. (안드로이드 앱 전환 시 Camera2 FULL 등급에서 고정.)
- **촬영 조건 안내**: 조건(각도·얼굴 크기·눈 상태·손·선명·밝기)이 안 맞으면 **안 맞는 것 하나만 한 줄**로 표시("조금 더 밝은 곳으로"). 칩 없음. 화면 4 품질 게이트와 같은 방식.
- **처리 (클라이언트)**: CV 얼굴 랜드마크 검출 모델(468점+홍채) → 눈 폭·입술 폭·얼굴 폭을 기준 길이로 삼는 **비율 척도**(절대 단위 mm 없음) → 이마·볼 비화장 영역 조명 참조, 눈 흰자 흰색 참조 → 부위별 맨얼굴 Lab 색 기준 → 눈 감은 장에서 눈꺼풀 기준점.
- **처리 (서버)**: 정면 눈 뜸·좌 45°·우 45° **3장**을 서버로 전송 → CV 단안 표면 법선 추정 모델(3장을 합쳐 옆 볼·턱선 법선 정밀화) + CV 얼굴 파싱 모델 → 광대 돌출·턱선 방향 맵, 부위 마스크 반환. 눈 감음 장은 보내지 않는다. 원본 즉시 삭제. 서버 장애 시 "잠시 후 다시 시도" 안내(랜드마크 근사는 지연 중 임시 표시용).
- **출력**: 랜드마크·척도·조명 참조·맨얼굴 색 기준(클라이언트), 법선 맵·부위 마스크(서버).
- **수용 기준**: 4장 촬영 60초, 폰 처리 1초, 서버 왕복 3초 이내.

### F-02 얼굴형 판정 (쉐딩·하이라이트 전용)
- 랜드마크 2D 비율(가로세로비, 광대 폭 대비 턱 폭, 턱 각도, 이마 폭 대비 광대 폭)로 얼굴형 5분류(계란·둥근·각진·긴·하트).
- **용도 한정**: 쉐딩·하이라이트 가이드(F-05)의 위치·범위 규칙과 완성본 멘트에만 쓴다. 눈썹·아이라이너·섀도우·입술·볼터치 가이드와 룩 얹어보기는 얼굴형과 무관하게 룩 템플릿 그대로.
- 얼굴형 자체는 화면에 표시하지 않는다. 대신 쉐딩·하이라이트 단계의 완성본 화면(F-06 화면 3) 근거 한 줄에 **멘트로만** 드러난다: "둥근 얼굴형이라 턱선과 광대 아래에 쉐딩을, 광대 위에 하이라이트를 넣었어요". 사용자 수정은 설정에서.
- 검증(선택): 공개 데이터셋(Face Shape 5,000장)으로 규칙 판정 일치율만 확인. 별도 분류 모델은 두지 않는다.

## 2. 룩 선택

### F-03 룩 얹어보기
- 룩 **초기 10개**의 참조 이미지를 생성 AI 확산 기반 화장 전이 모델로 사용자 정면 사진에 입힌다. **서버 생성이 끝나기 전에는 썸네일에 "로딩 중" 표시**(간단 미리보기 없음). 생성이 끝난 룩부터 순서대로 활성. 서버 GPU 워커. 룩은 조정 없이 참조 이미지 그대로.
- **실시간 트래킹(폰)**: 서버 결과에서 화장 레이어만 추출한다. 생성 이미지와 원본 정면 사진을 같은 랜드마크 메시(468점 삼각화)에 정렬 → 부위 마스크별 색 차이(Lab)와 알파를 메시 텍스처로 저장. 카메라 프리뷰에서 매 프레임 랜드마크로 메시를 워핑해 이 레이어를 곱하기·소프트라이트로 합성. 고개 ±30°, 눈 감기·입 벌리기에 메시가 따라감. 추가 모델 없음.
- 출력: 룩별 실시간 미리보기(전환 0.5초 이내), 정지 이미지(전체 완성 예상용). 룩당 서버 생성 3초 이내, 10개 병렬 시 첫 룩 3초·전체 30초 이내 목표, 캐시.
- 한계: 머리카락·손 가림은 처리하지 않음. 조명이 크게 바뀌면 레이어 색이 어긋남(색 차이 기반이라 밝기 변화에는 어느 정도 견딤). 서버 장애 시 재시도 안내(대체 미리보기 없음).
- 원칙: 얹어본 결과는 **채점 기준으로 쓰지 않음**. 원본·결과는 세션 종료 시 서버에서 삭제. 화장 레이어는 폰에만 남고 세션 종료 시 삭제.
- 수용 기준: 30fps 유지, 메시 정렬 오차 ±30°에서 공개, 서버 정지 이미지 대비 색 차이 ΔE 평균.

### F-04 룩 확정·전체 완성 예상·부위 순서·제품 목록
- **전체 완성 예상 (화면 2-b)**: "이 룩으로 시작"을 누르면 내 정면 사진(촬영 1)에 룩 전체가 입혀진 서버 렌더링 한 장을 보여준다. 아래에 "시작" 버튼. 멘트 없음. 이 이미지는 세션 끝까지 보관하고 **부위 완성본(화면 3)은 이 렌더링을 해당 부위로 줌해서 쓴다**.
- 선택 룩·숙련도 → 부위 순서. 기본: 눈썹 → 아이라이너 → 섀도우 → 입술 → 볼터치 (룩 템플릿 부위) → **쉐딩·하이라이트 (룩과 무관한 고정 마지막 단계, 얼굴형 규칙)**. 변경 가능.
- **룩 템플릿 범위**: 10개 룩은 눈썹·아이라이너·섀도우·입술·볼터치만 담는다. 쉐딩·하이라이트는 룩 템플릿에 없고 얼굴형 규칙(F-02·F-05)에서 온다. 제품 목록에서 쉐딩·하이라이트 줄은 얼굴형 규칙의 기본 제품(컨투어 파우더, 하이라이터, 브러시)으로 채운다.
- **단계 이동**: 상단 진행 칩(룩 5부위 + 쉐딩·하이라이트 = 6개)을 눌러 어느 단계로든 이동한다. 이전 부위로 돌아가면 그 부위의 가이드가 다시 뜨고 확인받기도 다시 할 수 있다. 앞 단계를 건너뛰고 뒤로 가는 것도 허용하되 "눈썹을 아직 안 했어요" 한 줄만 표시. 각 부위의 상태(미시작·**진행 중**·완료·확인만·건너뜀)와 최신 점수를 칩에 표시. 진행 중은 지금 보고 있는 부위.
- **제품 목록 표시**: 룩 템플릿에 부위별 {제품 종류, 색 계열, 질감·마감, 도구, 순서}를 사람이 적어 둔다. 룩 고른 직후 "이 룩에 쓰인 것"으로 **전부 펼쳐서** 표시(접기 없음). 브랜드·상품명 없음. 체크·필터 기능 없음.
- 색 계열 검수: 참조 이미지의 부위 색을 Lab로 샘플링해 "핑크 계열" 이름을 자동 제안, 사람이 확정.

## 3. 부위 코칭

### F-05 부위별 가이드 생성
- 눈썹(시작·산·꼬리, 룩 템플릿 형태), 아이라이너(꼬리 각도·길이, 눈 감은 기준점), 섀도우(눈꺼풀 방향·범위), 입술(경계), 볼터치(광대 위 영역·방향): 룩 템플릿 × 랜드마크 규칙. 얼굴형 무관.
- **쉐딩·하이라이트**: 얼굴형 규칙(F-02, 예: 둥근형은 턱선·광대 아래 쉐딩, 긴형은 이마·턱 끝 쉐딩, 하이라이트는 T존·광대 위) × 서버 법선 맵(광대 돌출 최고점·턱선 방향)으로 위치·방향·범위 산출. 법선 없으면 랜드마크 근사. **(2026-09-17 추가)** 법선 모델 1순위 후보 DSINE 은 **비상업 라이선스**(`tech-stack-v6.md` 8-2). 발표·과제는 가능하나 사업화 시 **Marigold-Normals(Apache-2.0) 또는 MediaPipe 3D 메시(468점 z값) 근사**로 교체한다. 랜드마크 근사 테두리는 `poc/screen3/contour.js` 로 구현돼 있어 법선 없이도 3-c 화면이 뜬다. 관련 특허 US 10,650,224 B2(2036년까지) 는 사업화 시 회피 설계 필요(`screen3-tech-v6.md` 4-2). **얼굴형 규칙이 들어가는 부위는 이 둘뿐.** 쉐딩·하이라이트는 룩 템플릿에 없으므로 **완성본(화면 3-c)은 서버 렌더링 위에 규칙 자리를 테두리로만** 보여준다(색 면 채우기 없음, "쉐딩"·"하이라이트" 라벨 두 개).
- 출력: 부위 마스크 + 근거 문장(룩 5부위는 룩 규칙 근거, 숫자 없이. **쉐딩·하이라이트는 얼굴형 멘트** "둥근 얼굴형이라 턱선과 광대 아래에 쉐딩을, 광대 위에 하이라이트를 넣었어요") + **필요한 제품 한 줄** + 섀도우·볼터치 목표 지수 밴드(채점용) + 쉐딩·하이라이트 목표 톤 밴드(교재 1~2톤 → ΔL* 환산, 가정값. 확인만이라 가이드 표시용).
- 수용 기준: 전문가 3~5명 동의율. 규칙·밴드 출처 문서화.

### F-06 부위 완성본 보기 + 실시간 테두리
- **화면 3 완성본**: 이 부위가 다 되면 어떤 모습인지 정지 이미지로 먼저 보여준다. **전체 완성 예상 렌더링(F-04, 2-b)을 이 부위로 줌한 이미지**(다른 부위도 화장된 채, 별도 합성 없음). **(2026-09-17 보류 사항)** 512 렌더를 눈 단계로 줌하면 7.4배 확대라 선이 뭉개진다(`screen3-tech-v6.md` 3장). 1순위 대안은 **원본 정면 사진 + F-03 화장 레이어를 확대한 뒤 좌표로 그리기**(3.6배, 새 모델 없음, PoC 확인) → 2순위 타일 업스케일 512→1024(Apache-2.0) → 3순위 512 줌. 1주차 검증 5(ΔE)로 확정하고 이 문장을 고친다. 완성본 소스를 읽는 코드는 한 곳(`getFullRender`)에 모아 둔다. 쉐딩·하이라이트만 렌더링에 없으므로 규칙 마스크 합성(F-05). 근거 한 줄은 **숫자 없이 말로**("눈꼬리를 살짝 올려 짧게 빼세요"), "지금 필요한 것". 버튼 "그리러 가기" → 화면 4. 진행 칩으로 이 부위를 다시 고르면 이 화면부터 다시 시작한다.
- **화면 4 실시간 테두리**: 라이브 프리뷰가 화면 전체를 채우고, 그 위에 그릴 자리 테두리(가이드 폴리라인·영역)가 매 프레임 랜드마크에 붙어 따라간다. 부위 2~3배 확대 크롭, 추적 정렬, 떨림 제거, 눈 감으면 눈꺼풀 기준 전환, 거울 모드. 화면에 두는 것은 진행 칩, 품질 게이트 한 줄, 구석의 작은 "확인받기" 버튼뿐. 제품 안내·근거는 화면 3에서만 보여주고 여기엔 없다.
- **부위별 화면 방향**
  - 눈썹·아이라이너·섀도우: 좌우를 같이 봐야 하므로 **양쪽 눈을 한 화면에** 담는다(눈 바깥쪽 끝에서 끝까지 + 여백 15%). **완성본(화면 3)·실시간 테두리(화면 4)·결과(화면 5) 모두 가로.** 눈·눈썹 단계에 들어갈 때 "폰을 가로로 돌리세요" 안내를 띄우고, 가로 모드로 바뀌면 안내를 닫는다. 세로로 계속 들면 양쪽 눈을 세로 화면에 맞춰 작게 보여주되 확대율이 낮다는 표시를 한다.
  - 입술·볼터치·쉐딩·하이라이트: 그 부위만 확대, 세로 모드(3·4·5 모두). 눈·눈썹 단계에서 세로 부위로 돌아올 때 "폰을 세로로 돌리세요" 안내. 진행 칩으로 눈 단계 ↔ 세로 부위를 오갈 때도 같은 안내.
  - 가이드·채점 좌표는 랜드마크 기준이라 화면 방향과 무관하다.
- 수용 기준: 30fps, ±30° 회전 정렬 오차 공개, 가로↔세로 전환 시 추적 끊김 0.5초 이내.

### F-07 상태 관리·세션 복원·확인받기 버튼
- **세션 복원**: 기준 데이터(랜드마크·색 기준·척도·법선 맵·부위별 상태·최신 점수)를 로컬 저장소에 기록. 사용자가 거울로 가서 앱이 종료돼도 복귀 시 같은 부위·같은 가이드로 복원.
- **가이드 유지**: 거울에서 돌아오면 같은 가이드 화면이 그대로 있다. 별도 버튼 없음. **자리 비움 상태 표시("거울에서 그리고 오세요" 같은 문구)는 없다.** 얼굴이 안 보이면 테두리만 사라지고 화면은 그대로, 얼굴이 다시 잡히면 테두리가 다시 붙는다. 내부적으로만 얼굴 미검출 시 카메라 저속 전환·세션 저장.
- **품질 게이트**: 얼굴 추적으로 정면성(yaw ±15°, pitch ±10°), 양쪽 눈·볼 보임, 손 없음(CV 손 검출 모델), 선명도(라플라시안 분산), 밝기(이마 L* 기준 대비 범위) 확인. 충족 시 "확인받기" 버튼 활성, 미충족 시 **칩 없이 한 줄만**: 가장 먼저 걸린 조건 하나("조금만 정면으로", "손을 내려 주세요", "조금 더 밝은 곳에서"). 우선순위 정면 → 양쪽 눈 → 손 → 선명 → 밝기.
- **확인받기**: 버튼을 누르면 **즉시 촬영**(카운트다운 없음). 흔들림 방지로 누른 직후 3~5프레임을 평균해 채점. 자동 채점 없음.
- **테두리 표시**: 그릴 자리는 **선(테두리)만** 그린다. 섀도우·볼 같은 면 부위도 윤곽선만, 안쪽 채우기 없음.
- **버튼**: 이 화면에는 "확인받기"만, 한쪽 구석에 작게(라이브 화면을 가리지 않게). 건너뛰기는 결과 화면(화면 5)에만 둔다.
- 수용 기준: 가림·미충족 상태에서 채점 0건. 복원 성공률.

### F-08 부위 결과 인식 (색·영역)
- 랜드마크 정렬 → 조명 참조 보정 → 맨얼굴 대비 Lab ΔE 차이 맵 → 프레임 평균 → 손 제외 → 부위 영역 추출.
- **CV 화장 영역 시맨틱 분할 모델(자체 학습, 경량 U-Net 계열, INT8 온디바이스)**로 ΔE 임계 영역을 정밀화(경계 잡음·그림자 오탐 제거). 모델 실패 시 ΔE 임계만으로 진행.
- 추가 산출:
  - **세션 내 지수(0~100)**: 부위 평균 ΔE에서 비화장 참조 ΔE를 뺀 값을 0~100으로.
  - **피부 대비 톤 차이**: 같은 프레임에서 쉐딩 영역 vs 인접 비화장 피부의 밝기 차이. 맨얼굴의 자연 그림자 대비를 빼서 화장 몫만 산출.
- 범위: 눈썹·아이라이너·입술 확실. 섀도우·볼터치는 유무·방향·지수. 쉐딩·하이라이트는 유무·좌우 톤 차이(확인만).

### F-09 부위 채점·결과 화면
- 형태 항목: 겹침률, 이탈 거리(눈 폭 대비 비율), 맨얼굴 비대칭 뺀 좌우 차이, 부위별 세부 지표(꼬리 각도·두께 등).
- 강도 항목(규칙, 라벨 불필요, 섀도우·볼터치): 유무, 좌우 지수 비교, 이전 시도 대비 증감, 목표 지수 밴드 대비. 한 줄 평은 방향 표현("오른쪽이 조금 진해요", "조금 더 진하게", "적당해요"). 숫자는 내부용.
- 출력(내부): 부위 점수 0~100, 이탈 좌표·비율·각도, 진단 코드. 측정 불가 항목은 "확인만"(점수 없음).
- **쉐딩·하이라이트는 항상 "확인만"**: 점수를 매기지 않는다. 결과 화면에 테두리 겹침 + "확인하고 넘어가세요" + (있으면) 좌우 비교 한 줄("오른쪽이 조금 진해요")만 보여주고 "다음". 합산에서 제외.
- **다른 부위가 측정 불가일 때**(화장 감지 안 됨·조명 급변·기준 없음): 점수 자리에 "확인만" + 이유 한 줄("색이 옅어서 재지 못했어요. 직접 보고 넘어가세요") + "다음". 결과 화면을 건너뛰지 않는다. 합산 제외.
- **화면 5 표시**: 점수, 내가 한 화장 사진 위에 가이드 테두리 겹침, 한 줄 평(방향 표현: "오른쪽 꼬리가 조금 위로 갔어요"). **거리·각도·% 숫자는 화면에 표시하지 않는다.** 어긋난 곳 표시(붉은 점·화살표)는 없고 **테두리 겹침만**. 버튼: **다음**(점수가 낮아도 누를 수 있음, 이 점수로 확정·합산 포함. **마지막 부위에서는 "결과 보러 가기"** → 화면 6) / **다시 확인받기**(화면 4 실시간 테두리로 돌아가 다시 촬영, 새 결과로 덮어쓰기) / 건너뛰기(이 부위 점수 미반영·합산 제외). 완성본부터 다시 보려면 진행 칩에서 그 부위를 누른다. 자동 통과 판정 없음. 쉐딩·하이라이트 결과 화면은 5-b(화면 브리프 참조, 점수 대신 "확인만").
- 수용 기준: 반복 채점 편차, 지수 재현성, 좌우 방향 정확도 공개. 거짓 점수 금지.

## 4. 전체 리뷰

### F-10 합산 점수·전체 대칭·조화
- **합산 = 측정된 부위 점수의 가중 평균**. 부위를 다시 확인받으면 그 부위의 최신 점수로 합산을 다시 계산한다. 전체 리뷰의 부위 막대를 누르면 그 단계로 돌아간다. 가중치(초안): 눈썹·아이라이너·입술 1.0, 섀도우 1.0, 볼터치 0.7. **쉐딩·하이라이트는 항상 확인만이라 합산에 없음.** "확인만" 부위와 건너뛴 부위는 제외한다. **화면에는 합산 숫자만** 보여주고 "5개 중 4개 기준" 같은 기준 표기는 하지 않는다(내부 `measuredCount`만 기록).
- **보정(내부 계산만, 화면 표시 없음)**: 전체 좌우 대칭(눈·볼 좌우 차이) 최대 −5, 부위 간 조화(볼·입술 톤 차이가 룩 템플릿 범위 안인지) 최대 −5.
- **쌩얼 vs 내 화장** 나란히: 촬영 1(정면 눈 뜸)과 리뷰 진입 시 품질 게이트 통과 프레임을 같은 크롭으로. 쌩얼 사진은 이 용도로 세션 끝까지 폰에 보관 후 삭제.

### F-11 리뷰 화면
- 합산 점수 크게(숫자만, 기준 표기 없음), 아래 부위별 가로 막대 + 결과 화면의 한 줄 평 그대로(막대 탭 → 그 단계로). 쉐딩·하이라이트와 측정 불가 부위는 막대 목록에 "확인만"으로 표시. 쌩얼 vs 내 화장은 나란히 두 장(슬라이더 아님). 숫자 지표 없음. 2초 이내. 음성 없음.
- 버튼 두 개: **"결과 저장"**(쌩얼·내 화장 비교 한 장 + 점수 카드를 이미지로 폰 갤러리에 저장, 앱 밖 파일이라 세션 삭제와 무관) / **"끝내기"**(세션 데이터·사진·결과 삭제). 결과 저장은 선택이며 서버 전송 없음.

- 피부 진단, 브랜드·상품명 추천, 음성 안내, 3D 얼굴 모델·아바타
- 얼굴형에 따른 룩·눈·입술 조정(쉐딩·하이라이트만 예외), 세션 기록 보관, 결과·리뷰 화면에 숫자 지표·보정 표시
- 서버 없이 쓰는 폰 전용 모드(동의 거부 시 이용 불가)

## 10. 시스템 구성 (요약)

- **클라이언트(지금은 모바일 웹, 이후 안드로이드)**: 촬영·추적·품질 게이트, 온디바이스 추론(랜드마크·손·분할. 웹은 WASM/WebGL, 앱은 INT8 런타임), 규칙 채점 엔진, 세션 임시 저장. 웹은 HTTPS 필수(카메라 권한).
- **서버**: nginx(TLS, 업로드 제한) → API(작업 ID, 폴링) → 큐 → GPU 워커 풀(법선 추정·얼굴 파싱·화장 전이, GPU당 1워커, 모델 상주) → 저장소(임시 사진 즉시 삭제, 결과, 규칙·룩 템플릿·제품 목록 DB, 모델 레지스트리). 자체 GPU 서버, API 사용료 없음.
- **학습·운영**: 데이터 저장소 → 합성 도구·라벨링 → 학습 → 평가 → INT8 변환 → 배포 → 모니터링.

## 13. 1주차 실기기 검증

1. 4장 자동 촬영 60초 이내, 눈 폭 기준 길이 재현성, 측면 촬영 각도 허용치
2. 브라우저 카메라에서 4장 연속 촬영 시 밝기 변동 폭 측정, 이마·눈 흰자 정규화로 충분한지 확인 (앱 전환 시 노출 고정 기기 등급 확인)
3. 부위 확대 크롭에서 추적 유지, 품질 게이트 반응
4. 서버 법선 추정(3장)·얼굴 파싱 왕복 3초, 쉐딩 위치가 사람 간 구분되는지
5. 화장 전이 모델 1차 결과(정체성 유지 여부), 룩당 생성 시간, 화장 레이어 추출 → 메시 워핑 30fps 여부
6. 섀도우·볼터치 3단계 ΔE 구분(지수 밴드 근거), 쉐딩 좌우 톤 차이 방향 정답률
7. 합성 데이터 생성기 100장 → 분할 모델 0차 학습 가능 여부

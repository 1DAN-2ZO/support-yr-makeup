### 2-2. 서빙 구성

| 요소 | 기술 |
|---|---|
| 앞단 | nginx — TLS, 업로드 크기 제한 |
| API | FastAPI — 작업 ID 발급, 폴링 응답 |
| 큐 | Redis + RQ (또는 Celery) |
| 워커 | GPU당 1워커, 모델 상주. PyTorch + diffusers |
| 가속 | **LCM/Turbo 증류 (필수)** — 아래 2-3 참조. 추가로 TensorRT |
| 저장소 | 임시 사진 즉시 삭제, 룩 템플릿·제품 목록 DB, 모델 레지스트리 |
| 배포 | Docker + NVIDIA Container Toolkit |

### 2-3. 속도 목표 (기능 정의서 F-01·F-03 기준)

| 작업 | 목표 | 달성 방법 |
|---|---|---|
| 법선 추정(3장) + 얼굴 파싱 왕복 | 3초 | 모델 상주 워커로 가능 |
| **룩 생성 — 룩당** | **3초** | 확산 기본 20~50스텝으로는 불가. **LCM/Turbo 증류로 4~8스텝 필요** |
| **룩 생성 — 첫 룩 / 10개 전체** | **3초 / 30초** (2026-09-16 확정) | 배치 추론 + 큐. 끝난 룩부터 썸네일 활성 |

> ⚠️ 전체 목표가 15초 → **30초**로 완화됐지만 **룩당 3초는 그대로**다. GPU 1장에서 SD1.5 기반 모델을 3초에 돌리려면 증류가 여전히 필요하다. 1주차 검증 5에서 **스텝 수와 룩당 실측 시간**을 함께 재야 한다.

## 8. 라이선스 위험과 대체안

발표·과제는 지금 구성으로 전부 가능하다. 아래는 **사업화로 넘어갈 때** 걸리는 것들과 그 대체안이다.
**5개 중 2개는 모델을 빼면 사라진다.** 우리가 모델에서 실제로 쓰는 정보가 일부뿐이기 때문이다.

### 8-1. 요약

| # | 위험 | 지금 | 대체안 | 확인 시점 |
|---|---|---|---|---|
| 1 | 법선 모델 **DSINE** — 비상업 전용 | 서버 GPU 모델 | **MediaPipe Face Geometry (클라이언트)** | 1주차 검증 4 |
| 2 | 파싱 가중치 — **CelebAMask-HQ 조건 승계** | BiSeNet 사전학습 | **랜드마크 다각형** → 부족하면 EasyPortrait 재학습 | 1주차 검증 4 |
| 3 | 분할 모델 학습 데이터 **FFHQ-Makeup** — CC-BY-NC-SA | 학습 1순위 | **자체 합성 100%**, FFHQ-Makeup은 평가 전용 | 1주차 검증 7 |
| 4 | 룩 참조 이미지 10장 | 미정 | **자체 촬영 + 서면 동의** 또는 FLUX.1-schnell 생성 | 1주차 룩 정의 |
| 5 | 화장 전이 베이스 **SD1.5** — CreativeML Open RAIL-M | 그대로 | **유지.** 상업 사용 허용, 용도 제한 조항만 준수 | — |

### 8-2. 위험 1 — 법선 모델

| 대체안 | 라이선스 | 평가 |
|---|---|---|
| **MediaPipe Face Geometry** — Canonical Face Model 468점 3D 메시 + Metric 3D 공간 + 자세 행렬 | **Apache-2.0** | **1순위.** 이미 쓰는 라이브러리에 포함 |
| Marigold-Normals | Apache-2.0 | 확산 기반이라 느리고 서버 유지 필요 |
| Imperial College 상업 라이선스 문의 | 유료 | 사업화 확정 후 |

법선 모델에서 받으려던 건 **광대 돌출 최고점과 턱선 방향 둘뿐**이고, 그건 3D 메시의 정점 법선으로 계산된다. 평균 메시라 개인차 반영이 약한 부분은 **이미 촬영하는 좌·우 45° 2장으로 보정**한다.

> 이게 되면 F-01의 **서버 왕복 3초가 통째로 사라지고** 쉐딩 가이드가 폰에서 즉시 나온다. 서버는 화장 전이 하나만 돌리는 구조가 된다. 단 **서버 처리 동의는 룩 생성 때문에 여전히 필요**하다.

### 8-3. 위험 2 — 얼굴 파싱

| 대체안 | 라이선스 | 평가 |
|---|---|---|
| **파싱 모델을 MVP에서 뺀다** — 부위 마스크를 랜드마크 다각형으로 | 없음 | **1순위.** 가이드 규칙(F-05)이 이미 랜드마크 기반 |
| **EasyPortrait 재학습** — 40,000장, 9분류(좌우 눈썹·좌우 눈·입술·치아 분리) | CC BY-**SA** 4.0 변형 | 2순위. 규모·분류가 우리 용도와 맞음 |
| Helen · iBugMask · LFW-Part 재학습 | **제약 없음** | 3순위. 규모가 작음 |

파싱 모델은 원래 "정밀화" 용도지 필수가 아니다. 빼고 시작해 정확도가 부족할 때 붙인다.
⚠️ EasyPortrait는 **SA(동일조건변경허락)**라 학습한 가중치 공개 의무가 생길 수 있다. 채택 전 라이선스 원문 확인.

### 8-4. 위험 3 — 분할 모델 학습 데이터 (가장 큼)

**우리가 직접 학습하는 모델**이라 비상업 데이터로 학습하면 그 조건이 우리 가중치에 따라붙는다.

| 대체안 | 평가 |
|---|---|
| **자체 합성 데이터 100%** — 맨얼굴에 랜드마크로 라이너·눈썹·립을 절차적으로 그려 정답 마스크 자동 생성 | **1순위. 원래 계획에 있던 것** |
| 맨얼굴 소스 = 팀원 촬영 + `poc/samples/phone-portraits-20/` 20장 | 소스가 우리 것이면 완전히 깨끗 |
| FFHQ-Makeup은 **평가·개발 참고 전용**으로 강등 | 학습에서 빼면 가중치는 자유 |

데모: `poc/synth/` (합성 생성기 브라우저 POC).

### 8-5. 위험 4·5 — 룩 참조 이미지, 베이스 모델

- **룩 참조**: 자체 촬영 + 서면 동의가 1순위. 차선은 FLUX.1-schnell(Apache-2.0) 생성 — 실존 인물이 아니라 초상권이 없다. Unsplash·Pexels는 상업 사용은 되지만 **모델 릴리스가 별도**라 비권장.
- **베이스 모델**: FLUX.1-schnell은 Apache-2.0로 가장 깨끗하지만 12B라 **룩당 3초 목표와 정면충돌**한다. SD1.5(RAIL-M)는 상업 사용이 허용되므로 유지한다.

### 8-6. 다 통했을 때
